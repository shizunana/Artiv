# 绘约（HuiYue）订单流转流程

> 版本：v1.0 ｜ 日期：2026-08-12 ｜ 性质：核心功能设计文档（尚未编码，供阶段 3 订单模块实现参考）

## 0. 需求来源（项目开发计划书 F8 原文）

> 本设计文档以《项目开发计划书.md》F8 为需求基准，原文如下：

**F8 订单与模拟资金托管（★核心）**

- 选定画师后创建订单（金额取企划预算或画师报价）
- 分阶段验收：初稿 → 修改 → 终稿 → 交付，按阶段提交与验收
- 订单状态：待接单 → 进行中 → 待验收 → 已完成 / 已取消 / 争议中
- 模拟托管：下单即视为托管，阶段验收通过即结算；争议由管理员处理
- **交付水印保护**：画师交付阶段提交附件时，企划方仅能看到带水印的低像素预览图；只有企划方确认收货（验收通过）后，才能下载高清无水印原图
  - 实现要点：附件区分为「预览图（水印 / 低像素）」与「原图（高清）」，原图下载接口在订单阶段验收通过后才放行
  - 数据落地：`order_stage.attachments` 记录预览图；原图另行存储（如 `order_stage.originals` 或独立附件表），并记录验收时间作为放行依据
- 简化：取消钱包、提现、手续费、详细仲裁流程

> 后续各章节（状态机、阶段验收、模拟结算、水印保护等）均围绕上述需求展开，若需求变更需同步更新计划书与本文档。

## 1. 订单生命周期（状态机）

### 完整业务流（含应征私聊）

```
发布企划
    ↓
多名画师同时应征（每名画师一条应征记录）
    ↓
企划方与各应征画师 1v1 私聊（沟通需求、风格、报价意向）
    ↓
确定沟通满意的画师 → 应征标记「已通过」
    ↓
创建订单（金额取该画师报价或企划预算）
    ↓
待接单 → 画师与企划方议价（H 阶段）→ 画师接单
    ↓
进行中 → 阶段验收 → 已完成 → 互评
```

### 订单状态机

待接单(0) → 进行中(1) → 待验收(2) → 已完成(3)

待接单(0) → 已取消(4) ｜ 进行中/待验收 → 争议中(5) →（管理员仲裁后）已完成/已取消

### 状态说明

| 状态 | 值 | 含义 | 进入条件 |
| --- | --- | --- | --- |
| 待接单 | 0 | 订单已创建，等待画师接单 | 创建订单成功 |
| 进行中 | 1 | 画师已接单，按阶段交付 | 画师接单 |
| 待验收 | 2 | 画师提交阶段稿件，等待企划方验收 | 画师提交阶段 |
| 已完成 | 3 | 全部阶段验收通过，模拟托管结算 | 最后阶段验收通过 |
| 已取消 | 4 | 任意方取消 / 超时未接单 | 企划方取消（待接单时）/ 管理员取消 |
| 争议中 | 5 | 双方纠纷，管理员介入 | 任意一方发起争议（进行中/待验收） |

## 2. 状态流转规则

| 从 | 到 | 触发方 | 前置条件 / 校验 |
| --- | --- | --- | --- |
| 0 待接单 | 1 进行中 | 画师 | 当前用户必须是 order.painter_id；**金额已确认**（双方议价达成一致后） |
| 0 待接单 | 4 已取消 | 企划方 / 管理员 | 当前用户是 employer 或 admin |
| 1 进行中 | 2 待验收 | 画师 | 画师提交阶段稿件（order_stage） |
| 2 待验收 | 1 进行中 | 企划方 | 企划方要求修改（stage 标记需修改） |
| 2 待验收 | 3 已完成 | 企划方 | 最后阶段验收通过 → 模拟结算 |
| 1/2 | 5 争议中 | 双方任一 | 发起争议，管理员介入 |
| 5 争议中 | 3 已完成 / 4 已取消 | 管理员 | 仲裁结果 |
| 任意（非完成） | 4 已取消 | 管理员 | 违规处理 |

## 3. 阶段验收流程（order_stage）

### 3.1 阶段初始化

创建订单时，根据订单来源初始化阶段：

- 企划下单：默认四阶段 **初稿 → 修改 → 终稿 → 交付**（与开发计划书 F8 一致），写入 order_stage
- 橱窗下单：从橱窗的 phases（JSON）复制阶段（画师发布时自定义），写入 order_stage

> 阶段占比示例（可配置）：初稿 30% → 修改 30% → 终稿 30% → 交付 10%；百分比用于「企划方原因中断时按已确认阶段支付对应比例稿酬」。

### 3.2 阶段流转

画师提交阶段（submitter=1, status=0 待确认）→ 企划方验收：

- 通过（status=1）→ 进入下一阶段；最后阶段通过 → 订单已完成(3)
- 需修改（status=2）→ 画师重新提交

关键规则：

- 只有当前阶段验收通过后才能提交下一阶段
- 阶段记录不可覆盖，追加新记录（保留历史）
- 最后阶段（交付）验收通过 → 订单完成 → 进入互评（F10 评价体系）

### 3.3 交付水印保护（计划书 F8 新增需求）

- 画师提交阶段附件时，企划方**仅能看到带水印的低像素预览图**
- 只有企划方**确认收货（验收通过）后**，才能下载高清无水印原图
- 数据落地：`order_stage.attachments` 记录预览图；原图另存（`order_stage.originals` 或独立附件表），并记录验收时间作为放行依据
- 原图下载接口必须校验该阶段 status=1（已通过）

## 4. 模拟托管结算

- 下单即视为资金托管（模拟，不接真实支付）
- 结算时机：最后一个阶段验收通过时视为结算完成
- 简化：不设钱包/余额/提现，仅记录订单金额与完成时间
- 完成后双方可互评（F10）：`POST /orders/{id}/review`，订单完成前禁止评价

## 4.0 应征与私聊（下单前筛选）

- 同一企划允许多名画师同时应征（application 表，互不冲突）
- 企划方与**每名应征画师**进行 1v1 私聊：沟通需求细节、风格、报价意向
- 私聊基于站内消息（message 表，type=3 私信），不依赖订单（下单前即可发起）
- 企划方确认某画师沟通满意 → 应征状态置为「已通过」，其余画师「已拒绝」（可选通知）
- 只有「已通过」的画师才能被创建订单

规则：

- 私聊内容仅双方可见（1v1）
- 应征记录保留沟通入口（应征列表可发起/继续私聊）
- 选定画师后可撤销/更换（在企划仍为招募中时）

## 4.1 订单金额规则

| 订单来源 | 金额取值 | 校验 |
| --- | --- | --- |
| 企划下单（选定画师） | 画师报价（应征 quote）；未报价则取企划预算 | 服务端计算，不接受前端传值 |
| 橱窗下单 | 橱窗价格（stall.price） | 校验橱窗上架中，并扣减库存 |

## 4.2 订单内沟通

- **待接单即可沟通**：订单创建后，画师与企划方在接单前就通过订单内消息沟通（尤其用于议价）
- `POST /orders/{id}/messages`：双方可发送订单内消息（F9 沟通与消息）
- 阶段验收、状态流转事件通过消息/WebSocket 通知对方

## 4.3 价格协商（接单前）

画师接单前，双方在订单内沟通并协商最终金额：

| 步骤 | 操作 | 接口 | 权限 / 校验 |
| --- | --- | --- | --- |
| 1 | 画师提出期望价格 | `PUT /orders/{id}/quote` | 仅 painter，且订单为待接单 |
| 2 | 企划方确认最终金额 | `PUT /orders/{id}/amount` | 仅 employer，且订单为待接单 |
| 3 | 画师接单 | `POST /orders/{id}/accept` | 金额确认后；接单即锁定金额，进入进行中 |

规则：

- 待接单阶段金额可反复协商（quote / amount 均可调整），聊天中说明理由
- 画师接单后金额锁定，不可再改（进入进行中后价格固定）
- 若协商不成，企划方可在待接单阶段取消订单（4 已取消）

## 5. 前提功能分析（当前缺陷清单）

以下为现有代码在实现订单流转前必须补齐或修复的点：

### 5.1 订单创建（POST /orders）——缺陷严重

- 无任何权限/字段校验：当前直接接收 OrderInfo 实体，调用方可伪造 employer_id、painter_id、amount
- 金额来源未约束：应取「企划预算 / 画师报价 / 橱窗价格」，而非前端传值
- 订单来源未区分：企划下单需关联 project_id；橱窗下单需关联 stall_id，且应校验橱窗上架状态
- 库存未扣减：橱窗下单后应扣 stall.stock，无库存时禁止下单
- 重复下单未拦截：同一企划可被重复下单

### 5.2 订单查询

- GET /orders/{id} 无归属校验：任何登录用户可查看任意订单详情，必须限制为 employer 或 painter

### 5.3 应征 → 订单闭环缺失

- 企划方「选定画师」按钮目前是占位（前端 TODO），后端无「应征通过 → 创建订单」的对接接口
- 应征状态流转（通过/拒绝）无后端实现

### 5.4 接单 / 阶段 / 状态接口缺失

- 画师接单（0→1）无接口
- 阶段提交/验收（order_stage 写与确认）无接口
- 状态流转（PUT /orders/{id}/status）无接口
- 争议流程无接口
- 订单内沟通（POST /orders/{id}/messages）无接口

### 5.5 数据与关联

- order_info 无 completed_at 等结算相关字段（可后续补充）
- 演示数据中订单状态与真实流转不一致（id=1 直接是进行中）
- order_stage 无 originals 字段（原图存储），需按水印保护需求补充

## 6. 建议实现顺序（编码时）

### 阶段 A：数据与模型基础

1. order_info 补充字段：completed_at（结算时间）、cancel_reason（取消原因）
2. order_stage 补充字段：originals（原图，水印保护用）、reviewed_at（验收时间）
3. 同步 init.sql 与实体

### 阶段 B：订单创建安全化（修复最严重缺陷）

4. 新增 OrderCreateRequest DTO：只收 projectId 或 stallId，不收金额/身份
5. 服务端计算金额：企划下单取画师报价（未报价取预算）、橱窗下单取橱窗价
6. 校验：橱窗上架中 + 扣减库存 + 同一企划不可重复下单
7. 创建订单时初始化 order_stage（企划四阶段 / 橱窗复制 phases）

### 阶段 C：订单权限

8. GET /orders/{id}、GET /orders 归属校验：仅 employer 或 painter 可见

### 阶段 D：接单与状态流转

9. 画师接单 POST /orders/{id}/accept（0→1，校验已认证画师）
10. 状态流转 PUT /orders/{id}/status：取消（待接单时企划方）、争议、完成，按状态机校验（非法流转 3001）
11. 管理员争议仲裁接口（争议 → 完成 / 取消）

### 阶段 E：阶段验收与水印保护

12. 画师提交阶段 POST /orders/{id}/stage（内容 + 预览图 + 原图）
13. 企划方验收 PUT /orders/{id}/stage/{stageId}（通过 → 下一阶段 / 完成；需修改 → 画师重提）
14. 原图下载接口校验该阶段已通过（水印保护放行）

### 阶段 F：业务闭环

15. 应征私聊：企划方与应征画师 1v1 站内私信（POST /messages/private，type=3），应征列表展示沟通入口
16. 应征选定画师 → 应征状态通过（其余拒绝）→ 自动创建订单（对接闭环）
17. 订单内沟通 POST /orders/{id}/messages（消息落库）
18. 评价校验：订单完成后方可 POST /orders/{id}/review

### 阶段 G：前端对接

19. 订单管理页：接单、阶段提交、验收操作
20. 订单详情页：阶段进度、附件预览（验收前水印图）/ 下载（验收后原图）
21. 应征列表页：私聊入口 + 选定画师操作

### 阶段 H：聊天消息传递与价格协商（接单前议价）

22. 订单内聊天消息接口：POST /orders/{id}/messages（待接单即可使用，双方可见）
23. 画师报价接口：PUT /orders/{id}/quote（仅 painter、待接单）
24. 企划方确认金额接口：PUT /orders/{id}/amount（仅 employer、待接单）
25. 画师接单校验金额已确认；接单后金额锁定
26. 订单内消息列表（GET /orders/{id}/messages，分页）+ 前端聊天框（订单详情页）

> 说明：聊天消息传递是接单前议价的前提，因此 H 阶段与 D 阶段（接单）衔接，建议在接单接口前完成消息与议价接口。

> 每个阶段完成后用演示账号走通对应接口，再进入下一阶段。

## 7. 验收清单（编码完成后）

- [ ] 企划方发布企划 → 画师应征 → 选定 → 生成订单（金额=报价）
- [ ] 橱窗立即下单 → 生成订单（金额=橱窗价格，库存扣减）
- [ ] 画师接单 → 提交阶段稿件 → 企划方验收通过/需修改
- [ ] 全部阶段通过 → 订单已完成（模拟结算）
- [ ] 交付阶段水印保护：验收前仅预览图，验收后放行原图
- [ ] 订单完成后双方可互评，完成前评价被拒
- [ ] 订单内沟通消息可发送并落库
- [ ] 越权访问他人订单返回 403/404
- [ ] 非法状态流转返回 3001
