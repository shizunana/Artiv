# 邀请系统优化与验收

> 文档状态：现行产品规则、实现结果与验收记录。
> 最近更新：2026-08-26。
> 代码基线：`198bd2a` 的邀请闭环基础上，已加入提醒箱、统一截稿日期规则，以及公开企划邀请报价/带价邀请。
> 结论：定向邀请核心流程继续复用；公开企划主动邀请在相同邀请、应征、会话和消息模型上扩展，不另造平行流程。

## 1. 产品定义

定向邀请是普通应征流程的变种：系统内部仍形成一条可用于沟通、选定和下单的应征；用户界面使用“邀请、接受邀请、拒绝邀请”等文案。

- 一次发布定向企划只允许选择一名画师。
- 一个定向企划只能对应这一名受邀画师，创建后不能追加、更换或重新邀请其他画师。
- 定向企划不进入公开企划大厅、首页推荐或普通搜索。
- 企划创建者、受邀画师、管理员及后续合法业务关联方可以按权限读取详情；普通无关账号不能通过企划 ID 越权访问。
- 接受邀请只创建有效应征并建立沟通，不等于选定、接单或创建订单。
- 企划方仍从应征画师区域进入既有选定、发单和履约流程。

## 2. 当前完整流程

### 2.1 发布与首次通知

企划方发布 `mode=1` 的定向企划并指定唯一画师后，系统在同一业务链路内完成：

1. 创建企划与邀请记录。
2. 向受邀画师写入 `INVITATION_CREATED` 系统消息。
3. 在画师工作台“收到的邀请”生成记录。
4. 在企划详情的应征画师区域显示受邀画师，状态为“等待回应”。
5. 待回应画师立即计入应征人数。

首次邀请只发送系统消息，不提前建立双方会话。邀请记录中的提示和系统消息正文使用同一内容，并携带企划详情入口。

### 2.2 收到的邀请

“收到的邀请”是画师侧提醒 / 记录入口，不是邀请、会话或订单的核心业务状态载体。页面复用订单列表的横向卡片结构：

| 订单卡字段 | 邀请卡字段 |
| --- | --- |
| 图片 | 企划封面 |
| 标题 | 企划名 |
| 订单编号 / 下单时间 | 类型 / 邀请时间 |
| 当前阶段 | 企划详情（最多 15 字，超出显示 `...`） |
| 金额 | 定向预算区间 / 邀请报价 / 带价金额 |
| 详情操作 | 企划详情 / 删除 |

邀请状态与蓝色邀请类型均显示在标题旁。页面默认选中“全部邀请”，并提供“待处理 / 已接受 / 已拒绝 / 已失效”筛选。全部列表按该状态顺序排列，同状态按邀请时间倒序；单状态列表按邀请时间倒序。数据库业务状态与页面文案统一为 `0 待处理 / 1 已接受 / 2 已拒绝 / 3 已失效`。

四种状态都允许“删除”。这里的删除只把该记录从当前画师的“收到的邀请”中隐藏，不修改 `invitation.status`，也不删除业务邀请，不等于拒绝、取消接受、取消会话或取消订单。待处理记录被隐藏后，画师仍可从合法的企划详情入口处理原邀请；已接受记录被隐藏后，既有会话、应征、订单和后续履约继续有效。删除前固定确认：

> 删除后该邀请将不再显示在“收到的邀请”中，但不会影响已建立的会话、订单或其他业务记录。

企划方“我的企划”按“公开企划 / 定向邀请”分组分页。被拒绝企划改为公开招募后，`mode` 从 `1` 变为 `0`，页面会自动切换并在“公开企划”中显示该记录。

列表的删除动作只改变画师侧提醒可见性，不在列表内直接改变邀请业务状态。

### 2.3 接受邀请

受邀画师在企划详情点击“接受邀请”，表单只填写报价。企划截稿日期当天仍可接受，进入次日后不能接受但仍可拒绝或隐藏提醒。成功后：

1. 邀请状态变为已接受。
2. 创建或恢复唯一有效 `application`，报价为画师本次填写的价格。
3. 画师继续显示在应征画师区域，可沿用普通应征的改价、选定和发单能力。
4. 自动建立或复用双方合并私聊。
5. 会话内写入一条 `INVITATION_ACCEPTED` 系统提示。
6. 系统消息分区另写一条 `type=0`、`subtype=INVITATION_ACCEPTED` 的独立通知。
7. 两处正文完全相同，均携带企划详情入口。
8. 不自动创建订单。

固定正文：

> 画师「名字」接受了您的企划「企划标题」的邀请，双方已建立会话，您可以开始与画师沟通后续合作内容。

### 2.4 拒绝邀请

受邀画师点击“拒绝邀请”后必须填写 1–500 字理由。成功后：

1. 邀请状态变为已拒绝并保存理由。
2. 只向企划方发送 `INVITATION_REJECTED` 系统消息，不建立邀请会话。
3. 受邀画师从应征画师区域移除并停止计数。
4. 定向企划自动下架。
5. 企划方不能撤回、重发或更换受邀画师。
6. 企划方可以在“我的企划”中选择至少当前日期 +2 天的新截稿日期，再将该企划改为公开企划；转换后进入企划大厅并使用普通应征流程，不带入已拒绝画师。

固定正文：

> 画师「名字」婉拒了您的企划「企划标题」的邀请，婉拒理由「拒绝理由」

## 3. 本轮优化内容

邀请核心闭环代码基线为 `198bd2a`；本轮在其上继续完成提醒箱优化。

- 接受邀请时新增独立系统通知，修正过去只有会话系统提示、系统消息分区没有记录的问题。
- 新建定向企划时新增首次邀请系统消息，正文与邀请记录一致。
- “收到的邀请”由表格改为订单同款卡片；现已扩展为全部加四个状态筛选、服务端排序和邀请时间展示。
- 新增画师侧 `painter_hidden / painter_hidden_at` 提醒可见性字段及独立隐藏接口；四种状态均可隐藏，且不触碰邀请、应征、会话或订单业务数据。
- 待处理邀请的画师进入企划详情应征画师区域并计入总数；拒绝后不再显示。
- 接受/拒绝按钮文案补全为“接受邀请 / 拒绝邀请”。
- 拒绝邀请后自动下架定向企划。
- 新增被拒绝定向企划“改为公开企划”入口与服务端校验。
- 待处理邀请期间禁止企划方撤回、下架或删除企划。
- 邀请接受复用企划统一截稿日期规则；过期后接受由前后端共同禁止，拒绝仍可完成。被拒绝企划转公开必须提交至少当前日期 +2 天的新日期。
- 企划详情初始加载态修正，避免请求返回前短暂闪现“不存在或已下架”。
- 系统消息增加邀请创建、接受、拒绝三类标题映射。
- 新增幂等迁移 `backend/sql/migrations/20260825_invitation_optimization.sql`：补齐历史已接受邀请的独立系统消息，并把历史已拒绝定向企划调整为下架状态。
- 新增幂等迁移 `backend/sql/migrations/20260825_invitation_reminder_inbox.sql`：补齐提醒隐藏字段及画师提醒列表复合索引。

## 5. 当前实现边界

- 不为同一企划增加多画师邀请。
- 不提供待处理邀请撤回。
- 不在接受时自动选定或下单。
- 不在拒绝时建立会话。
- 不把提醒页面“删除”实现成业务邀请删除、拒绝、撤销会话或撤销订单。
- 不因为提醒已隐藏而禁止受邀画师从其他合法入口处理原邀请。
- 不因本轮优化拆分现有 `project`、`invitation`、`application` 和 `message` 主模型。
- 历史分析文档已归档为 `docs/olddocs/邀请定向功能-旧试作分析.md`，只用于追溯，不再作为现行开发指令。

## 6. 公开企划主动邀请

### 6.1 类型与入口

已认证画师公开主页的“邀请”按钮打开邀请弹窗，企划方只能选择本人仍正常上架、未过期且未被治理下架的公开企划：

- `invitation_type=1` 邀请报价：企划方不填写价格；画师接受时只填写报价。
- `invitation_type=2` 带价邀请：企划方填写至少 ¥50 的邀请价格；画师接受时只确认价格，系统使用邀请价格生成锁价应征。

两类邀请创建时只写邀请记录和首次系统消息，不创建应征、会话或订单。同一公开企划允许邀请多名画师，也允许同一画师保留多条历史邀请；已有当前有效应征时禁止再邀请。

### 6.2 接受、拒绝与大厅应征

- 邀请报价只有报价提交成功后才标记已接受；带价邀请无需输入说明，只确认数据库保存的邀请价格，不接受客户端改价。两类公开邀请和定向邀请均由服务端写入固定的内部来源说明，普通大厅应征仍要求画师填写真实应征介绍。
- 带价形成的应征使用 `quote_source=1`，服务端拒绝后续改价；其他应征使用 `0`。
- 两类公开邀请接受后均创建有效应征、建立或复用合并会话，并分别写入正文相同的会话系统提示和独立系统通知；不创建订单。
- 画师从大厅自主应征时，同企划、同画师全部待处理公开邀请同步为已接受并关联该应征，同时建立或复用会话，不重复发送同义的普通应征通知。
- 公开邀请拒绝复用 1–500 字必填理由和拒绝通知，但不下架公开企划、不影响其他邀请或画师。

### 6.3 提醒与失效

“收到的邀请”在状态标签旁显示蓝色类型标签：定向邀请、邀请报价、带价邀请。金额区域小标题统一为“预算”：定向邀请显示预算区间，邀请报价显示固定文字“邀请报价”，带价邀请显示邀请价格。

状态扩展为 `0 待处理 / 1 已接受 / 2 已拒绝 / 3 已失效`。公开企划过期、主动下架、管理员下架或逻辑删除后，待处理邀请变为已失效；不能接受或拒绝，但仍可查看提醒和隐藏。延长截稿日期不会恢复旧邀请。已接受和已拒绝结果不覆盖，已形成的应征、会话与订单继续运行。

### 6.4 数据与接口

- 新增 `POST /api/v1/invitations` 作为公开企划主动邀请入口；定向邀请仍由 `POST /api/v1/projects` 的 `mode=1 + invitePainterId` 创建。
- `invitation` 新增 `invitation_type / offered_price`，`application` 新增 `quote_source`。
- 迁移 `backend/sql/migrations/20260826_public_project_invitations.sql` 删除会阻止多画师及重复历史邀请的唯一索引，改为 `(project_id,painter_id,status,created_at)` 普通索引；定向企划唯一画师规则由业务事务保证。
- 黑名单和画师个人最低带价金额尚未实现；当前只执行固定最低 ¥50，文档和界面不得声称这两项已经完成。
