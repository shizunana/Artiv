# 艺绘（Artiv）优化方案构想

> 用途：记录产品与界面优化构想，以及方案确认后的实施结果。未明确标记“已实施”的内容仍只作为备选，不代表已经排期。

## 1. 消息中心独立于工作台

**状态：已实施（2026-08-23，`02ddf48`）**

### 实施前方案

- 消息中心继续位于画师、企划方工作台内部。
- 两个工作台复用同一套会话数据和消息能力，仅入口路由不同。
- 左侧保留工作台导航，消息页内部维持“会话列表 + 聊天区域”的两栏结构。

### 确认实施方案

- 将消息中心调整为与工作台并列的独立一级页面，由顶栏铃铛、企划应征、橱窗和订单页面统一进入。
- 独立页面不展示画师或企划方工作台侧栏，避免同一会话因当前工作台身份产生视觉割裂。
- 消息权限仍按登录账号、会话参与关系和业务资源归属判断，不因脱离工作台而改变。
- 画师/企划方工作台不再保留重复的“消息中心”菜单，统一由全站顶栏进入。
- 顶栏入口显示消息图标与“消息”文字，点击进入“我的消息”；悬停下拉可直接进入“我的消息”或“系统消息”。
- 独立页面左侧只保留“我的消息”“系统消息”，并显示禁用的“消息设置（暂未开放）”作为后续占位。

### 保留评估点

- 移动端是否采用“会话列表页 → 单独聊天页”的双页面结构。
- 是否开放消息设置，以及允许用户控制哪些通知类型。
- 是否需要在独立消息中心补充返回当前工作台的快捷入口。

### 当前结论

独立消息中心已经落地：

- 正式路由为 `/messages`，不依赖当前画师或企划方工作台；系统消息使用 `/messages?tab=notifications`。
- 原 `/dashboard/messages` 与 `/painter/messages` 保留为兼容跳转，并完整保留查询参数和哈希，旧业务链接不会失效。
- 企划、橱窗、订单和应征等业务入口统一进入独立消息中心；工作台侧栏已移除重复入口。
- 原有会话合并、页面内缓存、气泡头像、居中系统卡、图片/订单状态消息、未读和 WebSocket 行为保持不变。
- 本轮只调整前端路由与布局，没有新增接口或改变消息权限。
