对隔离库恢复时使用不带原库 CREATE/USE/DROP DATABASE 指令的 portable.sql，必须明确选择隔离目标，不能把带 artiv 库名的 stopped.sql 直接导入隔离连接。原数据库备份脚本的 Restore 会覆盖目标，只在明确需要回退并评估新数据后使用；不得自动还原清除后续用户记录。新增迁移及演练脚本说明见《部署文档》。

`scripts/database-baseline.ps1` 用于把本机 Artiv MySQL 数据库恢复到正式测试开始前的固定状态。

默认基线为项目根目录 `.artiv-data/database-baseline.sql`，校验文件及每次还原前的自动备份保存在快照同目录。自定义 `-SnapshotPath` 会改变保存位置；自定义位置也须避免提交或公开，其中可能包含账号、消息、订单和其他测试数据。

本脚本只处理 MySQL 数据库，不删除或还原 `backend/uploads/`。测试期间不要手工删除仍可能被数据库引用的上传文件。

`backend/sql/init.sql` 中三个初始账号的余额仍为 0。当前本机为了测试曾把三者余额准备为 `100000.00`，这是运行库状态，不属于初始化 SQL，也不会因为检出同一 Git 提交自动出现。需要给空白库准备交易余额时，优先由管理员在“用户管理 → 详情”使用“发放资金”或“余额调整”，保留对应审计记录；若要把该状态固化成数据库基线，必须在人工核对数据后另行执行 `Capture`。

## 2. 创建和检查基线

首次执行以下命令会保存当前数据库：

```powershell
cd D:\ProjectForGraduation\Artiv
powershell.exe -ExecutionPolicy Bypass -File .\scripts\database-baseline.ps1 -Action Capture
```

查看基线状态及完整性：

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\scripts\database-baseline.ps1 -Action Status
```

如果确实需要用新的当前数据替换旧基线，必须显式执行：

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\scripts\database-baseline.ps1 -Action Capture -ReplaceBaseline
```

替换前的旧基线会自动保存在同一目录，不会直接丢失。

## 3. 测试后还原

先停止后端，避免还原过程中仍有请求写入数据库，然后执行：

```powershell
cd D:\ProjectForGraduation\Artiv
powershell.exe -ExecutionPolicy Bypass -File .\scripts\database-baseline.ps1 -Action Restore -ConfirmRestore
```

安全规则：

- 不带 `-ConfirmRestore` 时拒绝覆盖数据库。
- 还原前会自动生成 `pre-restore-时间.sql`，保存测试结束时的数据。
- 还原前校验基线 SHA-256，损坏或被修改时拒绝执行。
- 默认仅允许本地还原；当前 JDBC 解析器支持 `localhost` / `127.0.0.1`，虽有 `::1` 本地名单，但不能正确解析 IPv6 JDBC 地址。远程还原必须额外显式添加 `-AllowRemote`；该限制不作用于 `Capture`。
- 数据库目标、账号和密码从指定 YAML 的 `datasource` 段读取，支持整值 `${ENV}` / `${ENV:default}`。脚本不加载 Spring profile、不合并多个配置文件，也不自动应用 `SPRING_DATASOURCE_*` 覆盖；必须人工核对脚本目标与后端实际数据库一致。
- 密码临时通过进程环境变量 `MYSQL_PWD` 传给客户端，调用后恢复原值；这不等于密码加密存储，配置文件和快照仍须保护。
- 快照包含 `DROP DATABASE` / 重建数据库语句，还原会覆盖目标库，失败时也可能已发生部分修改；自动备份不是事务回滚。校验只检查哈希和前 80 行数据库标记，不会全面审计 SQL 内容，仅使用可信快照。

## 4. 自定义位置

如需使用其他快照或配置文件，可以传入：

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\scripts\database-baseline.ps1 `
  -Action Status `
  -SnapshotPath D:\backup\artiv-baseline.sql `
  -ConfigPath .\backend\src\main\resources\application-local.yml
```

指定配置文件必须单独包含完整的 `url`、`username`、`password`；只含差异项的 `application-local.yml` 不能依靠主配置补齐。

## 5. 客户端与验证边界

- 客户端查找顺序：`PATH`、Windows 服务 `MySQL80` 的可执行文件目录、`Program Files/MySQL/MySQL Server */bin`。与启动脚本的 `MySQL80-Artiv` 不同，基线脚本不会自动按该服务名寻找客户端；自定义安装目录应将 MySQL `bin` 加入 `PATH`。
- `Status` 只解析配置并检查本地快照、哈希及数据库名标记，不连接数据库，也不能证明快照能成功恢复、与在线数据相同或图片齐全。
- 若需完整演示环境恢复，应在停止业务写入后，另行备份实际 `artiv.upload.dir`，记录数据库和文件备份的对应关系；本脚本不处理文件备份。
