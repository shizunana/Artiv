# 艺绘（Artiv）演示脚本

> 目标时长：15 分钟 ｜ 最近校准：2026-08-13 ｜ 演示前准备：启动 MySQL80、后端（8080）、前端（5173）、导入演示数据
> 注意：第 5、6 段中的正式订单验收、互评、后台仅为最终目标，当前不可作为已完成能力演示；本版本应展示橱窗最小下单—沟通与企划作者主动沟通。

## 演示账号

| 角色 | 账号 | 密码 | 说明 |
|------|------|------|------|
| 企划方 | `planner` | `123456` | 已发布企划、有应征与订单 |
| 画师 | `artist` | `123456` | 已认证、有作品与服务板 |
| 管理员 | `admin` | `123456` | 平台管理 |

---

## 第 1 段：项目介绍（2 分钟）

1. 打开首页，展示平台定位：美术约稿交易平台。
2. 口播业务闭环：发布需求 → 画师应征 / 定向邀请 → 选定下单 → 沟通修改 → 分阶段验收 → 互相评价。
3. 技术栈：Vue 3 + Spring Boot + MySQL，前后端分离；强调 11 个功能模块（认证、入驻、作品、服务板、企划、应征邀请、订单、消息、评价、后台）。

## 第 2 段：注册、登录与画师入驻（3 分钟）

1. 打开注册页，演示画师角色模拟注册（用户名 + 密码 + 角色）。
2. 使用 `artist` 登录，刷新保持登录态（JWT）。
3. 展示画师个人资料：简介、风格标签、接稿状态。
4. 展示画师认证状态（已认证），说明「认证后才能接稿、开设服务板」的约束。

## 第 3 段：作品与服务板（2 分钟）

1. 画师工作台：上传 1 张作品到作品集。
2. 服务板管理：查看已有服务（国潮插画 1200 元），演示上架 / 下架切换。
3. 公开页面：作品广场、服务板列表展示。

## 第 4 段：企划—应征—邀请（3 分钟）

1. 切企划方 `planner`，发布公开招募企划（标题、需求、预算、截止时间、标签、合作方式）。
2. 切画师 `artist` 应征该企划（简介 + 作品链接 + 报价）。
3. 企划方在应征管理列表看到应征记录。
4. 演示定向邀请：发布定向企划邀请画师 → 画师在「收到的邀请」接受。

## 第 5 段：当前可演示的下单与沟通（3 分钟）

1. 企划方打开上架橱窗，点击“立即下单”。
2. 说明当前不经过支付：系统创建用于沟通关联的最小订单，买家和画师都会收到系统通知。
3. 跳转消息中心，展示橱窗下单引导卡片与同画师的合并私聊会话，发送一条文字消息。
4. 回到企划详情/应征管理，展示企划方可主动对已应征画师点击沟通；画师仅可在已有会话回复。
5. 说明正式接单、议价、阶段验收、支付/结算和库存扣减属于下一阶段。

## 第 6 段：消息与后续规划（2 分钟）

1. 展示“我的消息 / 系统通知”、未读状态、系统提示卡片与隐藏滚动条的自适应聊天区域。
2. 说明 WebSocket 已有 JWT 鉴权、落库后推送和前端重连；双账号实时到达仍待最终人工回归。
3. 说明评价闭环、认证审核和管理后台尚未实现，并展示其已纳入订单与开发计划文档。

## 收尾（1 分钟）

1. 总结业务闭环与亮点（画师认证、服务板、定向邀请、分阶段验收、模拟托管、实时消息）。
2. 结束语：感谢观看，欢迎提问。

---

## 应急预案

| 问题 | 处理 |
|------|------|
| 数据库连不上 | 检查 MySQL80 服务，确认 root 密码与 `application.yml` 一致 |
| 前端 403 / 404 | 确认后端已启动、代理配置正确、接口前缀为 `/api/v1` |
| WebSocket 连不上 | 检查 `/ws` 代理的 `ws: true` 配置与 token 参数 |
| 演示数据被改乱 | 重新执行 `backend/sql/init.sql` 恢复演示数据 |
| 网络 / 设备故障 | 使用提前录制的录屏兜底 |
