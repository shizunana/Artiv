## 1. 项目目标与范围

2026-09-07 结构调整增量（回退基线 df62197）：企划采用独立六类，数据库 project.category 改为 project.project_category，Java/API 为 projectCategory。发布、编辑、大厅、统计与向导同步适配；橱窗/作品原十类及题材风格不变，订单交易流程不重构。详情和迁移安全步骤见[六类方案](开发计划/企划六类与大厅筛选优化方案.md)。下述 243 项为上一版历史测试数量，本次结果另记《测试》。

毕业设计规模的美术约稿交易平台，业务闭环：

**发布需求 → 画师应征 / 定向或公开企划主动邀请 → 选定下单 → 沟通修改 → 分阶段验收 → 互相评价**

核心范围：

1. 企划方能力（所有正常登录账号可用）：浏览画师与作品、发布企划（公开招募 / 定向邀请）、管理应征、订单验收与结算，以及完成后 7 天内评价画师。
2. 创作方能力：普通正常账号即可维护作品和公开主页；应征、橱窗创建、接单和受邀接受等交易能力要求认证，并叠加账号状态/资源关系校验。邀请发起方是企划作者，受邀目标需认证；注册 `role` 只决定默认工作台。
3. 订单流转：下单 → 沟通 → 分阶段验收 → 模拟托管结算 → 评价。
4. 后台管理：用户管理、企划审核、数据统计。

简化处理：

- 注册为**模拟注册**（用户名 + 密码 + 角色），无手机验证码、无短信。
- 资金托管为**模拟**（订单状态流转驱动，不接真实支付）。
- 不做：App、企业财务 / 发票、营销活动大赛、真实支付。

## 3. 功能模块分解（11 个模块）

### F1 用户与认证

- 模拟注册：用户名、密码、昵称、主身份（企划方 / 画师，仅决定默认工作台入口）；用户名和昵称均唯一，管理员不能通过公开注册创建
- 角色模型：**同账号多角色**——发布企划等企划方能力所有登录账号可用；应征、橱窗等画师能力以画师认证（cert_status=2）为准
- 登录：JWT 签发与校验，刷新保持登录
- 个人资料维护：统一 `/settings` 已实现头像裁剪、唯一昵称、密码、企划方简介，以及独立的画师简介和题材标签维护

### F2 画师入驻与认证

- 画师提交认证申请：画师简介完整、至少 4 件公开作品、笔名和受支持平台的个人主页地址均为必填
- 管理员可查看申请历史、主页、作品和修改前后差异，并通过或带原因驳回
- 已认证用户修改笔名或常用站时生成独立修改申请；审核期间旧正式资料继续生效
- 应征、创建内容服务板和接受邀请的服务端认证门槛均已实现；应征另要求至少 4 件公开作品
- 用户侧认证状态：未认证 / 审核中 / 已认证；拒绝是申请记录终态，初次申请拒绝后用户恢复未认证

### F3 个人主页与作品集管理

- 个人主页：简介、风格标签、接稿状态、信誉（评分与评价数）、作品展示
- 作品上传 / 删除 / 展示，按分类浏览
- 接稿状态简化：空闲 / 忙碌

> 当前实现进度（2026-08-24）：作品上传、删除、公开/隐藏、作品广场、筛选、公开详情，以及画师/企划方双身份公开主页均已实现；正常用户未认证也可访问画师视角并查看公开作品，页面显示“未认证”，认证只控制交易能力。企划方主页已移除意义不足的需求完成率，角色分离的信誉评分和合作评价已接入。关注画师、收藏作品和收藏橱窗已实现；两种工作台保留共用快捷卡，分别进入画师大厅“关注”、作品广场“我收藏的”和橱窗大厅“我收藏的橱窗”，不再维护独立收藏中心。作品点赞、接稿状态和作品内容编辑仍未实现。

### F4 内容服务板（橱窗）

- 画师发布明码标价服务：名称、类型、价格、交付说明
- 上架 / 下架 / 编辑
- 企划方浏览并「立即下单」，转入订单流程
- 当前实现补充：保留库存、交付时间说明、创作阶段和稿件参数；公开列表只展示上架且有库存的橱窗，详情允许作者和历史买家查看下架/无库存项。存在非终态订单时禁止删除；创建后编辑仅能改库存和补充题材，不能任意重写价格/内容。
- “立即下单”已接入固定价、余额与库存扣减、双方通知、合并会话及正式履约订单。
- 创作阶段编辑器已统一为只编辑名称和顺序，不再录入百分比；既有订单继续读取下单时的阶段快照。
- 当前权限口径：`POST /stalls` 由服务端强制核验正常账号、未删除及 `cert_status=2`；前端入口限制只用于体验，不能替代后端校验。

### F5 企划发布

- 发布表单：标题、需求描述、预算区间、截稿日期、参考图、标签、合作方式
- 企划类型与题材：发布单选头像 / 立绘 / 角色设计 / 插画 / 平面设计 / 自设/OC；题材风格保留 35 个选项可多选，不追加二级原类型。橱窗和作品继续原十类。
- 企划时间：只保留截稿日期；新日期至少为操作当日 +2 天，所选日期当天仍有效，次日由后端查询动态排除并禁止新增应征
- 合作方式：公开招募（全员可见）/ 定向邀请（仅被邀画师可见）
- 企划展示状态：正常上架且未过期为“招募中”，正常上架但日期已过为“已过期”，用户主动下架为“已下架”；自然过期不写入重复状态
- 创作阶段：在“需求详情”页参考图下方配置，默认 `初稿 → 修改 → 终稿`；支持自定义名称、增删和排序，不设置百分比。企划详情在应征画师列表上方展示该创作阶段。
- 发布者管理：企划面板提供完整内容编辑、日期弹窗、上下架/转公开开关及应征/邀请/参与订单管理；完整编辑被有效应征、待处理/已接受邀请或任何未删除历史订单锁定。删除在“我的企划”的独立选择弹窗。重新上架日期至少为操作日 +2 天，已有订单不受来源日期编辑影响。

> 当前实现边界：独立 `recruit_deadline` 已删除。公开大厅、新应征和定向邀请接受统一按 `deadline` 动态判断；已有应征、会话和订单不受过期影响。定向企划详情仅允许创建者、受邀画师、管理员及后续合法关联方读取。

### F6 约稿大厅（企划浏览）

- 企划列表：分页、关键词搜索、筛选（类型、预算区间、截稿时间）
- 企划卡片：标题、摘要、预算、截止时间、应征数
- 简化：取消商业 / 个人 Tab、多维排序、认证企业筛选

### F7 应征与邀请

- 画师应征：个人简介 + 作品链接 + 报价；可查看、撤销
- 企划方查看应征列表并选定画师
- 定向邀请：企划方邀请指定画师，画师接受 / 拒绝
- 公开企划主动邀请：企划方可从认证画师主页发送邀请报价或带价邀请；接受后形成有效应征并自动建立会话，不直接下单

> 当前实现边界：公开应征的认证、4 件公开作品、报价和归属校验已完成。三类邀请均由后端校验发起者、企划状态、目标认证、黑名单关系和响应归属；公开带价邀请当前最低 ¥50 并锁定应征报价。画师个人最低带价金额仍为后续能力。

### F8 订单与模拟资金托管（★核心）

- 企划方可对任意有效应征逐笔创建订单（金额优先取对应应征报价）；一个企划可关联多名画师的独立订单
- 分阶段验收统一称为**创作阶段**。企划默认 `初稿 → 修改 → 终稿`，终稿即最终交付，不再追加独立“交付”阶段；橱窗与企划均以创建时配置的阶段名称和顺序生成订单快照
- 订单状态：待接单 → 进行中 → 待验收 → 已完成 / 已取消 / 争议中
- 模拟托管：下单扣减企划方余额并视为托管；普通阶段通过只进入下一阶段，最终阶段通过或企划方明确“完成交易”时才结算给画师
- **交付水印现状**：每阶段版本支持 1–9 张图，`order_stage.attachments/originals` 分别以逗号分隔存储预览/原图路径；订单详情在交易完成前清空企划方的原图字段，完成后放行，普通非最终阶段验收不开放原图。
- **尚未完成的保护**：没有带业务授权的独立原图下载接口，文件仍在公开 `/uploads/**` 中；须按 CR-002 隔离原图/证据访问。橱窗购买也尚无请求级幂等键（CR-004），已有事务不能防止同一购买的网络重试重复扣款。
- 简化：不做真实支付、充值、提现和手续费；争议已实现双方说明/图片证据及管理员全额退款或全额结算，部分退款仅保留扩展位

> 2026-08-14 实现状态：阶段百分比已退出企划和橱窗发布表单；新企划订单按企划创作阶段生成快照，默认 `初稿 → 修改 → 终稿`，最后阶段验收后直接完成，不再产生额外“交付”阶段（`2172d46`）。

### F9 沟通与消息

- 已完成主体能力：系统通知、1v1 文本/多图私信、会话摘要、未读计数、通知已读、WebSocket JWT 鉴权与多连接推送、事务提交后推送、前端退避重连。
- 已确定规则：同一对用户只保留一条会话；企划作者可对有效应征者主动发起，画师只能在已有会话回复。
- 实现差异：不携带企划/订单 ID 的普通私信尚未校验已有合法会话；双向拉黑校验已存在。会话准入需按 CR-005 整改，WebSocket URL Token 和握手账号状态见 CR-013。
- 2026-08-23 已完成收尾：阶段/订单事件落库与定向推送、双账号实时到达、断线期间落库、重连主动补拉、未读消除和主要系统通知资源跳转均已回归（`32f2bb7`）。
- 已确定不开发订单内独立聊天端点：同一对用户统一使用合并私聊，并以订单状态卡片及 `orderId` 来源校验区分所讨论的订单。

### F10 评价体系

- 完成订单后双方分别拥有 7×24 小时评价期；逾期不自动好评、不计分，期限内提交的评价长期有效。
- 评价包含 1–5 星、最多 500 字文字和可选图片；评价对象由服务端从订单推导，每方每订单最多一次。
- 画师与企划方公开主页按身份分别展示收到的评价；无评价时不显示主页头部评分。
- 画师大厅以真实评分替换账号名，并在企划应征卡和橱窗详情画师卡展示紧凑评分。
- 画师可对收到的评价申请删除，管理员只能批准逻辑隐藏或驳回，处理原因、通知和审计必须完整保留。
- 简化：取消「第 N 次合作」标记、评价回复、点赞和普通评价举报。
- 详细数据结构、接口、安全边界、页面和验收口径见[《评价系统设计计划书》](开发计划/评价系统设计计划书.md)。数据库迁移、正式接口、订单入口、公开展示、申诉治理和自动化验证已于 2026-08-23 完成。

### F11 后台管理

- 已完成管理员统一后端鉴权和只读操作审计。
- 已完成用户永久/限时封禁、自动解封、未结束订单退款和认证审核。
- 已完成双方争议证据、管理员全额退款/全额结算仲裁，以及企划违规下架/恢复。
- 已完成总用户、新增用户、新增订单、完成订单、成交额和用户需求分析等真实统计。
- 已完成账号级黑名单与用户举报治理：黑名单双向限制核心互动，举报按目标用户聚合人数，管理员只记录结论与审计，处罚继续使用既有治理操作。
- 封禁多订单退款、全额退款/全额结算两类仲裁、评价申诉两种终态和限时自动解封已于 2026-08-26 完成专用数据高风险端到端回归；52/52 条真实链路检查及 152 项后端测试通过。
- 已完成用户详情模拟资金维护：“发放资金”追加余额，“余额调整”直接设置最终余额；专用接口由管理员鉴权、事务、用户行锁和操作审计保护，不修改订单与托管历史，也不等同真实充值。
- 已完成“艺绘向导”管理员测试范围：右侧非模态图文会话、约稿需求整理、本人业务只读解释和单轮最多 4 张会话私有参考图。DeepSeek 视觉实验模型已联调；GLM 只保留扩展接口，普通用户开放、跨重启持久化和复杂图大样本评估未完成。

## 10. 风险与注意事项

1. 订单状态机是核心复杂度：先画状态图再编码，避免状态流转遗漏。
2. 资金虽为模拟，但「先验收后结算」逻辑要严格，便于答辩演示。
3. 上传文件限制大小与类型，保存相对路径（`/uploads/xxx`）。
4. 企划截稿日期是招募有效期和订单准时率参考，不是订单交付状态机的截止开关；后续修改企划日期不得回写订单快照。
5. WebSocket 实时链路已有历史回归，但上线前还需处理 URL Token、任意 Origin、握手账号状态等 CR-013 问题，并验证代理配置。
6. 提前准备一套完整演示数据与 15 分钟演示脚本，避免现场造数据。
