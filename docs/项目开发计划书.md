## 1. 项目目标与范围

毕业设计规模的美术约稿交易平台，业务闭环：

**发布需求 → 画师应征 / 定向邀请 → 选定下单 → 沟通修改 → 分阶段验收 → 互相评价**

核心范围：

1. 企划方能力（所有正常登录账号可用）：浏览画师与作品、发布企划（公开招募 / 定向邀请）、管理应征、订单验收与结算，以及完成后 7 天内评价画师。
2. 创作方能力（原则上需画师认证通过）：个人主页与作品集、内容服务板、应征与邀请、订单管理；应征、橱窗创建和邀请创建/响应均已由后端按账号状态、资源关系与 `cert_status=2` 校验。注册 `role` 只决定默认工作台，不代表永久能力边界。
3. 订单流转：下单 → 沟通 → 分阶段验收 → 模拟托管结算 → 评价。
4. 后台管理：用户管理、企划审核、数据统计。

简化处理：

- 注册为**模拟注册**（用户名 + 密码 + 角色），无手机验证码、无短信。
- 资金托管为**模拟**（订单状态流转驱动，不接真实支付）。
- 不做：App、企业财务 / 发票、营销活动大赛、真实支付。

## 3. 功能模块分解（11 个模块）

### F1 用户与认证

- 模拟注册：用户名、密码、昵称、主身份（企划方 / 画师，仅决定默认工作台入口）；用户名和昵称均唯一，管理员不能通过公开注册创建
- 角色模型：**同账号多角色**——发布企划等企划方能力所有登录账号可用；应征、橱窗等画师能力以画师认证（cert_status=2）为准
- 登录：JWT 签发与校验，刷新保持登录
- 个人资料维护：统一 `/settings` 已实现头像裁剪、唯一昵称、密码、企划方简介，以及独立的画师简介和题材标签维护

### F2 画师入驻与认证

- 画师提交认证申请：画师简介完整、至少 4 件公开作品、笔名和受支持平台的个人主页地址均为必填
- 管理员可查看申请历史、主页、作品和修改前后差异，并通过或带原因驳回
- 已认证用户修改笔名或常用站时生成独立修改申请；审核期间旧正式资料继续生效
- 认证通过后才能应征企划；创建内容服务板和响应邀请仍需补齐同一后端认证门槛
- 用户侧认证状态：未认证 / 审核中 / 已认证；拒绝是申请记录终态，初次申请拒绝后用户恢复未认证

### F3 个人主页与作品集管理

- 个人主页：简介、风格标签、接稿状态、信誉（评分与评价数）、作品展示
- 作品上传 / 删除 / 展示，按分类浏览
- 接稿状态简化：空闲 / 忙碌

> 当前实现进度（2026-08-24）：作品上传、删除、公开/隐藏、作品广场、筛选、公开详情，以及画师/企划方双身份公开主页均已实现；正常用户未认证也可访问画师视角并查看公开作品，页面显示“未认证”，认证只控制交易能力。企划方主页已移除意义不足的需求完成率，角色分离的信誉评分和合作评价已接入。关注画师、收藏作品和收藏橱窗已实现；两种工作台保留共用快捷卡，分别进入画师大厅“关注”、作品广场“我收藏的”和橱窗大厅“我收藏的橱窗”，不再维护独立收藏中心。作品点赞、接稿状态和作品内容编辑仍未实现。

### F4 内容服务板（橱窗）

- 画师发布明码标价服务：名称、类型、价格、交付说明
- 上架 / 下架 / 编辑
- 企划方浏览并「立即下单」，转入订单流程
- 当前实现补充：保留库存、截稿时间、创作阶段和稿件参数；公开列表/详情只展示上架且有库存的橱窗，画师可在“我的橱窗”管理下架项，存在未完成订单时禁止删除。
- “立即下单”已接入固定价、余额与库存扣减、双方通知、合并会话及正式履约订单。
- 创作阶段编辑器已统一为只编辑名称和顺序，不再录入百分比；既有订单继续读取下单时的阶段快照。
- 当前权限口径：`POST /stalls` 由服务端强制核验正常账号、未删除及 `cert_status=2`；前端入口限制只用于体验，不能替代后端校验。

### F5 企划发布

- 发布表单：标题、需求描述、预算、截止时间、参考图、标签、合作方式
- 类型与题材：发布时选择类型（同橱窗 10 分类：头像 / 立绘 / 服设 等）与题材风格（35 个选项可多选）
- 招募期：默认 10 日，超过招募期或超过截稿日期自动关闭招募（查询校验 + 定时任务）
- 合作方式：公开招募（全员可见）/ 定向邀请（仅被邀画师可见）
- 企划状态：招募中 / 已选定 / 进行中 / 已完成 / 已关闭
- 创作阶段：在“需求详情”页参考图下方配置，默认 `初稿 → 修改 → 终稿`；支持自定义名称、增删和排序，不设置百分比。企划详情在应征画师列表上方展示该创作阶段。
- 发布者管理：企划详情与“我的企划”共用“变更企划”能力。下架停止公开招募但不影响既有订单；只有从未产生任何订单的企划才可删除。

> 当前实现边界：发布和应征时会校验日期，应征接口会在招募期到期后拒绝新应征；但企划列表尚未按 `recruit_deadline` 自动过滤，未实现招募期/截稿期定时改状态，定向企划详情也未完全限制为被邀画师可见，因此自动关闭与定向可见性仍是部分完成。

### F6 约稿大厅（企划浏览）

- 企划列表：分页、关键词搜索、筛选（类型、预算区间、截稿时间）
- 企划卡片：标题、摘要、预算、截止时间、应征数
- 简化：取消商业 / 个人 Tab、多维排序、认证企业筛选

### F7 应征与邀请

- 画师应征：个人简介 + 作品链接 + 报价；可查看、撤销
- 企划方查看应征列表并选定画师
- 定向邀请：企划方邀请指定画师，画师接受 / 拒绝

> 当前实现边界：公开应征的认证、4 件公开作品、报价和归属校验已完成；邀请创建/响应已有基本归属校验，但尚未统一验证发起者资格、被邀请画师认证状态及对应定向企划关系。

### F8 订单与模拟资金托管（★核心）

- 企划方可对任意有效应征逐笔创建订单（金额优先取对应应征报价）；一个企划可关联多名画师的独立订单
- 分阶段验收统一称为**创作阶段**。企划默认 `初稿 → 修改 → 终稿`，终稿即最终交付，不再追加独立“交付”阶段；橱窗与企划均以创建时配置的阶段名称和顺序生成订单快照
- 订单状态：待接单 → 进行中 → 待验收 → 已完成 / 已取消 / 争议中
- 模拟托管：下单扣减企划方余额并视为托管；普通阶段通过只进入下一阶段，最终阶段通过或企划方明确“完成交易”时才结算给画师
- **交付水印保护**：画师交付阶段提交附件时，企划方仅能看到带水印的低像素预览图；只有企划方确认收货（验收通过）后，才能下载高清无水印原图
  - 实现要点：附件区分为「预览图（水印 / 低像素）」与「原图（高清）」，原图下载接口在订单阶段验收通过后才放行
  - 数据落地：`order_stage.attachments` 记录预览图；原图另行存储（如 `order_stage.originals` 或独立附件表），并记录验收时间作为放行依据
- 简化：不做真实支付、充值、提现和手续费；争议已实现双方说明/图片证据及管理员全额退款或全额结算，部分退款仅保留扩展位

> 2026-08-14 实现状态：阶段百分比已退出企划和橱窗发布表单；新企划订单按企划创作阶段生成快照，默认 `初稿 → 修改 → 终稿`，最后阶段验收后直接完成，不再产生额外“交付”阶段（`2172d46`）。

### F10 评价体系

- 完成订单后双方分别拥有 7×24 小时评价期；逾期不自动好评、不计分，期限内提交的评价长期有效。
- 评价包含 1–5 星、最多 500 字文字和可选图片；评价对象由服务端从订单推导，每方每订单最多一次。
- 画师与企划方公开主页按身份分别展示收到的评价；无评价时不显示主页头部评分。
- 画师大厅以真实评分替换账号名，并在企划应征卡和橱窗详情画师卡展示紧凑评分。
- 画师可对收到的评价申请删除，管理员只能批准逻辑隐藏或驳回，处理原因、通知和审计必须完整保留。
- 简化：取消「第 N 次合作」标记、评价回复、点赞和普通评价举报。
- 详细数据结构、接口、安全边界、页面和验收口径见[《评价系统设计计划书》](评价系统设计计划书.md)。数据库迁移、正式接口、订单入口、公开展示、申诉治理和自动化验证已于 2026-08-23 完成。

## 6. 数据库设计要点

命名规范：小写下划线，`id BIGINT AUTO_INCREMENT`，必备 `created_at` / `updated_at`，状态用 `TINYINT` + 后端枚举。

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `user` | 用户（含角色与认证状态） | username、password、nickname、avatar、bio、employer_bio、tags、artist_name、artist_site、role、cert_status、status |
| `work` | 作品集 | user_id、title、category、image |
| `stall` | 内容服务板 | painter_id、title、category、price、description、status |
| `project` | 企划 | employer_id、title、description、budget、deadline、tags、images、mode（公开 / 定向）、recruit_deadline、phases（创作阶段）、status |
| `application` | 应征 | project_id、painter_id、intro、work_link、quote、status |
| `invitation` | 定向邀请 | project_id、painter_id、status（待处理 / 接受 / 拒绝） |
| `order_info` | 订单 | project_id、stall_id、employer_id、painter_id、amount、status（0 待接单 / 1 进行中 / 2 待验收 / 3 已完成 / 4 已取消 / 5 争议中） |
| `order_stage` | 订单创作阶段 | order_id、name、sort/order、status；历史 percent 仅兼容旧数据，不再由用户填写 |
| `message` | 站内消息 / 聊天 | from_id、to_id、order_id、type、content、read_at |
| `review` | 评价 | order_id、from_id、to_id、score、content |
| `review_image` | 评价图片 | review_id、image_url、sort_order |
| `review_appeal` | 画师评价申诉 | review_id、applicant_id、reason、status、admin_id、decision_reason、decided_at |
| `user_follow` | 用户关注认证画师 | user_id、painter_id、created_at；用户与目标唯一 |
| `work_favorite` | 用户收藏公开作品 | user_id、work_id、created_at；用户与作品唯一 |
| `stall_favorite` | 用户收藏上架橱窗 | user_id、stall_id、created_at；用户与橱窗唯一 |

> 说明：订单表在库中命名为 `order_info`（`order` 为 MySQL 保留字），实体类名仍为 `Order`。

ER 关系：企划 1—N 应征；画师 1—N 作品 / 服务板；订单 1—N 阶段；订单关联企划或服务板；用户分别通过三张关系表 N—N 关注认证画师、收藏作品和收藏橱窗。当前 `init.sql` 共 20 张表，建表脚本见 [../backend/sql/init.sql](../backend/sql/init.sql)；最终 ER 图尚未生成，纳入阶段 6 答辩材料收尾。
