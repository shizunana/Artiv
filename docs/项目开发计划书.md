## 1. 项目目标与范围

毕业设计规模的美术约稿交易平台，业务闭环：

**发布需求 → 画师应征 / 定向邀请 → 选定下单 → 沟通修改 → 分阶段验收 → 互相评价**

核心范围：

1. 企划方能力（所有账号可用）：浏览画师与作品、发布企划（公开招募 / 定向邀请）、管理应征、订单验收与结算、评价。
2. 创作方能力（需画师认证通过）：个人主页与作品集、内容服务板、应征与邀请、订单管理、评价。
3. 订单流转：下单 → 沟通 → 分阶段验收 → 模拟托管结算 → 评价。
4. 后台管理：用户管理、企划审核、数据统计。

简化处理：

- 注册为**模拟注册**（用户名 + 密码 + 角色），无手机验证码、无短信。
- 资金托管为**模拟**（订单状态流转驱动，不接真实支付）。
- 不做：App、企业财务 / 发票、营销活动大赛、真实支付。

## 3. 功能模块分解（11 个模块）

### F1 用户与认证

- 模拟注册：用户名、密码、昵称、主身份（企划方 / 画师 / 管理员，仅决定默认工作台入口）
- 角色模型：**同账号多角色**——发布企划等企划方能力所有登录账号可用；应征、橱窗等画师能力以画师认证（cert_status=2）为准
- 登录：JWT 签发与校验，刷新保持登录
- 个人资料维护：头像、昵称、简介、标签

### F2 画师入驻与认证

- 画师提交认证申请（作品 + 简介）
- 管理员审核通过后才能接稿、开设内容服务板
- 认证状态：未认证 / 审核中 / 已认证 / 已驳回

### F3 个人主页与作品集管理

- 个人主页：简介、风格标签、接稿状态、信誉（评分与评价数）、作品展示
- 作品上传 / 删除 / 展示，按分类浏览
- 接稿状态简化：空闲 / 忙碌

### F4 内容服务板（橱窗）

- 画师发布明码标价服务：名称、类型、价格、交付说明
- 上架 / 下架 / 编辑
- 企划方浏览并「立即下单」，转入订单流程
- 简化：取消库存、已售、截稿时间、创作阶段参数等商品化字段

### F5 企划发布

- 发布表单：标题、需求描述、预算、截止时间、参考图、标签、合作方式
- 类型与题材：发布时选择类型（同橱窗 10 分类：头像 / 立绘 / 服设 等）与题材风格（35 个选项可多选）
- 招募期：默认 10 日，超过招募期或超过截稿日期自动关闭招募（查询校验 + 定时任务）
- 合作方式：公开招募（全员可见）/ 定向邀请（仅被邀画师可见）
- 企划状态：招募中 / 已选定 / 进行中 / 已完成 / 已关闭

### F6 约稿大厅（企划浏览）

- 企划列表：分页、关键词搜索、筛选（类型、预算区间、截稿时间）
- 企划卡片：标题、摘要、预算、截止时间、应征数
- 简化：取消商业 / 个人 Tab、多维排序、认证企业筛选

### F7 应征与邀请

- 画师应征：个人简介 + 作品链接 + 报价；可查看、撤销
- 企划方查看应征列表并选定画师
- 定向邀请：企划方邀请指定画师，画师接受 / 拒绝

### F8 订单与模拟资金托管（★核心）

- 选定画师后创建订单（金额取企划预算或画师报价）
- 分阶段验收：初稿 → 修改 → 终稿 → 交付，按阶段提交与验收
- 订单状态：待接单 → 进行中 → 待验收 → 已完成 / 已取消 / 争议中
- 模拟托管：下单即视为托管，阶段验收通过即结算；争议由管理员处理
- **交付水印保护**：画师交付阶段提交附件时，企划方仅能看到带水印的低像素预览图；只有企划方确认收货（验收通过）后，才能下载高清无水印原图
  - 实现要点：附件区分为「预览图（水印 / 低像素）」与「原图（高清）」，原图下载接口在订单阶段验收通过后才放行
  - 数据落地：`order_stage.attachments` 记录预览图；原图另行存储（如 `order_stage.originals` 或独立附件表），并记录验收时间作为放行依据
- 简化：取消钱包、提现、手续费、详细仲裁流程

### F9 沟通与消息

- 站内信 + WebSocket 实时推送（应征通知、验收结果、订单变化、系统通知）
- 消息已读 / 全部已读

### F10 评价体系

- 交易完成后双方互评（评分 + 内容）
- 画师主页展示评分与评价数
- 简化：取消「第 N 次合作」标记、评价举报

### F11 后台管理

- 用户管理：封禁 / 解封、画师认证审核
- 企划管理：上架 / 下架 / 驳回
- 数据统计：注册量、订单量、成交额

## 5. 后端接口规划

统一前缀 `/api/v1`，返回 `{ code, message, data }`。

| 模块 | 接口 |
| --- | --- |
| 认证 | `POST /auth/register`（模拟注册）、`POST /auth/login`、`GET /auth/me` |
| 用户 | `PUT /users/{id}`、`PUT /users/{id}/avatar`、`GET /users/{id}`、`GET /users/{id}/works`、`GET /users/me/notifications` |
| 作品 | `POST /works`、`DELETE /works/{id}`、`GET /works`（公开浏览） |
| 企划 | `POST /projects`、`GET /projects`、`GET /projects/{id}`、`PUT /projects/{id}`、`DELETE /projects/{id}` |
| 应征 | `POST /projects/{id}/applications`、`GET /projects/{id}/applications`、`DELETE /applications/{id}` |
| 服务板 | `POST /stalls`、`GET /stalls`、`GET /stalls/{id}`、`PUT /stalls/{id}`、`POST /stalls/{id}/purchase` |
| 邀请 | `POST /invitations`、`PUT /invitations/{id}/respond` |
| 订单 | `POST /orders`、`GET /orders`、`GET /orders/{id}`、`PUT /orders/{id}/stage`、`PUT /orders/{id}/status`、`POST /orders/{id}/messages` |
| 评价 | `POST /orders/{id}/review`、`GET /reviews` |
| 消息 | `GET /messages`、`PUT /messages/{id}/read`、`PUT /messages/read-all`、`WS /ws?token=` |
| 后台 | `GET /admin/users`、`PUT /admin/users/{id}/status`、`GET /admin/projects`、`PUT /admin/projects/{id}/status`、`GET /admin/stats` |
| 上传 | `POST /upload`（≤5MB，png / jpg / jpeg / gif / webp） |

## 6. 数据库设计要点

命名规范：小写下划线，`id BIGINT AUTO_INCREMENT`，必备 `created_at` / `updated_at`，状态用 `TINYINT` + 后端枚举。

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `user` | 用户（含角色与认证状态） | username、password、nickname、avatar、bio、tags、role、cert_status、status |
| `work` | 作品集 | user_id、title、category、image |
| `stall` | 内容服务板 | painter_id、title、category、price、description、status |
| `project` | 企划 | employer_id、title、description、budget、deadline、tags、images、mode（公开 / 定向）、recruit_deadline、status |
| `application` | 应征 | project_id、painter_id、intro、work_link、quote、status |
| `invitation` | 定向邀请 | project_id、painter_id、status（待处理 / 接受 / 拒绝） |
| `order_info` | 订单 | project_id、stall_id、employer_id、painter_id、amount、status（0 待接单 / 1 进行中 / 2 待验收 / 3 已完成 / 4 已取消 / 5 争议中） |
| `order_stage` | 订单阶段 | order_id、name、percent、status |
| `message` | 站内消息 / 聊天 | from_id、to_id、order_id、type、content、read_at |
| `review` | 评价 | order_id、from_id、to_id、score、content |

> 说明：订单表在库中命名为 `order_info`（`order` 为 MySQL 保留字），实体类名仍为 `Order`。

ER 关系：企划 1—N 应征；画师 1—N 作品 / 服务板；订单 1—N 阶段；订单关联企划或服务板。ER 图见 [ER图.png](ER图.png)，建表脚本见 [../backend/sql/init.sql](../backend/sql/init.sql)。

## 7. 开发顺序（阶段任务）

### 阶段 0：环境与骨架（1 天）

- 初始化 `frontend/`（Vite + Vue3 + Pinia + Router + Axios）与 `backend/`（Spring Boot 3 + MyBatis-Plus + JWT）
- 配置 Vite 代理（`/api`、`/ws` → 8080）、Git 分支（main / dev）

### 阶段 1：建库建表 + 后端认证（3 天）

- 编写 `sql/init.sql`（10 张核心表 + 演示数据）
- 统一返回体、全局异常、JWT 登录拦截器
- 模拟注册（用户名 + 密码 + 角色）、登录、当前用户
- 验证：Postman 调通注册 / 登录

### 阶段 2：前端骨架与登录注册（3 天）

- 整体布局（顶部导航 / 页脚）、Axios 封装、路由守卫
- 登录页、模拟注册页（选角色）
- 验证：能登录并跳转、刷新保持登录、未登录访问工作台自动跳登录

### 阶段 3：核心闭环：企划—应征—订单—验收（6–7 天）★

- 企划发布 / 列表筛选 / 详情 / 修改 / 下架，招募期自动关闭
- 画师应征（查看 / 撤销）、企划方选定画师、定向邀请
- 订单创建、阶段提交与验收、订单状态流转、模拟托管结算
- 验证：完整走通「发布 → 应征 → 选定 → 下单 → 阶段验收 → 完成 → 评价」

### 阶段 4：消息、个人中心、作品与服务板（5 天）

- WebSocket 实时推送（应征 / 订单 / 系统通知）+ 站内信已读
- 个人资料编辑、画师认证申请与审核状态展示
- 作品上传管理、服务板创建 / 上下架 / 立即下单

### 阶段 5：管理后台、演示数据、打磨（3 天）

- 用户管理（封禁 / 解封、认证审核）、企划审核、数据统计
- 完善演示数据、空态 / 加载 / 错误提示、移动端适配

### 阶段 6：测试、部署、答辩材料（3 天）

- 全链路回归与权限用例（越权访问、超招募期、状态非法流转）
- 前端 `npm run build`、后端 `mvn clean package -DskipTests`、Nginx 部署
- 准备 15 分钟演示脚本、接口文档、ER 图、答辩素材

## 10. 风险与注意事项

1. 订单状态机是核心复杂度：先画状态图再编码，避免状态流转遗漏。
2. 资金虽为模拟，但「先验收后结算」逻辑要严格，便于答辩演示。
3. 上传文件限制大小与类型，保存相对路径（`/uploads/xxx`）。
4. 招募期自动关闭用「查询校验 + 定时任务」双保险。
5. WebSocket 需处理断线重连，消息必须落库。
6. 提前准备一套完整演示数据与 15 分钟演示脚本，避免现场造数据。
