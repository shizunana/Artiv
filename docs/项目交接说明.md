## 1. 项目一句话定位

绘约是一个面向**企划方与自由画师**的美术约稿交易平台（毕业设计），前后端分离：Vue 3 + Spring Boot 3 + MySQL 8。

## 5. 启动方式

1. 启动 MySQL80 服务（手动启动类型，重启电脑后需手动启）
2. 执行 `backend/sql/init.sql`（如需重置演示数据）
3. 后端：`cd backend && mvn spring-boot:run`（8080）
4. 前端：`cd frontend && npm.cmd run dev`（5173，PowerShell 下用 npm.cmd）

## 7. 核心业务规则（务必遵守）

### 7.1 角色模型

- **同账号多角色**：发布企划等企划方能力所有登录账号可用；应征、橱窗等画师能力以画师认证（cert_status=2）为准
- 画师认证：未认证(0) → 审核中(1) → 已认证(2) / 已驳回(3)；已认证/审核中不可重复申请

### 7.2 类型与题材

- 类型（category）：10 个固定分类（头像/Q版全身/半身像/立绘/组合页/服设/壁纸/表情包/Live2d/平面设计），橱窗与企划共用（`constants/subjects.js`）
- 题材风格（subject）：35 个选项（同文件），橱窗存 params JSON，企划存独立列
- 橱窗公开规则：列表与详情只开放上架橱窗；画师“我的橱窗”可见本人下架项，但须先上架才能查看公开详情。删除会同时下架并逻辑删除。

### 7.3 订单状态机（设计，待编码）

```
待接单(0) → 进行中(1) → 待验收(2) → 已完成(3)
    └→ 已取消(4) ｜ 争议中(5)（管理员仲裁）
```

接单前流程：多画师应征 → 1v1 私聊 → 选定 → 创建订单 → 议价（画师报价/企划方确认）→ 画师接单（锁价）

## 8. 代码约定

- 接口前缀：`/api/v1`；返回统一 `{ code, message, data }`（`common/Result`）
- 状态用 TINYINT + 后端枚举（前端映射在 `utils/status.js`）
- 登录拦截器：`security/AuthInterceptor`——仅 GET 的列表/数字 ID 详情公开，其余需登录
- 错误码：200 成功、400/401/403/404/500、1001 用户名存在、2001 参数、2003 无权、3001 状态流转不合法、4001 上传非法
- Git：`main`（稳定）+ `dev`（开发）；提交信息 `feat:/fix:/docs:` 前缀

## 9. 环境注意（常见坑）

- **MySQL80 是手动启动**：重启电脑后后端全部 500（Connection refused），需启动 MySQL80 服务
- **npm 在 PowerShell 报执行策略**：用 `npm.cmd` 代替
- **上传文件**保存在 `backend/uploads/`（git 忽略），Vite 已代理 `/uploads`
- 后端启动用 `mvn spring-boot:run`（本机 Maven 本地仓库 `C:\Users\95847\.m2\repository`）
