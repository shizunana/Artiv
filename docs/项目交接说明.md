# 艺绘（Artiv）项目交接说明

> 用途：切换开发模型 / 开发者时，用本文件快速了解项目全貌并接续开发。
> 最近更新：2026-08-29

## 1. 项目一句话定位

艺绘是一个面向**企划方与自由画师**的美术约稿交易平台（毕业设计），前后端分离：Vue 3 + Spring Boot 3 + MySQL 8。

## 7. 核心业务规则（务必遵守）

### 7.1 角色模型

- **同账号多角色**：普通账号的 `role=1/2` 只决定默认工作台，权限没有差异；点击工作台切换会持久化该偏好并在刷新后保持。发布企划等企划方能力所有正常登录账号可用，应征、橱窗和邀请等画师交易能力以正常账号、未删除及 `cert_status=2` 为准。画师大厅与后台供需统计也只按认证状态统计，不再错误排除默认企划方工作台的认证画师。`role=3` 仍保留为管理员安全角色，不能调用普通工作台切换接口。
- 画师认证用户态：未认证(0) → 审核中(1) → 已认证(2)，初次申请被拒后恢复未认证；“已驳回”只属于申请记录终态。已认证用户修改笔名/常用站生成独立待审申请，认证状态和旧正式资料在审核期间保持不变。
- 公开画师主页不以认证为准入条件：所有正常用户都可访问 `role=painter` 视图和公开作品，页面按 `cert_status` 显示“认证画师”或“未认证”；认证仍只控制应征等交易能力。企划方主页不展示需求完成率。

### 7.2 类型与题材

- 类型（category）：10 个固定分类（头像/Q版全身/半身像/立绘/组合页/服设/壁纸/表情包/Live2d/平面设计），橱窗创建、橱窗大厅、作品与企划共用（`constants/subjects.js`）；创建橱窗后端也执行相同白名单校验。
- 题材风格（subject）：35 个选项（同文件），橱窗存 params JSON，企划存独立列
- 橱窗公开规则：大厅仅展示上架且库存大于 0 的橱窗。所属画师可查看本人下架/无库存项；已有订单的企划方可从订单查看对应下架/无库存橱窗。下架不改变订单；存在未完成订单时禁止删除，其他情况删除会同时下架并逻辑删除。“我的橱窗”仅保留统一“编辑”入口，上下架与删除均在详情编辑弹窗内操作。

### 7.3 订单状态机（橱窗订单与企划订单主链路均已接入）

```
待接单(0) → 进行中(1) → 待验收(2) → 已完成(3)
    └→ 已取消(4) ｜ 争议中(5)（管理员仲裁）
```

橱窗接单前流程：固定价橱窗 → 确认下单 → 扣减余额与库存 → 画师接单。企划订单流程：多画师应征 → 1v1 私聊 → 企划方按应征逐笔发单 → 按报价扣减余额 → 画师接单。两种来源共用履约状态机。

### 7.4 企划创作阶段与企划管理规则（已实现）

- 全项目统一术语为“创作阶段”，不再使用“交付流程”指代阶段配置。
- 发布企划在需求详情的参考图下配置创作阶段；默认三阶段：初稿、修改、终稿，支持自定义名称/增删/排序，不提供百分比。
- 企划详情在应征画师列表上方展示创作阶段；订单创建时复制阶段快照，历史订单不受企划后续修改影响。
- 企划发布者从“我的企划”的“企划面板”执行完整内容编辑、变更企划、应征沟通/发单、邀请和参与订单管理；卡片只保留“企划详情 / 企划面板”。“编辑企划”在存在有效应征、有效邀请或任何历史订单时锁定，“变更企划”仍独立处理截稿日期、上下架和删除。被拒绝的定向企划改为公开后会移动到公开分组。
- 画师“收到的邀请”只是提醒箱：状态为待处理、已接受、已拒绝、已失效，类型为定向邀请、邀请报价、带价邀请；所有状态都可删除提醒，实际只隐藏当前画师列表记录。待处理提醒被隐藏后仍不等于拒绝，合法企划详情入口仍可处理原邀请。
- 下架只停止大厅展示、新应征和新发单，不影响既有订单及订单双方访问；只要企划存在任何状态的关联订单，就禁止删除。
- 橱窗创建/修改同样移除创作阶段百分比，仅保留名称和顺序。

数据库：升级现有库需执行一次 `backend/sql/20260814_p0_project_phase_management.sql`；全新建库的 `backend/sql/init.sql` 已包含 `project.phases`。当前本地 `artiv` 库已执行迁移。

### 7.5 管理后台规则（已实现）

- 升级现有数据库先执行 `backend/sql/migrations/20260820_admin_backend.sql`；脚本只新增字段、表和索引，并会迁移旧“审核中认证”和旧 `status=5` 售后记录，可安全重复执行。当前本地库已执行，执行前备份位于系统临时目录。
- 再执行 `backend/sql/migrations/20260823_profile_certification.sql`：新增双身份简介、正式认证资料和申请类型/旧值快照，迁移历史数据并修复没有待审记录的孤立审核中状态；脚本已在本地 MySQL 重复执行验证。
- `/api/v1/admin/**` 必须由后端按数据库 `role=3` 和正常账号状态校验，前端路由不构成安全边界。
- 被封禁用户仍可登录和浏览，但不能发布企划、应征、创建橱窗、购买橱窗或发送新企划订单；封禁会在同一事务内取消并退款其全部未结束订单，橱窗订单恢复库存。
- 争议允许企划方或画师发起；证据仅包括双方主动提交的 1–9 张图片、说明和订单事件，管理员不得读取无关私聊。首期只允许全额退款企划方或全额结算画师。
- 企划违规下架使用独立 `moderation_status`，不修改业务状态；停止公开展示和新应征，但现有应征仍可沟通/发单，已有订单仍能访问来源快照。
- 数据统计默认进入用户需求分析，总用户、新增用户、新增订单、完成订单和成交额五项基础指标在需求与运营标签均显示；成交额只按已完成订单的 `completed_at` 汇总。

## 8. 代码约定

- 接口前缀：`/api/v1`；返回统一 `{ code, message, data }`（`common/Result`）
- 状态用 TINYINT + 后端枚举（前端映射在 `utils/status.js`）
- 登录拦截器：`security/AuthInterceptor`——仅 GET 的列表/数字 ID 详情公开，其余需登录
- 错误码：200 成功、400/401/403/404/500、1001 用户名存在、1004 昵称存在、2001 参数、2003 无权、3001 状态流转不合法、4001 上传非法；其中 `2003` 使用真实 HTTP 403 并保留统一响应体
- Git：`main`（稳定）+ `dev`（开发）；提交信息 `feat:/fix:/docs:` 前缀

## 9. 环境注意（常见坑）

- **MySQL80 是手动启动**：重启电脑后后端全部 500（Connection refused），需启动 MySQL80 服务
- **npm 在 PowerShell 报执行策略**：用 `npm.cmd` 代替
- **上传文件**保存在 `backend/uploads/`（git 忽略），Vite 已代理 `/uploads`
- 上传文件不进入 Git；2026-08-18 审计确认 Git 索引中上传文件为 0。当前每次上传保留 UUID 独立文件，避免共享物理文件带来的误删、替换和授权耦合；历史重复文件因可能被数据库路径引用而未自动删除，清理前必须执行引用审计，详见《上传文件存储审计.md》。
- 作品广场当前每批 25 件自动加载，画师大厅每批 10 人自动加载，均不再显示传统分页器。画师大厅服务端已使用数据库分页，评分、分类和最近 5 件公开作品只按当前页画师批量聚合。
- 公开主页统一为 `/profiles/{id}?role=painter|employer`；正常账号两种视图均可访问，作品/橱窗每批 20 项，企划每批 12 项自动加载。公开资料接口不得扩展用户名、余额、手机号、私聊或后台认证材料。
- 后端启动用 `mvn spring-boot:run`（本机 Maven 本地仓库 `C:\Users\95847\.m2\repository`）
