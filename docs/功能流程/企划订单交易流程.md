# 艺绘（Artiv）企划订单交易流程

> 版本：v1.4（正式订单 + 创作阶段 + 统一截稿日期）
> 最后更新：2026-08-26
> 当前状态：**企划正式订单、阶段快照、消息通知、企划管理与统一截稿日期规则已实现并联调**
> 范围：企划应征通知 → 企划方选择一名或多名应征画师 → 分别发送企划订单 → 复用现有订单履约、交付、验收与结算流程。  
> 流程图源文件：[企划订单交易状态流转.mmd](企划订单交易状态流转.mmd)、[企划订单多画师角色流程.mmd](企划订单多画师角色流程.mmd)

## 1. 本轮确认的核心规则

1. 画师应征企划后，企划方收到“收到新的企划应征”系统通知；通知按钮显示“查看应征”，点击后跳转到对应企划详情 `/projects/{projectId}`。
2. 应征不会自动创建订单，也不会自动创建新的私聊分身。企划方仍可先从应征列表主动与画师建立沟通，在双方合并私聊中确认价格和要求。
3. 企划发布者可以对**任意有效应征画师**点击“发送企划订单”。画师不能主动创建企划订单。
4. 一个企划允许同时向多名应征画师分别发送订单，形成“一个企划 → 多名画师 → 多笔独立订单”的一对多关系。
5. 不再限制“一个企划只能有一笔有效订单”。不同画师的订单互不影响；某位画师拒单、某笔订单取消或售后，不会重开、关闭或回退整个企划。
6. 同一个企划、同一条应征在同一时间最多保留一笔非终态订单，防止重复点击生成重复订单。存在非终态订单时，画师卡片按钮显示禁用状态“已发送”。订单取消或被拒绝后，企划方可以基于原应征再次发送；订单完成结算后，该应征自动退出列表，画师必须重新应征才能再次获得该企划订单。
7. 点击“发送企划订单”后打开与橱窗“立即下单”一致的确认订单弹窗，不填写委托备注，也不进入真实支付页面。
8. 订单金额由服务端读取该应征的有效报价；若历史应征没有有效报价，才回退到企划预算。前端展示金额但不能自报或修改金额。
9. 每笔企划订单独立扣减企划方余额、独立等待画师接单、独立交付、独立结算和独立售后。企划订单没有库存扣减与库存恢复。
10. 订单创建后的接单、单图交稿、水印预览、要求修改、阶段通过、跨阶段直接完成、原图解锁、结算、售后登记与订单状态卡片，全部复用现有橱窗订单状态机。
11. 全项目统一使用“创作阶段”术语；默认企划阶段为 `初稿 → 修改 → 终稿`，终稿就是最终交付，不生成独立“交付”阶段，也不让用户配置阶段百分比。
12. 接单和阶段提交的订单事件、系统通知及会话系统提示统一包含画师展示名和企划标题快照；标题超过 10 字时显示前 10 字加 `...`，交稿通知使用真实阶段名。
13. 企划方主动取消通知为 `订单「企划标题」已取消，托管金额已退回：取消理由`；标题仍读取订单快照，不受来源企划后续编辑影响。
14. 企划只保留一个截稿日期。该日期在企划层控制公开大厅、新应征和待处理邀请接受，日期当天仍有效；已有应征、会话与订单不受过期影响。
15. 创建企划订单时把截稿日期写入订单快照，作为后续准时交稿率的统计基准；企划方之后延长或修改企划日期，不回写历史订单。

## 2. 企划应征通知与跳转

### 2.1 通知产生

画师成功提交应征后，继续使用现有 `APPLICATION_CREATED` 系统通知：

- 接收者：企划发布者；
- 关联数据：通知记录保存 `projectId`，正文保存提交时的画师展示名和企划标题；
- 固定正文：`画师「展示名」应征了您的企划「企划标题」。`；展示名优先昵称、其次登录名，仅异常资料回退内部 ID；
- 按钮文字：`查看应征`；
- 目标路由：`/projects/{projectId}`；
- 页面行为：进入企划详情后展示公开应征画师列表，企划发布者可在对应画师卡片执行私信或发送企划订单。

### 2.2 异常处理

- 企划不存在或已删除：提示“企划不存在或已删除”，不跳转空白页面。
- 应征已撤销：仍可进入企划详情，但已撤销画师不出现在有效应征列表。
- 通知缺少 `projectId` 的旧测试数据：只显示通知内容，不展示可点击的“查看应征”。

> 本节已实现并完成前端路由回归：`APPLICATION_CREATED.projectId` 直接映射企划详情，不再进入单独的应征占位页。

## 3. 一企划多画师、多订单模型

### 3.1 关系说明

```text
企划 A
├─ 应征画师 1 ── 企划订单 A-1（独立金额、状态、交付和结算）
├─ 应征画师 2 ── 企划订单 A-2（独立金额、状态、交付和结算）
└─ 应征画师 3 ── 可继续沟通，尚未发送订单
```

### 3.2 必须保持的隔离

- 订单 A-1 被拒绝，不改变 A-2，也不改变企划 A 的招募状态。
- 订单 A-1 完成，不代表企划 A 的其他订单完成。
- 订单 A-1 申请售后，只冻结/标记 A-1 对应金额，不影响其他画师订单。
- 每创建一笔订单都重新校验企划方余额；余额不足时只阻止当前订单创建。
- 企划自然过期只负责停止新应征和待处理邀请接受，不自动取消已经创建的订单，也不阻止基于已有有效应征继续发单。
- 企划详情中的应征列表继续公开展示；订单详情只允许该笔订单的企划方与对应画师查看。

### 3.3 企划状态与订单状态解耦

企划是招募资源，订单是履约资源。单笔订单不再驱动企划状态在“招募中/已选定/进行中”之间来回切换。

- 是否继续接受新应征，由企划唯一的截稿日期和“主动下架”共同决定；不再维护独立招募截止时间。
- 已经创建的企划订单，即使企划停止招募，也继续正常履约。
- 截稿日期当天仍可招募，进入次日才动态判定过期；自然过期不修改企划持久状态。
- 企划的最终完成/归档规则后续单独设计，不以任意一笔子订单完成作为整个企划完成条件。

## 4. 发送企划订单

### 4.1 前端入口

入口位于企划详情的应征画师卡片右上角，仅企划发布者可见：

- `私信`：进入/创建与该画师的企划沟通引导消息；
- `发送企划订单`：打开确认订单弹窗；
- 普通访问者看不到以上按钮；
- 应征画师在自己的卡片上仍使用“取消应征/更改报价”，不显示发送订单。

### 4.2 确认订单弹窗

弹窗复用橱窗订单确认页的布局与交互，展示：

- 企划标题和第一张参考图；
- 被选中的画师昵称与头像；
- 应征报价（订单金额）；
- 企划截稿日期（约定参考，创建订单后写入快照）；
- 企划类型、题材风格、稿件格式、尺寸、发布权限等要求摘要；
- 企划创建时配置的创作阶段快照和交易说明；
- `取消`、`确认发送订单`。

本弹窗不提供：

- 修改价格；
- 填写委托备注；
- 支付渠道选择；
- 同时勾选多名画师批量创建。企划方应在每名画师卡片上逐笔确认，避免误下多单。

### 4.3 服务端创建校验

确认创建时必须在一个事务中完成：

1. 当前用户是企划发布者；
2. 企划存在且未删除；
3. 应征属于该企划，且为有效应征；
4. 应征画师账号正常且仍为已认证画师；
5. 不允许企划方给自己发送订单；
6. 应征报价为正数；无有效报价时才使用企划预算；
7. 企划方余额足够支付这一笔订单；
8. 同一 `projectId + applicationId` 不存在待接单、进行中、待确认或售后中的订单；
9. 锁定企划方余额与应征记录，避免双击或并发请求重复扣款；
10. 创建订单失败时，余额、订单、通知和消息必须全部回滚。

### 4.4 订单创建结果

创建成功后：

- `order_info.project_id` 指向来源企划；
- `order_info.stall_id` 为空，订单来源为 `project`；
- 记录 `applicationId`，明确订单来自哪一条应征；
- `employer_id` 为企划发布者，`painter_id` 为应征画师；
- 金额取服务端确认的应征报价；
- 企划方余额按现有简化托管方式立即扣除；
- 订单进入“待画师接单”；
- 创建企划标题、封面、需求、稿件参数、报价和阶段快照，后续企划修改、关闭或删除不改变既有订单内容；
- 向双方写入订单事件、系统通知和合并私聊中的企划订单卡片；
- 订单卡片携带 `orderId` 和 `source=project`，“查看详情”进入该笔企划订单详情。

## 5. 企划订单状态流转

| 状态 | 企划方操作 | 画师操作 | 资金 | 对企划其他订单的影响 |
| --- | --- | --- | --- | --- |
| 待画师接单 | 取消订单 | 确认接单 / 拒绝 | 已从企划方余额扣除，尚未结算 | 无 |
| 进行中 | 查看进度、申请售后 | 上传当前阶段 1–9 张原图 | 保持托管 | 无 |
| 待确认 | 查看水印预览、要求修改、通过阶段、直接完成 | 等待验收 | 保持托管 | 无 |
| 已完成 / 待评价 | 下载本次确认交付的高清原图、7 天内评价画师 | 查看结算、7 天内评价企划方 | 立即增加至该画师余额 | 无 |
| 已取消 | 查看记录 | 查看记录 | 退回企划方余额 | 无；可再次向同一应征发送订单 |
| 退款/售后 | 发起售后并填写原因 | 联系客服（预留） | 本轮保持托管并记录状态 | 无 |

### 5.1 接单与取消

- 画师确认接单：该笔订单进入进行中，不修改企划及其他画师订单。
- 画师拒绝：只取消该笔订单并退回金额；应征关系仍保留，便于双方继续沟通或后续重新发单。
- 企划方在待接单阶段取消：只取消该笔订单并退回金额。
- 企划订单没有橱窗库存，因此拒绝/取消时不执行库存恢复。
- 企划订单完成结算时，仅将该订单对应的应征转为已撤销并退出应征画师列表；不影响该企划下其他画师的应征和订单。该画师后续重新应征后，才能再次获得该企划订单。

### 5.2 阶段交付与验收

完全复用现有橱窗订单能力：

1. 画师每次上传 1–9 张原图，按上传顺序组成同一阶段版本；
2. 服务端为每张原图生成最长边不超过 1080px、带重复水印的验收图；
3. 订单完成前，企划方响应中隐藏原图地址；
4. 企划方可要求修改并填写意见，画师重新提交，历史版本保留；
5. 企划方可通过当前阶段进入下一阶段；
6. 企划方可从任意阶段直接确认当前交付并完成交易，跳过剩余阶段；
7. 完成事务内立即结算至对应画师余额，并开放当前确认版本的全部原图。

### 5.3 创作阶段口径（2026-08-14 已实现）

- 发布企划“需求详情”页在参考图下增加创作阶段配置；默认 3 次提交：初稿、修改、终稿。
- 自定义阶段只包含名称和顺序，可增删、重命名和排序；去掉百分比。
- 企划详情在应征画师列表上方展示创作阶段，正式发单时将其复制到订单阶段快照。
- 最后一个创作阶段验收通过即订单完成、金额结算并开放该次提交的高清原图。
- 新企划订单优先复制企划 `phases`；企划未配置时回退为 `初稿 → 修改 → 终稿`，不再创建额外“交付”阶段。
- 已存在订单继续按自身阶段快照履约，不对历史订单强制删改阶段。

## 6. 订单管理与详情

企划订单继续复用统一订单组件，不新增第三套订单页面，但两个工作台只暴露与当前身份相符的入口：

1. 企划方工作台只显示“我委托的订单”，固定使用 `participantRole=employer`；
2. 画师工作台只显示“我承接的订单”，固定使用 `participantRole=painter`；
3. 内容区来源筛选保持：`企划订单 / 橱窗订单`；
4. 内容区状态筛选保持：`全部订单 / 待交付 / 待评价 / 退款/售后`。

同一账号拥有双角色时：

- 在“我委托的订单 → 企划订单”查看自己向各画师发出的订单，对应接口参数 `participantRole=employer`；
- 在“我承接的订单 → 企划订单”查看其他企划方向自己发来的订单，对应接口参数 `participantRole=painter`；
- 需要查看另一交易身份下的本人订单时，必须先切换工作台；订单列表不再通过查询参数切换身份；
- 路由仍可保留 `/dashboard/orders/{id}` 与 `/painter/orders/{id}`，但页面能力由订单中的 viewer role 决定；
- 一对用户有多笔企划/橱窗订单时，会话“发送订单状态”必须先选择具体订单。

## 7. 消息、通知与跳转

### 7.1 订单创建

- 画师收到“收到新的企划订单”系统通知；
- 企划方收到“企划订单已发送，等待画师确认”系统通知；
- 双方合并私聊插入企划订单系统卡片，不新建第二个同名会话；
- 卡片显示企划标题、画师、金额、订单状态，并携带 `orderId`。

### 7.2 后续事件

接单、拒单、取消、交稿、要求修改、阶段通过、完成和申请售后均复用现有订单事件机制：

- 写入 `order_event`；
- 给双方创建站内通知；
- 向合并私聊写入系统订单消息；
- 通过 WebSocket 推送；
- “查看详情”按当前用户在该订单中的身份进入订单详情。

### 7.3 多订单会话规则

企划方可对同一画师存在多笔企划订单和橱窗订单，但左侧会话仍只有一条。所有订单卡片必须显示订单编号或企划标题，不能只显示对方昵称；发送订单状态时由用户选择具体订单。

## 8. 已实现接口（2026-08-14）

### 8.1 新建正式企划订单

旧的无副作用占位接口：

```text
POST /api/v1/projects/{projectId}/order-intents/{painterId}
```

已移除，并替换为以应征为中心的正式接口：

```text
POST /api/v1/projects/{projectId}/applications/{applicationId}/order
```

请求体为空，金额、身份、画师和企划快照全部由服务端查询生成。成功响应返回现有 `OrderInfo` 或 `OrderDetailResponse`。

采用 `applicationId` 而不是前端直接传 `painterId` 的原因：

- 能验证该画师确实应征了此企划；
- 能唯一读取应征报价；
- 能为“一企划多画师订单”保留清晰来源；
- 避免前端伪造画师、价格或跨企划应征。

### 8.2 复用接口

创建后继续复用现有接口：

- `GET /api/v1/orders?source=project&participantRole=employer|painter`
- `GET /api/v1/orders/{id}`
- `PUT /api/v1/orders/{id}/accept`
- `PUT /api/v1/orders/{id}/reject`
- `PUT /api/v1/orders/{id}/cancel`
- `PUT /api/v1/orders/{id}/after-sale`
- `POST /api/v1/orders/{id}/stages`
- `PUT /api/v1/orders/{id}/stages/current/review`

### 8.3 建议数据补充

为避免企划后续修改或关闭影响订单，应补充：

- `application_id`：订单来源应征；
- `project_title`：下单时企划标题快照；
- `project_cover`：第一张参考图快照；
- `project_snapshot`：需求描述和结构化稿件要求快照；
- 现有 `phase_snapshot`：企划订单默认阶段快照。

数据库和服务层不得对 `project_id` 建立“只能一笔有效订单”的唯一约束；只需防止同一 `application_id` 同时存在重复非终态订单。

1. 企划详情左侧在“返回企划列表”上方增加“变更企划”，仅发布者可见。

实现补充：

- 企划数据库只保留 `deadline`，历史 `recruit_deadline` 已回填后删除。发布和修改的新日期均不得早于操作当日 +2 天。
- 修改日期接口为 `PUT /api/v1/projects/{id}/deadline?deadline=YYYY-MM-DD`。过期企划允许延长日期；若仍为正常上架状态，保存后会自然重新进入大厅。
- 下架接口为 `PUT /api/v1/projects/{id}/status?status=4`；重新上架使用 `status=0&deadline=YYYY-MM-DD`，必须显式选择新日期，不再自动续期。
- 被拒绝的定向企划转公开使用 `PUT /api/v1/projects/{id}/publish-public?deadline=YYYY-MM-DD`，同样必须显式选择新日期。
- 公开大厅动态要求 `deadline >= 当前日期`。日期当天仍可展示和应征；过期不批量改企划状态，也不删除已有应征和会话。
- 定向邀请遵循同一日期：过期后不能接受，但仍可拒绝或隐藏提醒；已接受产生的业务关系不受影响。
- 公开企划邀请报价与带价邀请接受后都只形成普通有效应征；带价应征使用企划方价格并锁定改价。企划方后续发送订单时仍统一读取服务端应征报价，不从邀请记录直接创建订单或扣款。
- 企划订单不读取当前企划日期决定状态流转；创建时的日期快照只用于约定展示和准时交稿率。
- 删除接口为 `DELETE /api/v1/projects/{id}`，任何状态的关联企划订单都会阻止删除。
- 下架企划仅作者及关联订单双方可读取，公开大厅不会返回；下架不修改订单状态、阶段快照、余额、会话和通知。
