# 艺绘（Artiv）订单流转流程

> 版本：v1.4 ｜ 最近核对：2026-09-05 ｜ 基准：`fec304f` ｜ 性质：核心功能总览
> 当前实现说明：两类订单主链路已实现，企划支持一对多发单。本轮仅静态核对 `OrderController`、`OrderServiceImpl`、订单实体及已有接口文档，没有重新运行验收；发布风险见 [未解决问题](../未解决问题.md)。

## 0. 需求来源（项目开发计划书 F8 原文）

> 以下为早期 F8 需求摘录，保留设计背景，不是当前实现保证。现阶段已有余额和争议仲裁，但尚无受鉴权保护的原图下载接口；现行规则以第 1～4 节为准。

**F8 订单与模拟资金托管（★核心）**

- 选定画师后创建订单（金额取企划预算或画师报价）
- 创作阶段验收：默认初稿 → 修改 → 终稿，按阶段提交与验收；终稿即最终交付
- 订单状态：待接单 → 进行中 → 待验收 → 已完成 / 已取消 / 争议中
- 模拟托管：下单即视为托管，阶段验收通过即结算；争议由管理员处理
- **交付水印保护**：画师交付阶段提交附件时，企划方仅能看到带水印的低像素预览图；只有企划方确认收货（验收通过）后，才能下载高清无水印原图
  - 实现要点：附件区分为「预览图（水印 / 低像素）」与「原图（高清）」，原图下载接口在订单阶段验收通过后才放行
  - 数据落地：`order_stage.attachments` 记录预览图；原图另行存储（如 `order_stage.originals` 或独立附件表），并记录验收时间作为放行依据
- 简化：取消钱包、提现、手续费、详细仲裁流程

> 后续各章节（状态机、阶段验收、模拟结算、水印保护等）均围绕上述需求展开，若需求变更需同步更新计划书与本文档。

## 1. 订单生命周期（状态机）

### 完整业务流（含应征私聊）

```
发布企划
    ↓
多名画师同时应征（每名画师一条应征记录）
    ↓
企划方与各应征画师 1v1 私聊（沟通需求、风格、报价意向）
    ↓
确定沟通满意的画师 → 从有效应征发送独立订单（不必先标记已通过）
    ↓
创建订单并扣款（有效应征报价；历史无有效报价才回退企划预算）
    ↓
待接单（金额已锁定，不支持订单内改价）→ 画师接单
    ↓
进行中 → 阶段验收 → 已完成 → 互评
```

### 订单状态机

待接单(0) → 进行中(1) → 待验收(2) → 已完成(3)

待接单(0) → 已取消(4) ｜ 进行中/待验收 → 争议中(5) →（管理员仲裁后）已完成/已取消

### 状态说明

| 状态 | 值 | 含义 | 进入条件 |
| --- | --- | --- | --- |
| 待接单 | 0 | 订单已创建，等待画师接单 | 创建订单成功 |
| 进行中 | 1 | 画师已接单，按阶段交付 | 画师接单 |
| 待验收 | 2 | 画师提交阶段稿件，等待企划方验收 | 画师提交阶段 |
| 已完成 | 3 | 交易完成并全额模拟结算 | 最后阶段通过、任意当前阶段直接完成或管理员裁决结算 |
| 已取消 | 4 | 订单终止并退款，橱窗订单恢复库存 | 待接单时企划方取消或画师拒单、管理员退款/封禁联动；无自动超时取消 |
| 争议中 | 5 | 双方纠纷，管理员介入 | 任意一方发起争议（进行中/待验收） |

## 2. 状态流转规则

| 从 | 到 | 触发方 | 前置条件 / 校验 |
| --- | --- | --- | --- |
| 0 待接单 | 1 进行中 | 画师 | 当前用户是订单画师，账号正常且已认证；没有额外金额确认步骤 |
| 0 待接单 | 4 已取消 | 企划方 / 画师 | 分别调用取消 / 拒单接口 |
| 1 进行中 | 2 待验收 | 画师 | 画师提交阶段稿件（order_stage） |
| 2 待验收 | 1 进行中 | 企划方 | `revise` 留在当前阶段；非末阶段 `approve` 进入下一阶段 |
| 2 待验收 | 3 已完成 | 企划方 | 末阶段 `approve` 或任意阶段 `complete` → 全额模拟结算 |
| 1/2 | 5 争议中 | 双方任一 | 发起争议，管理员介入 |
| 5 争议中 | 3 已完成 / 4 已取消 | 管理员 | 仲裁结果 |
| 非终态 0/1/2/5 | 4 已取消 | 管理员 | 封禁联动取消；不是任意改状态的通用接口 |

实际履约接口统一位于 `/api/v1/orders/{id}`：`POST /accept`、`/reject`、`/cancel`、`/after-sale`、`/stages` 和 `PUT /stages/current`。不存在通用 `POST /orders`、`PUT /orders/{id}/status` 或正式订单改价接口。争议状态 5 仍是非终态。

## 3. 阶段验收流程（order_stage）

### 3.1 阶段初始化

创建订单时，根据订单来源保存阶段配置到 `order_info.phase_snapshot`；尚不创建 `order_stage` 提交记录：

- 企划下单：复制企划阶段配置，默认 **初稿 → 修改 → 终稿**。
- 橱窗下单：复制橱窗 `phases`（JSON）。两类订单都在画师实际提交稿件时追加 `order_stage`，以 `stage_index` 和 `submission_no` 记录阶段与版本。

> 当前发布企划和发布/修改橱窗均已移除百分比输入。历史 `percent` 字段仅作兼容，不再参与用户阶段配置；新的阶段顺序由数组顺序决定。

### 3.2 阶段流转

画师提交阶段（submitter=1, status=0 待确认）→ 企划方验收：

- 通过（status=1）→ 进入下一阶段；最后阶段通过 → 订单已完成(3)
- 需修改（status=2）→ 画师重新提交

关键规则：

- 只有当前阶段验收通过后才能提交下一阶段
- 阶段记录不可覆盖，追加新记录（保留历史）
- 最后创作阶段验收通过 → 订单完成、结算并开放高清原图 → 进入互评（F10 评价体系）

### 3.3 交付水印保护（计划书 F8 新增需求）

- 画师每个阶段版本可提交 1–9 张原图，企划方完成交易前**仅能看到对应的带水印低像素预览图**
- 只有企划方**确认收货（验收通过）后**，才能下载当前确认版本的全部高清无水印原图
- 数据落地：`order_stage.attachments` 与 `order_stage.originals` 按相同顺序保存逗号分隔地址，并记录验收时间作为放行依据
- 上述“仅预览”是正常详情 DTO / 页面层的行为，不是存储访问授权：`/uploads/**` 当前公开，已知原图 URL 可以绕过页面直接访问，受鉴权下载接口尚未实现。
- 完成后详情响应会返回历史提交的原图，不仅限当前确认版本；当前页面主要展示确认版本。详情 GET 还可能为历史提交生成水印并回写记录，并非严格只读。

## 4. 模拟托管结算

- 下单即视为资金托管（模拟，不接真实支付）；当前简化实现为直接扣减企划方可用余额，不另设冻结余额字段
- 结算时机：企划方在任意阶段确认当前交付并完成交易时，立即增加至对应画师余额
- 当前已设用户余额，但充值、提现、独立冻结余额和资金流水仍未实现
- 完成后双方可互评（F10）：`POST /orders/{id}/reviews`，仅限 `completed_at` 后 7×24 小时，订单完成前及逾期均禁止评价

## 4.0 应征与私聊（下单前筛选）

- 同一企划允许多名画师同时应征（application 表，互不冲突）
- 企划方与**每名应征画师**进行 1v1 私聊：沟通需求细节、风格、报价意向
- 私聊基于站内消息（message 表，type=3 私信），不依赖订单（下单前即可发起）
- 企划方确认某名画师沟通满意后，可对该条有效应征发送一笔独立企划订单
- 一个企划可向多名有效应征画师分别发送订单；不自动拒绝其他应征，也不限制整个企划只能有一笔有效订单

规则：

- 私聊内容仅双方可见（1v1）
- 应征记录保留沟通入口（应征列表可发起/继续私聊）
- 每名应征画师的订单独立接单、取消、交付和结算，单笔订单状态不回退或重开整个企划

入口（场景①：应征沟通）：

- 企划方：我的企划 → 应征管理 → 每条应征记录右侧「沟通」按钮（与「选定」并列，先沟通后选定）
- 画师：我的应征 → 可撤销待处理应征；企划方主动建立会话后，画师在消息中心回复

## 4.1 订单金额规则

| 订单来源 | 金额取值 | 校验 |
| --- | --- | --- |
| 企划下单（选定画师） | 画师报价（应征 quote）；未报价则取企划预算 | 服务端计算，不接受前端传值 |
| 橱窗下单 | 橱窗价格（stall.price） | 已实现固定价、库存扣减，以及待接单取消/拒单时恢复库存。 |

## 4.2 订单内沟通

- **待接单即可沟通**：订单创建前后都复用当前“一对用户一条合并私聊”，不再开发第二套订单聊天。
- 普通文字/图片继续使用 `/messages/private`；订单系统卡片与订单状态卡片携带具体 `orderId`。
- 阶段验收和状态流转事件通过订单事件、站内通知、合并私聊系统消息与 WebSocket 同步双方。

入口（场景③：订单沟通）：消息中心的双方合并会话。若双方存在多笔企划/橱窗订单，发送订单状态前必须选择具体订单。

> 其余私聊入口（场景②发现画师：画师列表/主页「私聊」按钮；场景④消息中心：顶栏铃铛会话列表）见[《沟通与消息设计》](../开发计划/沟通与消息设计.md) 6.1。

## 4.3 订单金额确认（接单前）

- 价格协商发生在应征报价修改和下单前私聊阶段，不在正式订单内反复改价。
- 发送企划订单时，服务端取该应征的有效报价；历史数据无有效报价时才回退企划预算。
- 确认订单弹窗只展示服务端金额，不允许前端提交或修改金额；订单创建后金额锁定。
- 若双方需要重新议价，应先修改应征报价，再创建订单；已创建待接单订单只能接单、拒单或由企划方取消。

## 5. 前提功能分析（当前缺陷清单）

> 本章及第 6～7 章是开发前的历史分析与旧验收清单，不是现行待办。其中通用订单创建、状态修改、订单内议价、建单预建阶段等方案均已被替代；旧“缺少字段/接口”和勾选状态不能用来判断当前实现。现行接口见 [接口文档](../接口文档.md)，运行验证记录见 [测试](../测试.md)。

以下为现有代码在实现订单流转前必须补齐或修复的点：

### 5.1 订单创建（POST /orders）——缺陷严重

- 无任何权限/字段校验：当前直接接收 OrderInfo 实体，调用方可伪造 employer_id、painter_id、amount
- 金额来源未约束：应取「企划预算 / 画师报价 / 橱窗价格」，而非前端传值
- 订单来源未区分：企划下单需关联 project_id；橱窗下单需关联 stall_id，且应校验橱窗上架状态
- 库存未扣减：橱窗下单后应扣 stall.stock，无库存时禁止下单
- [x] 企划订单已实现“同一应征同一时间只能有一笔非终态订单”的防重复校验；整个企划允许向多名应征画师分别创建独立订单

### 5.2 订单查询

- [x] `GET /orders/{id}` 已限制为 `employer` 或 `painter` 访问；第三方返回 2003。

### 5.3 应征 → 订单闭环缺失

- [x] 企划方可选定待处理应征，状态变为“已通过”，并向画师写入通知。
- [x] 企划作者可通过 `POST /projects/{projectId}/applications/{applicationId}/order` 从任意有效应征创建正式订单。
- [x] 企划订单与招募状态解耦：不会拒绝其他应征或锁定整个企划，可对多名画师并行发单。

### 5.4 接单 / 阶段 / 状态接口缺失

- 画师接单（0→1）无接口
- 阶段提交/验收（order_stage 写与确认）无接口
- 状态流转（PUT /orders/{id}/status）无接口
- 争议流程无接口
- 独立订单沟通接口已取消规划；订单详情进入双方合并私聊，通过订单状态卡片表达当前订单上下文

### 5.5 数据与关联

- order_info 无 completed_at 等结算相关字段（可后续补充）
- 演示数据中订单状态与真实流转不一致（id=1 直接是进行中）
- order_stage 无 originals 字段（原图存储），需按水印保护需求补充

## 6. 建议实现顺序（编码时）

### 阶段 A：数据与模型基础

1. order_info 补充字段：completed_at（结算时间）、cancel_reason（取消原因）
2. order_stage 补充字段：originals（原图，水印保护用）、reviewed_at（验收时间）
3. 同步 init.sql 与实体

### 阶段 B：订单创建安全化（修复最严重缺陷）

4. 新增 OrderCreateRequest DTO：只收 projectId 或 stallId，不收金额/身份
5. 服务端计算金额：企划下单取画师报价（未报价取预算）、橱窗下单取橱窗价
6. 校验：橱窗上架中 + 扣减库存；企划订单只限制同一应征重复创建非终态订单，不限制一个企划向多名画师发单
7. 创建订单时初始化 order_stage（企划四阶段 / 橱窗复制 phases）

### 阶段 C：订单权限

8. [x] GET /orders/{id}、GET /orders 归属校验：仅 employer 或 painter 可见

### 阶段 D：接单与状态流转

9. 画师接单 POST /orders/{id}/accept（0→1，校验已认证画师）
10. 状态流转 PUT /orders/{id}/status：取消（待接单时企划方）、争议、完成，按状态机校验（非法流转 3001）
11. 管理员争议仲裁接口（争议 → 完成 / 取消）

### 阶段 E：阶段验收与水印保护

12. 画师提交阶段 `POST /api/v1/orders/{id}/stages`（内容 + 1–9 张原图），服务端逐张生成水印低分辨率预览
13. 企划方验收 PUT /orders/{id}/stage/{stageId}（通过 → 下一阶段 / 完成；需修改 → 画师重提）
14. 原图下载接口校验该阶段已通过（水印保护放行）

### 阶段 F：业务闭环

15. 应征私聊：企划方与应征画师 1v1 站内私信（POST /messages/private，type=3），应征列表展示沟通入口
16. 企划方在每条有效应征上主动确认并创建独立订单；不自动拒绝其他应征，允许一企划多画师订单
17. [x] 订单沟通复用 `POST /messages/private`，消息可携带 `orderId` 并发送订单状态卡片；不另建订单会话
18. [x] 评价校验：订单完成后 7 天内方可 `POST /orders/{id}/reviews`，双方各一次且评价对象由服务端推导

### 阶段 G：前端对接

19. 订单管理页：接单、阶段提交、验收操作
20. 订单详情页：阶段进度、附件预览（验收前水印图）/ 下载（验收后原图）
21. 应征列表页：私聊入口 + 选定画师操作

### 阶段 H：聊天消息传递与价格协商（接单前议价）

22. [x] 订单聊天沿用双方合并私聊（待接单即可使用，双方可见），独立订单消息接口取消
23. 画师报价接口：PUT /orders/{id}/quote（仅 painter、待接单）
24. 企划方确认金额接口：PUT /orders/{id}/amount（仅 employer、待接单）
25. 画师接单校验金额已确认；接单后金额锁定
26. [x] 订单详情跳转到双方合并会话并读取统一分页历史，不提供独立订单消息列表

> 说明：聊天消息传递是接单前议价的前提，因此 H 阶段与 D 阶段（接单）衔接，建议在接单接口前完成消息与议价接口。

> 每个阶段完成后用演示账号走通对应接口，再进入下一阶段。

## 7. 验收清单（编码完成后）

- [ ] 企划方发布企划 → 多名画师应征 → 分别发送独立订单（金额分别等于各自应征报价）
- [ ] 同一企划两笔订单分别拒单/完成时，资金、消息和状态互不影响
- [ ] 橱窗立即下单 → 生成订单（金额=橱窗价格，库存扣减）
- [ ] 画师接单 → 提交阶段稿件 → 企划方验收通过/需修改
- [ ] 全部阶段通过 → 订单已完成（模拟结算）
- [x] 交付阶段水印保护：橱窗订单与企划订单均在验收前仅返回水印预览，完成后放行原图；历史橱窗订单读取时自动补生成规范预览（2026-08-18）
- [x] 订单完成后 7 天内双方可互评，完成前、非参与方、逾期和单方重复评价均被拒（2026-08-23，F10）
- [ ] 订单内沟通消息可发送并落库
- [ ] 越权访问他人订单返回 403/404
- [ ] 非法状态流转返回 3001
