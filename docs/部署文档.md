# Artiv 跨电脑部署文档（Windows，无 Docker）

> **方案状态：当前正式、推荐的部署方式。** 目标电脑不需要 Docker 或 WSL；按本文直接安装 MySQL、JDK、Maven 和 Node.js 即可。仓库中的 Docker 文件仅为备用项，不影响本方案，也不是使用 Artiv 的前置条件。
>
> 文档同步：2026-09-07，对照本地 `main` / `1728985` 的启动器、构建、代理、艺绘向导与管理员测试资金配置；`1728985` 尚未推送远端。本轮未安装软件、启动服务、导入数据或执行跨电脑验收。本文适用于本机/受控演示，公网发布仍须处理《未解决问题》CR-001–CR-005 等阻断项。

## 1. 部署目标

### 2026-09-07 企划六类版本的升级前置条件

- 新版使用 project.project_category，旧版使用 project.category，不能混跑；橱窗、作品、订单表列不变。Git 回退检查点 df62197 只保护代码，不代替数据库备份。
- 全新空库才执行新版 init.sql。已有库先确认实际 profile/数据源、停写、备份数据库和 backend/uploads，并在隔离库验证恢复；不得直接重跑 init.sql。
- 本机迁移入口：`scripts/migrate-project-category.ps1 -Database artiv -BackupPath <完整数据库备份.sql> -ConfirmMigration`。备份必须带 SHA256 文件及 artiv 库标记。脚本仅支持已核对的本机 MySQL 8 列属性，拒绝异常双列/缺列、旧业务非空、未知列属性、视图/触发器和未核对环境覆盖；其他部署需先评审，不绕过检查。
- 隔离演练入口：`scripts/test-project-category-migration.ps1 -Database artiv_category_test_<标识> -BackupPath <备份.sql>`，只对已恢复且业务为空的专用测试库运行。恢复到隔离库使用不含 CREATE/USE/DROP DATABASE 的可移植转储，不能直接导入带原库名称的整库备份。
- 正式迁移使用 `backend/sql/migrations/20260907_rename_project_category.sql`，由脚本按列状态分步执行；已改名则只核验/补注释。成功后部署同版后端与前端，旧缓存页面需刷新。不得把两个 DDL 当作可整体事务回滚。
- 只在确认无新增数据时停服逆向改名并恢复旧应用；已有新六类记录或快照时先保留数据评估兼容，不能仅改回列名或自动整库恢复覆盖后续数据。详细证据与备份位置见《测试》及六类方案第 9.1 节。

本文用于把 Artiv 部署到另一台 Windows 电脑，不使用 Docker。适合毕业答辩、现场演示和本机开发运行。

推荐的原生运行结构：

```text
浏览器 http://127.0.0.1:5173
        │
        ▼
Vue / Vite 前端（5173）
        │ 代理 /api、/ws、/uploads
        ▼
Spring Boot 后端（8080）
        │
        ▼
MySQL 8（3306）
```

目标电脑需要安装 MySQL、JDK、Maven 和 Node.js。首次安装完成后，每次使用只需启动 MySQL、后端和前端。

## 4. 初始化 MySQL

> `backend/sql/init.sql` 会重建 Artiv 业务表，并且只写入 `planner`、`artist`、`admin` 三个初始用户。作品、橱窗、企划、应征、邀请、订单、阶段、消息及其他业务表初始均为空。只在首次部署或明确要重置数据库时执行，不要在日常启动时重复执行。

### 4.1 启动 MySQL 服务

可在 Windows“服务”中启动 MySQL，也可以在管理员 PowerShell 中执行（实际服务名可能不同）：

```powershell
Get-Service *mysql*
Start-Service MySQL80
```

`MySQL80` 是通用示例；本机辅助启动器固定使用 `MySQL80-Artiv`。先用 `Get-Service` 查出本机真实服务名，再替换启动命令，启动类型也以当前服务配置为准。

### 4.2 导入数据库

在项目根目录执行：

```powershell
cmd.exe /c "mysql -u root -p < backend\sql\init.sql"
```

根据提示输入安装 MySQL 时设置的 `root` 密码。导入结束后检查：

```powershell
mysql -u root -p -e "USE artiv; SHOW TABLES; SELECT id,username,nickname FROM user;"
```

应能看到 Artiv 的业务表以及 `planner`、`artist`、`admin` 三个账号。

### 4.3 创建专用数据库账号（推荐）

不要让应用长期使用 MySQL `root`。先登录 MySQL：

```powershell
mysql -u root -p
```

然后执行；请自行替换强密码：

```sql
CREATE USER IF NOT EXISTS 'artiv_app'@'127.0.0.1'
  IDENTIFIED BY '请替换为强密码';
GRANT ALL PRIVILEGES ON artiv.* TO 'artiv_app'@'127.0.0.1';
FLUSH PRIVILEGES;
EXIT;
```

## 5. 配置并启动后端

### 5.1 创建上传目录

建议把运行数据放在项目目录之外。下面以 `C:\ArtivData\uploads` 为例：

```powershell
New-Item -ItemType Directory -Force C:\ArtivData\uploads
```

不要删除该目录。用户头像、作品、企划参考图和订单交付图片均会保存在这里。

### 5.2 设置当前窗口的运行配置

打开一个新的 PowerShell，进入后端目录并设置环境变量：

```powershell
cd C:\你的项目路径\Artiv\backend

$env:SPRING_DATASOURCE_URL = 'jdbc:mysql://127.0.0.1:3306/artiv?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true'
$env:SPRING_DATASOURCE_USERNAME = 'artiv_app'
$env:SPRING_DATASOURCE_PASSWORD = '请替换为数据库强密码'
$env:ARTIV_JWT_SECRET = '请替换为至少32位且不可公开的随机字符串'
$env:ARTIV_JWT_EXPIRE_HOURS = '8'
$env:ARTIV_UPLOAD_DIR = 'C:/ArtivData/uploads'
$env:ARTIV_UPLOAD_URL_PREFIX = '/uploads'
```

这些变量只对当前 PowerShell 窗口有效，关闭窗口后不会保留，也不会把密码写入 Git。

艺绘向导是可选的管理员测试功能，默认关闭。若需要启用当前已经完成联调的 DeepSeek 视觉模型，再在同一个后端 PowerShell 中设置：

```powershell
$env:ARTIV_GUIDE_ENABLED = 'true'
$env:ARTIV_GUIDE_PROVIDER = 'deepseek'
$env:ARTIV_GUIDE_API_KEY = '请替换为模型平台 API Key'
$env:ARTIV_GUIDE_TEXT_MODEL = 'deepseek-v4-flash-vision-exp'
$env:ARTIV_GUIDE_VISION_MODEL = 'deepseek-v4-flash-vision-exp'
$env:ARTIV_GUIDE_REQUEST_TIMEOUT_SECONDS = '90'
$env:ARTIV_GUIDE_MAX_OUTPUT_TOKENS = '2048'
```

不要把真实 API Key 写入 `application.yml`、启动脚本、文档或 Git。当前代码虽然预留了 GLM Provider 扩展接口，但尚未完成 GLM-5.3-Flash 的真实 Key 联调，不能只把 `ARTIV_GUIDE_PROVIDER` 改成 `glm` 就视为可用。未配置向导或保持 `ARTIV_GUIDE_ENABLED=false` 不影响其他业务功能。

向导会话和向导上传图片当前只保存在后端进程内存中：最多每条消息 4 张图、每个会话累计 12 张图；重启后端会清空会话与图片，不能把它们列入持久化迁移或备份范围。

若使用 `application-local.yml` 覆盖配置，需要显式激活 `local` profile；仅创建该文件不会自动覆盖基础配置。启动器也不主动加载第 5.2 节的环境变量，双击启动时须另行配置其运行环境。基础 `application.yml` 仍有默认开发凭据，应用尚未实现拒绝示例密钥的启动校验。

### 5.3 启动后端

```powershell
mvn.cmd spring-boot:run
```

看到类似以下内容代表启动成功：

不要关闭这个 PowerShell 窗口。后端默认地址为 `http://127.0.0.1:8080`。

## 8. 日常启动和停止

### 本机辅助启动器的适用范围

`启动Artiv.cmd` 含本机固定配置，2026-09-05 已移出 Git 跟踪并加入忽略规则，本地文件保留；新检出不包含它，跨电脑请使用下方手动启动步骤。以下仅记录本机辅助脚本的行为与已验证修复，不作为仓库自带启动器的承诺：

- 项目目录取脚本自身位置；工具路径固定为 `D:\CodeTool\Java\jdk-21.0.12`、`D:\CodeTool\Maven\apache-maven-3.9.16\bin`、`D:\CodeTool\NodeJS\node-v24.19.0-win-x64`。
- 检查并尝试启动 `MySQL80-Artiv`；启动服务可能需要管理员权限。
- 自动创建项目内 `.artiv-data/java-sockets`，通过局部 `JAVA_TOOL_OPTIONS` 指定 `jdk.net.unixdomain.tmpdir`，同时传入 Maven 与其派生的后端 JVM；保留原有 JVM 选项，不修改系统环境变量。该目录受 Git 忽略，需要当前用户可写，避免将项目放在过长路径下。
- 8080 或 5173 已被监听时跳过对应启动，没有核验占用者身份或代码版本。
- 前端启动参数为 `--host 127.0.0.1`，不能直接供其他电脑访问；局域网场景按第 11 节启动。
- 使用 PowerShell 固定等待 8 秒后打开页面，避免 `timeout` 在非交互终端中的输入重定向错误；仍不做服务就绪检查，不能把“启动命令已发送”当作成功验收。

本机本次已验证：默认临时目录下独立 `Selector.open()` 复现 `Unable to establish loopback connection`，指定项目目录后成功；修复后由启动脚本拉起前后端，首页 HTTP 200，后端及前端代理的企划列表均为 HTTP 200 / 业务码 200，运行中 JVM 的 socket 目录参数已确认生效。该结果仅覆盖本机启动、代理和数据库读取，不代表完整业务或跨电脑验收。

换电脑后优先按下面手动步骤确认环境，再决定是否调整启动器中的固定配置。

### 启动顺序

1. 启动 MySQL 服务。
2. 打开后端 PowerShell，设置第 5.2 节环境变量并运行 `mvn.cmd spring-boot:run`。
3. 打开前端 PowerShell，运行 `npm.cmd run dev`。
4. 浏览器访问 `http://127.0.0.1:5173`。

### 停止顺序

在前端和后端窗口中分别按 `Ctrl+C`。正常停止程序不会删除 MySQL 数据或 `C:\ArtivData\uploads` 中的文件。

## 9. 目标电脑不能联网时

目标电脑离线时，不能直接执行首次 `mvn spring-boot:run` 或 `npm install`，因为它们需要下载依赖。推荐在可联网电脑先生成可交付产物。

### 9.1 在可联网电脑构建

```powershell
cd C:\你的项目路径\Artiv\backend
mvn.cmd clean package -DskipTests

cd ..\frontend
npm.cmd install
npm.cmd run build
```

构建完成后准备以下文件：

```text
Artiv-offline/
├── backend/
│   ├── artiv.jar                # 来自 backend/target/artiv-0.0.1-SNAPSHOT.jar
│   └── init.sql                 # 来自 backend/sql/init.sql
├── frontend/
│   └── dist/                    # frontend/dist 的完整内容
```

目标电脑仍需提前安装 MySQL 8 和 Java 21 运行环境（可使用 JDK 21）。运行 JAR 不需要 Maven；已构建前端需配合第 10 节 Nginx 提供静态文件和代理，也不需要 Node.js。若选择离线运行 Vite，必须额外准备同平台可用的 `frontend/node_modules` 或完整离线安装缓存；仅带 Node.js 安装包与源码无法完成首次 `npm install`。

如果目标电脑只能接收构建产物，建议同时携带 Windows 版 Nginx，并按第 10 节配置。

## 10. 使用 JAR + Nginx 运行（可选，更接近正式部署）

这一方式不使用 Maven 和 Vite 常驻运行：后端运行 JAR，Nginx 提供前端静态文件并代理接口。

下面配置保留了现有 `/uploads` 公共代理，不会自动补齐原图/证据下载授权（CR-002）；完成代理配置不等于达到公网生产标准。

### 10.1 启动后端 JAR

先设置与第 5.2 节相同的环境变量，再执行：

```powershell
java -jar C:\ArtivApp\backend\artiv.jar
```

### 10.2 准备前端

把 `frontend/dist` 中的全部文件复制到：

```text
C:\ArtivApp\frontend\dist
```

在 Nginx 的 `conf/nginx.conf` 中配置一个 `server`；Windows 路径使用 `/`：

```nginx
server {
    listen 8088;
    server_name 127.0.0.1;

    root C:/ArtivApp/frontend/dist;
    index index.html;
    client_max_body_size 10m;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location /uploads/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
    }

    location /ws {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 65s;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

在 Nginx 目录执行：

```powershell
.\nginx.exe -t
.\nginx.exe
```

浏览器访问 `http://127.0.0.1:8088`。重新加载配置使用 `.\nginx.exe -s reload`，停止使用 `.\nginx.exe -s quit`。

## 11. 让局域网内其他电脑访问

如果使用 Vite 方式，在前端目录改用：

```powershell
npm.cmd run dev -- --host 0.0.0.0
```

然后在管理员 PowerShell 中只为“专用网络”开放前端端口：

```powershell
New-NetFirewallRule -DisplayName "Artiv Vite 5173" -Direction Inbound -Protocol TCP -LocalPort 5173 -Action Allow -Profile Private
```

运行 `ipconfig` 找到部署电脑的局域网 IPv4，其他电脑访问：

```text
http://部署电脑IPv4:5173
```

Vite 会在部署电脑本机代理后端，因此无需对局域网开放 MySQL 3306 或后端 8080。

演示结束后删除防火墙规则：

```powershell
Remove-NetFirewallRule -DisplayName "Artiv Vite 5173"
```

不要做路由器端口转发，也不要把这套演示配置直接暴露到公网。

## 12. 迁移原电脑的数据

项目数据由两部分组成，必须成对迁移：

1. MySQL 中的账号、企划、订单、消息等业务数据。
2. 上传目录中的头像、作品、参考图和交付图片。

### 12.1 原电脑导出

先停止业务写入，并确认当前有效 `ARTIV_UPLOAD_DIR`。下面只以 `C:\ArtivData\uploads` 为例；未覆盖默认目录的原电脑可能使用 `backend/uploads`，必须替换成实际目录。数据库与文件需要处于同一业务静止窗口，不能只依赖 `--single-transaction` 保证两者一致。

```powershell
New-Item -ItemType Directory -Force C:\ArtivBackup
mysqldump -u root -p --single-transaction --routines --triggers artiv --result-file=C:\ArtivBackup\artiv.sql
Compress-Archive -Path C:\ArtivData\uploads -DestinationPath C:\ArtivBackup\uploads.zip -Force
```

### 12.2 目标电脑恢复

首次执行前确认目标数据库没有需要保留的数据：

```powershell
mysql -u root -p -e "DROP DATABASE IF EXISTS artiv; CREATE DATABASE artiv CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
cmd.exe /c "mysql -u root -p artiv < C:\ArtivBackup\artiv.sql"

New-Item -ItemType Directory -Force C:\ArtivData
Expand-Archive -Path C:\ArtivBackup\uploads.zip -DestinationPath C:\ArtivData -Force
```

恢复后确认最终目录是 `C:\ArtivData\uploads`，并按第 5.2 节把 `ARTIV_UPLOAD_DIR` 指向该目录。

备份包含账号资料、消息和业务图片，不要提交到 Git，也不要发送给无关人员。

## 13. 常见问题

### MySQL 登录失败

- 确认 MySQL 服务已启动。
- 确认 `artiv_app` 密码与 `SPRING_DATASOURCE_PASSWORD` 完全一致。
- 确认数据库地址是 `127.0.0.1:3306/artiv`。

### 后端 8080 端口被占用

```powershell
Get-NetTCPConnection -LocalPort 8080 -ErrorAction SilentlyContinue
```

先根据进程 ID 确认占用者，若确为要替换的旧 Artiv 后端，再正常停止它。不要直接结束未知进程；改变后端端口时 Vite 和 Nginx 的代理地址也必须同步修改。

### 前端页面能打开，但接口报错

- 确认后端 PowerShell 没有退出。
- 查看后端启动日志是否存在数据库连接错误。
- 必须通过 `5173`（Vite）或 `8088`（Nginx）访问，不要直接双击打开 `dist/index.html`。

### 图片上传后刷新不显示

- 确认 `ARTIV_UPLOAD_DIR` 指向存在且可写的绝对目录。
- 确认前端是通过 Vite 或 Nginx 访问，`/uploads` 代理不能缺失。
- 数据迁移时必须同时恢复数据库和上传目录。

### 修改代码后没有生效

- Vite 开发模式通常会自动刷新；如无效，停止后重新执行 `npm.cmd run dev`。
- JAR 方式需要重新运行 `mvn.cmd clean package -DskipTests`，替换 JAR 并重启后端。
- Nginx 方式需要重新执行 `npm.cmd run build`，替换完整 `dist` 目录。
