# 管理员操作教程

核对日期：2026-09-10。受众：管理员。不得作为普通用户功能入口推荐；向导只讲解操作，不执行管理员写操作。下列资金、封禁和仲裁会影响真实测试业务记录，确认前必须核对对象。

## ADMIN-01 查看后台概览与用户详情

入口：管理员头像菜单 → 工作台 `/admin`；侧栏“用户管理” `/admin/users`。

1. 在“概览”查看当前待处理数据及近期操作；需要时点击“刷新”。
2. 进入用户管理，按用户名/昵称、注册主身份、账号状态或认证状态查询。
3. 点击目标用户“详情”，核对用户 ID、用户名、昵称、余额和近期订单。

结果：定位账号及待处理业务。注册主身份不是该用户唯一可用的工作台，不能据此认定其没有另一身份的订单。

## ADMIN-02 发放测试资金

入口：用户管理 → 目标用户详情 → 余额 → 发放资金。

1. 核对账号和当前余额。
2. 输入要增加的“发放金额”，填写操作原因，例如“订单流程测试资金”。
3. 查看预计变化，点击“确认发放”，完成后核对新余额和操作审计。

结果：增加可用模拟余额，不修改托管金额、旧订单价格或历史成交记录。金额必须为正数，遵守页面金额上限和小数位校验；不是用户真实充值或给银行卡汇款。

## ADMIN-03 调整可用余额到指定值

入口：用户管理 → 目标用户详情 → 余额调整。

1. 输入“调整后余额”，这里是最终余额，不是扣减数。
2. 填写操作原因，核对调整前后金额。
3. 点击“确认调整”，再核对用户详情和审计记录。

结果：可调高或调低到允许的非负余额，不改变已经托管的订单资金。例：当前 1,000 元，填写 200 元后余额是 200 元，不是扣 200 后剩 800。需要单纯追加金额时用“发放资金”。

## ADMIN-04 封禁与解封用户

入口：用户管理 → 封禁/解封。

1. 核对账号及相关未完成订单，确认处罚对象。
2. 封禁时填写原因；指定未来截止时间为限时封禁，不选表示永久封禁。
3. 确认操作后查看反馈中的退款取消订单数量，并核对订单及审计记录。
4. 手动解除时点击“解封”，填写原因后确认。

结果：封禁不是仅更改显示标签，会触发相关未完成订单的退款取消处理；必须提前评估影响。不能从这里封禁管理员账号或修改自己的封禁状态。解封不把已经退款取消的订单自动恢复成进行中。

## ADMIN-05 审核画师认证与资料修改

入口：认证审核 `/admin/certifications`。

1. 按用户名/昵称、申请类型、审核状态查询，点击目标“审核”。
2. 区分“初次认证”和“认证资料修改”，核对笔名、常用站、简介、作品与申请记录。
3. 根据页面可用操作选择“通过申请”或“驳回”，按提示提供必要说明。
4. 查看结果和审核历史；需要修正的申请用驳回原因向用户说明。

结果：初次通过开放认证能力，资料修改通过更新正式认证资料；资料修改未通过前原资料继续生效。不能把已通过认证用户的简介/题材日常保存误当成每次都要审核。

## ADMIN-06 违规下架与恢复企划

入口：企划治理 `/admin/projects`。

1. 按标题、治理状态或业务状态查询，打开“治理详情”核对内容、应征和关联订单。
2. 确认违规时点击“违规下架”，填写原因并确认。
3. 确认可以解除治理限制时点击“管理员恢复”，填写恢复说明。
4. 检查当前业务状态和招募日期，核对公开展示结果。

结果：治理操作不等于删除企划，也不自动抹掉历史订单。“管理员恢复”解除治理限制，不应被解释为可以无视过期、删除等其他可见性条件。

## ADMIN-07 处理订单争议仲裁

入口：订单仲裁 `/admin/disputes`。

1. 按订单号/标题和仲裁状态查询，打开待仲裁记录“处理”。
2. 核对订单金额、双方身份、争议原因及双方证据。
3. 选择“全额退款企划方”或“全额结算画师”，填写仲裁依据并确认。
4. 核对订单终态、资金结果和处理记录。

结果：立即执行对应资金流转并通知双方，不能重复执行。当前不提供部分退款；证据不足先核查，不要随便选择一个按钮作为暂存操作。

## ADMIN-08 处理评价申诉

入口：评价申诉 `/admin/review-appeals`。

1. 按处理状态、画师昵称/账号、日期筛选，打开待处理申诉。
2. 核对被申诉评价、原评分、图片、来源订单和申诉原因。
3. 选择“批准并隐藏评价”或“驳回申诉”，填写处理说明再确认。

结果：批准后评价退出公开展示和评分统计，当前不可恢复；驳回则保留。管理员不能在这里修改原评价文字或星级。

## ADMIN-09 处理用户举报

入口：用户举报 `/admin/reports`。

1. 按状态、用户关键词、日期查询，打开聚合案件。
2. 查看被举报账号、举报人数及各举报说明/图片，核对证据。
3. 选择“记录已处理”或“驳回举报”，按提示填写结论。
4. 如另需封禁用户或下架企划，进入对应治理模块核实后单独处理。

结果：这里只记录治理结论，不自动处罚、退款或屏蔽。相同被举报用户的记录聚合，重复举报不应被当作多个独立举报人。

## ADMIN-10 查看需求与运营统计

入口：数据统计 `/admin/stats`。

1. 选择近 7 天、近 30 天、全部历史或日期范围，按页面要求点击“应用”；日期范围遵守当前页面限制。
2. “用户需求分析”查看新增企划/应征、企划类型、在售橱窗类型、需求转化和供需缺口。
3. 在“企划订单成交价格分层”选择企划类型，查看对应完成订单的价格分布。
4. 切到“平台运营”查看用户、订单趋势及分别展示的企划/橱窗成交类型排名。

结果：统计反映所选时间与口径，不是页面当前第一屏数据。价格分层只含已完成企划订单，不含橱窗订单；企划六类与橱窗十类不能按相同名称直接混算。供需映射允许重复覆盖，不能把各组供给简单相加当唯一画师总人数。

## ADMIN-11 查看管理员操作审计

入口：操作审计 `/admin/audit-logs`。

1. 按动作类型、对象类型或管理员 ID 输入条件，点击“查询”。
2. 查看时间、操作者、目标、原因等字段，点击“快照”的“查看”核对变化。
3. 配合用户详情、订单或治理记录确认操作是否按预期执行。

结果：审计用于追踪，不是回退按钮，不能直接恢复已删除评价、已取消订单或撤销仲裁。普通用户无此入口，向导不应返回其他用户或管理员的私有审计内容。
