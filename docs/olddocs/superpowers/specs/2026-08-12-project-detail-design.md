# 企划详情与应征沟通历史设计（归档）

> 归档说明（2026-08-13）：本设计已实施并合并至 `main`。实现差异、当前消息会话规则与接口状态以 `../../沟通与消息设计.md`、`../../接口文档.md`、`../../项目进度.md` 为准。

## 目标

实现可公开浏览的企划详情页，并让企划发布者在自己的企划详情中查看应征画师作品、主动发起该企划专属沟通；同时完善发布企划的多参考图和稿件要求。

## 范围

- 详情页参照 `http://127.0.0.1:8767/site/projects_11631031.html` 的双栏、白色卡片、灰色页面背景和应征画师卡片信息层级。
- 保留发布者基本资料、截稿日期、预算、标题、发布时间、用途/类型、参考图、需求详情、稿件要求、应征入口与本人企划的应征者列表。
- 不实现流程图、关联人设卡、分享、评价、需求完成率、反馈间隔、企划流程、订单详情或订单状态。
- 发布企划支持最多六张参考图；提交顺序保存，第一张继续作为约稿大厅封面。
- 稿件要求独立保存：尺寸规格、颜色模式、稿件格式、发布权限；题材风格沿用现有 `project.subject`。

## 权限与沟通

- 公共详情页不返回应征列表；只有企划发布者可读取该企划的应征画师资料与作品缩略图。
- 画师应征时仅填写应征介绍与报价；作品由系统按画师账号自动查询，不采集手填作品链接。
- 发布者可对状态为“待处理”或“已通过”的应征画师主动创建企划会话；画师不能主动创建。
- 会话创建后双方都可发送该企划关联消息；撤销应征仅允许待处理状态，撤销后不能创建新会话。
- 每个企划目前只允许一个最终选定画师；“发送企划订单”仅为前端和接口占位，不创建订单、不改变应征状态。未来多人模式通过放开单选校验扩展，继续以 application 记录为合作关系。

## 数据与接口

- `project.requirements`：TEXT，保存 JSON 对象 `{ size, colorMode, formats, publishPermission }`。
- `GET /projects/{id}`：返回企划和稿件要求；公开可访问。
- `GET /projects/{projectId}/applications`：只允许企划发布者，返回应征记录、`painter` 基础资料和最多四个 `works` 缩略图。
- `POST /projects/{projectId}/conversations/{painterId}`：只允许企划发布者；检查画师存在有效应征（待处理或已通过），创建幂等的项目会话并返回会话定位信息。
- `POST /projects/{projectId}/order-intents/{painterId}`：只允许企划发布者与有效应征，返回“订单功能开发中”的明确占位响应，不创建订单。

## 视觉验收

三次比对参考页：详情页骨架、参考图/稿件要求主体、应征画师卡片。每次确认只保留本设计范围内的内容，并确保无本人权限时不显示操作按钮。
