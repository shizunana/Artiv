# 收藏关注设计（调整）

> 文档状态：已实现，自动化与生产构建已通过，浏览器回归见《测试》
> 制定日期：2026-08-24
> 替代范围：《收藏关注设计》中“独立收藏中心、工作台收藏路由、快捷入口跳转和收藏列表页面”的界面方案
> 保留范围：已实现的关注/收藏业务规则、数据库关系、状态查询、幂等新增与取消接口
> 适用页面：`/artists`、`/works`、`/stalls`、企划方与画师工作台共用侧栏

## 1. 调整目标

第一版已经完成关注画师、收藏作品、收藏橱窗及独立收藏中心，但独立收藏中心重复实现了三套简化卡片，和公开大厅的筛选、详情入口与展示能力割裂。

本次调整不重做关系业务，而是把收藏内容放回对应大厅：

1. “画师收藏”进入画师大厅的“关注”视图。
2. “作品收藏”进入作品广场的“我收藏的”视图。
3. “橱窗收藏”进入橱窗大厅的“我收藏的橱窗”视图。
4. 删除独立收藏中心的正常访问入口，三类内容继续复用各自大厅现有卡片、筛选、分页和详情交互。
5. 保留第一版数据库、关系状态和增删接口，仅扩展三个关系列表接口的筛选与卡片摘要能力。

调整后的原则是：**关系数据只有一份，列表页面也只有一套。** `user.role` 和当前工作台只影响工作台外壳，不拆分关注或收藏数据。

## 2. 最终入口与路由

### 2.1 共用快捷卡

企划方与画师工作台继续共用 `FavoriteShortcutCard.vue`，按钮位置和三列样式不变，只调整点击目标：

| 快捷入口 | 新目标 | 默认视图 |
| --- | --- | --- |
| 画师收藏 | `/artists?view=following` | 关注 |
| 作品收藏 | `/works?view=favorites` | 我收藏的 |
| 橱窗收藏 | `/stalls?view=favorites` | 我收藏的橱窗 |

快捷卡不再根据 `/dashboard` 或 `/painter` 拼接收藏中心地址，也不请求预览数据和虚构数量。

### 2.2 查询参数口径

三个大厅统一使用 `view` 表示当前数据视图：

- 画师大厅：`recommended`、`following`。
- 作品广场：`latest`、`popular`、`favorites`。
- 橱窗大厅：普通列表不写 `view`，收藏视图使用 `favorites`。

页面切换视图时使用 `router.replace` 更新 URL，并保留当前页面允许继续使用的分类、题材和搜索条件。URL 可以刷新、复制和通过浏览器前进后退恢复，不使用只存在组件内存中的伪状态。

### 2.3 废弃页面与路由清理

本项目中的独立收藏中心尚未作为稳定外部地址发布，不承担历史链接兼容责任。为避免保留无入口页面、重复卡片和后续误维护，本次直接清理：

- 删除 `frontend/src/views/favorites/FavoriteCenter.vue`。
- 删除 `router/index.js` 中 `DashboardFavorites`、`PainterFavorites` 两条路由记录。
- `frontend/src/views/favorites/` 目录清空后删除目录。
- 不保留 `/dashboard/favorites`、`/painter/favorites` 重定向或隐藏入口；旧地址按普通不存在路由处理。
- 删除项目内所有对上述组件、路由名和地址的代码引用，并同步修正文档与测试记录。

保留旧路由重定向虽然能兼容书签，但也会留下已经作废的产品结构。本次以代码整洁和单一入口为准，不采用该方案。

## 3. 页面设计

### 3.1 画师大厅：推荐 / 关注

在当前筛选栏上方增加二项视图切换：

```text
推荐    关注
```

- `推荐`：保持当前认证画师大厅逻辑和现有卡片样式。
- `关注`：仅显示当前账号关注且仍正常、未删除、`cert_status = 2` 的画师。
- 两个视图都复用现有题材风格、关键字搜索、动态加载、评分、简介、标签和作品预览。
- 从工作台快捷入口进入时直接激活“关注”。
- 未登录访问“关注”时跳转登录页，并携带当前 URL 作为登录后返回地址。
- 关注列表为空时显示“暂未关注画师”，并提供返回“推荐”的操作。
- 在关注画师主页取消关注后，再返回或刷新“关注”视图，该画师不再出现。

不能直接把现有 `FollowedPainterItem` 当成大厅卡片使用：它目前缺少评分、公开作品预览和作品分类摘要。后端应批量补齐这些字段，前端继续使用同一套 `artist-row`，不得为关注视图另造简化卡片，也不得逐名请求作品或评分。

### 3.2 作品广场：最新 / 热门 / 我收藏的

利用作品页顶部搜索框左侧的空白区域增加三项视图切换：

```text
最新    热门    我收藏的                         [搜索作品标题、作品说明]
```

#### 最新

- 对应当前 `sort=newest`。
- 按作品 `created_at DESC, id DESC` 排序。

#### 热门

- 使用真实收藏关系计算热度，不制造随机热度、静态权重或前端假排序。
- 排序口径：有效收藏数 `DESC`，再按 `created_at DESC, id DESC`。
- 只聚合数量，不公开收藏用户列表。
- 未产生收藏的作品仍可出现，收藏数相同时按发布时间稳定排序。

#### 我收藏的

- 调用当前账号的收藏作品列表，只显示仍公开有效的作品。
- 默认按 `favorited_at DESC, favorite_id DESC` 排序。
- 继续复用作品瀑布流、详情弹窗、作者信息和取消收藏按钮。
- 从工作台快捷入口进入时直接激活“我收藏的”。
- 在详情弹窗取消收藏后，当前收藏视图立即移除该作品并重新整理瀑布流；当前批次为空时继续补拉或显示空态。

#### 左侧筛选卡调整

- 删除“发布时间”分组；“最新、热门、我收藏的”已经在顶部承担列表视图选择，侧栏不再保留“最新发布 / 最早发布”。
- 保留“作品分类”和“题材风格”，并同时作用于三个视图。
- 为避免删除发布时间后卡片明显变矮，分类标题、按钮和间距适度放大：标题约 `16px`，按钮约 `13px`，按钮内边距和行间距各增加约 `1–2px`，两个分组的垂直留白适当增加。
- 调整后的筛选卡高度应接近现有三分组卡片，但不能通过空白占位、固定大高度或不可见元素硬撑。
- 原 `sort=oldest` 后端兼容能力可保留，但不再从本页面提供入口。

### 3.3 橱窗大厅：我收藏的橱窗

普通橱窗大厅保持当前行为。`view=favorites` 时：

- 在筛选区域增加明确标题“我收藏的橱窗”。
- 分类、题材风格、价格区间、截稿时间、排序和搜索全部保留，并作用于收藏结果。
- 继续复用当前五列卡片、真实头像、价格、销量和详情跳转，不创建收藏专用卡片。
- 默认按收藏时间倒序；用户主动选择价格排序时按价格排序，并用收藏时间与 ID 保证稳定顺序。
- 在橱窗详情取消收藏后返回收藏视图，该橱窗应从列表消失。
- 空态文案使用“暂未收藏橱窗”，而不是普通模式的“暂无符合条件的橱窗”。

筛选区只做紧凑化，不删功能：

- 缩小分类栏上下内边距与标签横向间距。
- 缩小分类栏和下方筛选行之间的距离。
- 保持输入框和下拉框可点击高度，不通过压缩到难以操作的方式换空间。
- 收藏标题、分类和筛选在常用桌面宽度内尽量控制为两行；窄屏允许自然换行。

## 4. 数据与接口复用方案

### 4.1 完整保留

以下实现继续使用，不重建、不改业务含义：

- `user_follow`、`work_favorite`、`stall_favorite` 三张关系表及唯一约束。
- 关注、收藏状态查询接口。
- 幂等关注/收藏与幂等取消接口。
- 正常账号、目标有效性、禁止自关注/自收藏、封禁账号只能取消不能新增等规则。
- 目标下架、隐藏、删除或失效后不公开展示，但不强制删除历史关系的规则。
- 画师主页关注与邀请、作品详情收藏、橱窗详情收藏按钮。

### 4.2 扩展现有列表接口

不新增第二套“大厅收藏接口”，在现有关系列表接口上增加筛选参数和大厅卡片需要的摘要字段。

#### 关注画师

`GET /api/v1/follows/painters`

新增可选参数：

- `subjects`
- `keyword`
- `page`
- `size`

返回直接复用画师大厅 `ArtistSummary`，包含：

- `id`、`username`、`nickname`、`avatar`、`bio`、`tags`
- `certStatus`
- `categories`
- `works`（每名画师最近最多 5 个公开作品预览）
- `averageScore`
- `reviewCount`

筛选、分页和画师有效性判断必须在数据库查询阶段完成；当前页作品、分类和评分采用批量查询组装，复用 `ArtistService` 的摘要组装逻辑，禁止 N+1。

#### 收藏作品

`GET /api/v1/favorites/works`

新增可选参数：

- `category`
- `subject`
- `keyword`
- `page`
- `size`

保留当前返回字段，并保证 `workId`、标题、图片、分类、题材、描述和作者摘要足够驱动现有瀑布流与详情入口。查询按收藏时间倒序，筛选与分页在数据库完成，前端不得先取全量再过滤。

#### 收藏橱窗

`GET /api/v1/favorites/stalls`

新增与公开橱窗列表一致的可选参数：

- `category`
- `keyword`
- `sort`
- `subject`
- `priceMin`
- `priceMax`
- `deliverTime`
- `page`
- `size`

返回继续保留当前字段，并补齐公开卡片所需的真实 `soldCount`。画师昵称和头像由关联查询一次返回，不再为每张卡片逐个请求公开主页。

### 4.3 热门作品排序

`GET /api/v1/works` 的 `sort` 增加 `popular`：

- 使用 `work_favorite` 对仍有效关系进行聚合。
- `ORDER BY COUNT(work_favorite.id) DESC, work.created_at DESC, work.id DESC`。
- 返回结构继续与普通作品列表一致，不要求前端获得收藏用户信息。
- 查询应使用数据库分页；实现后通过 `EXPLAIN` 检查索引和临时排序开销。

### 4.4 响应字段归一化

现有关系 DTO 使用 `painterId`、`workId`、`stallId`，公开大厅卡片使用 `id`。为避免破坏已实现接口，后端保留原 ID 字段，前端在数据入口统一映射为大厅卡片模型；不得在模板中到处判断两套字段名。

## 6. 数据库变更结论

本次调整**不需要数据库迁移，也不需要新增、删除或修改表与字段**。

原因如下：

1. `user_follow`、`work_favorite`、`stall_favorite` 保存的是账号与目标之间的真实关系，不是 `FavoriteCenter.vue` 的页面缓存。
2. 三张表已有 `(user_id, target_id)` 唯一键，继续保证幂等新增与状态查询。
3. 三张表已有 `(user_id, created_at)` 索引，支持“我关注 / 我收藏”按关系时间分页。
4. 三张表已有以目标 ID 开头的索引，`work_favorite` 可用于真实收藏数聚合和热门作品排序。
5. 画师筛选、作品筛选、橱窗筛选、销量和卡片摘要均可通过现有业务表关联查询与 DTO 扩展完成，不需要复制数据到新表。

## 11. 第一版设计转换总结

《收藏关注设计》不删除，作为已完成功能和历史提交的记录；后续开发按下表转换：

| 第一版内容 | 调整后处理 | 说明 |
| --- | --- | --- |
| 关注/收藏目标、权限、幂等和失效规则 | 保留 | 继续作为业务规则依据 |
| `user_follow`、`work_favorite`、`stall_favorite` | 保留 | 不新增替代关系表，不迁移已有数据 |
| 状态查询、关注/收藏、取消接口 | 保留 | 路径、幂等语义和权限不变 |
| 三个关系分页列表接口 | 转换并扩展 | 保留原路径，增加大厅筛选参数和卡片摘要字段 |
| 画师主页关注/邀请、作品详情收藏、橱窗详情收藏 | 保留 | 不因列表调整回退已完成功能 |
| 工作台共用收藏快捷卡 | 保留组件、修改目标 | 从收藏中心改为三个公共大厅视图 |
| `/dashboard/favorites`、`/painter/favorites` | 删除 | 不保留路由和重定向 |
| `FavoriteCenter.vue` 三标签收藏中心 | 删除 | 连同空目录和全部引用清理，不再维护独立列表和简化卡片 |
| 第一版“收藏中心独立分页与取消操作”验收项 | 由大厅验收替代 | 分页、筛选、取消均在对应大厅验证 |
| 黑名单、举报和高级收藏管理预留 | 保留为后续项 | 本次不扩大范围 |

因此，第一版并非整体废弃：**废弃的是重复页面和跳转结构，继续复用的是已经完成的关系数据、权限规则、接口基础和详情按钮。**
