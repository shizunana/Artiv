# 我的应征生命周期与有效关系

> 文档状态：已按确认口径实现。
> 最近更新：2026-08-25。

## 1. 产品口径

“我的应征”只展示当前仍然有效的应征关系，不承担订单进度或历史记录展示。

| 业务事件 | 是否继续出现在“我的应征” | 是否继续出现在企划应征画师列表 |
| --- | --- | --- |
| 画师应征企划 / 接受定向邀请 | 是 | 是 |
| 企划方发送订单 | 是 | 是 |
| 订单待接单、进行中、待验收或售后中 | 是 | 是 |
| 画师主动取消应征 | 否 | 否 |
| 对应合作订单完成 | 否 | 否 |

订单创建和履约状态只进入“订单管理 → 我承接的订单”，不在“我的应征”增加“已收到订单、进行中、已完成”等状态。只要记录仍在“我的应征”中，就代表应征关系当前有效。

## 2. 数据结构

`application` 增加：

- `active`：当前有效关系标记，`1` 有效、`0` 已结束；企划侧和画师侧列表均只读取 `active=1`。
- `ended_reason`：内部审计字段，当前使用 `WITHDRAWN`、`REJECTED`、`ORDER_COMPLETED`。
- `ended_at`：关系终止时间。

旧 `status` 字段继续保留用于兼容原有“待处理 / 已选定”内部流转，但不再作为“我的应征”的展示状态，也不会由本人应征接口返回给页面。

迁移脚本：`backend/sql/migrations/20260825_active_application_relation.sql`。

迁移规则：

1. `status=0/1` 的旧应征恢复为有效关系。
2. 即使旧状态为 `3`，只要仍有关联的待接单、进行中、待验收或售后订单，也恢复为有效关系；这修复了历史上“企划侧仍合作、画师侧却显示撤销”的冲突。
3. 其余旧退出记录标记为非当前，并按已完成订单或旧状态补充终止原因。

数据库保留终止记录用于唯一关系复用和内部审计，但任何用户列表都不展示这些历史记录。

## 3. 服务端一致性

- `GET /api/v1/applications/mine`：只返回本人 `active=1` 的记录。
- `GET /api/v1/projects/{projectId}/applications`：只返回该企划 `active=1` 的记录；定向邀请待回应的特殊展示逻辑不变。
- 发起企划会话、发送企划订单和非公开企划的应征关联访问均统一检查 `active=1`。
- 修改报价和取消应征均要求关系仍有效；已有订单使用下单时的金额快照，后续改价不修改旧订单。
- 画师取消应征：`active=0`、`ended_reason=WITHDRAWN`。
- 企划订单完成结算：`active=0`、`ended_reason=ORDER_COMPLETED`。
- 重新应征会复用同一企划与画师的旧记录，重置为 `active=1` 并清空终止字段。

## 4. 页面结构

“我的应征”复用订单横向卡片：

- 企划图片；
- 最多 10 字企划标题；
- 企划类型与应征时间；
- 最多 15 字企划详情；
- 我的报价；
- “企划详情”“更改应征”两个入口。

“企划详情”进入对应企划；“更改应征”进入同一页面并自动定位本人应征、打开既有改价/取消应征弹窗。两者不再重复提供相同详情入口。

## 5. 已验证结果

- 数据库迁移连续执行两次成功，字段与索引幂等。
- 迁移后本地主库共有 5 条当前有效应征；登录画师 Enana 对应 4 条，页面与数据库数量一致。
- 后端完整回归 130 项通过，前端生产构建通过。
- 浏览器确认历史退出记录不再出现，企划详情和更改应征入口正常；验收未提交报价、未取消应征，也未创建测试橱窗。
