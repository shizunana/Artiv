## 1. 页面怎么改

> 后续发布页样式调整（2026-09-07，已实施）：按用户新批注，发布页题材不再使用下拉，改为随企划类型变化的等宽多选按钮，并单独提供默认选中的“不限”（对应空数组，与具体题材互斥）。第一步六类改为三列两行圆角按钮；最新批注取消立体效果，采用 48px 高、白底细边框的扁平样式，选中为浅蓝底配蓝字，无渐变、高光、阴影或按压位移。题材按钮仍为浅蓝选中。编辑页仍用下拉，大厅仍不显示“不限”按钮。此条覆盖下文仅涉及发布页的旧下拉方案，不改变数据、接口或大厅筛选语义。最新样式仅完成代码检查、前端 29 项测试及构建，视觉由用户验收。

- 企划大厅：将顶部“全部＋六类”按钮栏与独立题材下拉合并成一个“类型与题材”下拉面板，减少常驻按钮。预算、日期、搜索和排序暂保留原位置及行为，不重做卡片或整页。
- 最新尺寸对齐：类型与题材、排序、稿酬区间、截稿日期入口统一 148×40px、6px 圆角及 14px 左右留白；长摘要省略，窄屏等宽换行，搜索框和开关保持原样。前端 30 项测试与构建通过，视觉由用户验收。
- 面板上半区为六个企划类型，下半区为题材，底部“重置 / 确定”；沿用 Element Plus 弹出层、项目品牌蓝、白底及圆角，无黑色遮罩。
- 类型可多选，再点一次取消；选中为浅蓝底＋蓝字，多个选中同时保留。使用等宽栅格，桌面面板约 460～520px、每行 3～4 格，窄屏随视口缩减列数；按钮高度至少 36px，不按文字长度忽疏忽密，并支持键盘及明确选中状态。
- 不显示“全部 / 不限”选项按钮；未选即不限制。关闭时入口显示“类型与题材”，单类型显示类型及已选题材，多类型显示“已选 N 类”，避免入口被长文本撑开。
- 常用词前置、顺序固定，不随点击跳动。目前没有频次数据，先按下表候选顺序，由用户审阅，不声称是统计热度。

## 2. 筛选规则与确认行为

| 类型选择 | 题材区 | 点击确定后的查询 |
| --- | --- | --- |
| 0 个 | 完全隐藏题材标题与选项，不显示提示或占位 | 不限制类型和题材 |
| 1 个 | 显示该类型对应题材，可多选并保持浅蓝选中 | 类型匹配，并且包含任一所选题材；未选题材则不限制题材 |
| 2～6 个 | 完全隐藏题材标题与选项，不显示提示或占位 | 所选类型取并集，不附加题材条件 |

- “头像＋插画”表示两类符合条件的企划都能看到，不要求一条企划同时属于两类。公开、招募中、审核正常、未删除、未过期及预算等条件仍全部生效。
- 发布时未填题材的企划，可以在大厅未筛题材时显示；不会自动命中“古风”等具体题材。这条现行规则不变。
- 面板使用“待选条件”和“已应用条件”两份状态。点选只改变待选状态，不请求、不刷新列表；只有“确定”才提交条件、回到第一页并关闭面板。
- 单类型切换为其他类型、多类型或零类型时，清空待选题材；返回单类型时不自动恢复旧题材。此时列表仍按上一次确定的条件显示。
- “重置”只清空面板内待选类型和题材，仍需确定才生效；不重置面板外的预算、搜索等条件。点击外部、Esc 或再次点击入口关闭，均放弃未确定的修改；重开从已应用条件开始。
- 查询失败明确提示并允许重试，不显示成真实空结果；快速连续确认时只允许最新请求更新结果、总数和加载状态，含应征数补充请求。

## 3. 企划专用题材风格（本轮必做，不是可选配套）

各组允许交叉；仅使用用户已经讨论并调整的集合，下表只调整排列，不新增、删除词项。

新建企划专用 `PROJECT_SUBJECT_OPTIONS`（各组去重后的全集）及 `PROJECT_SUBJECT_OPTIONS_BY_CATEGORY`（六类对应集合），统一放在 `constants/projectSubjects.js`；后端设置对应的企划专用规则并用测试核对前后端一致。原 `SUBJECT_OPTIONS` 及其 35 项保留给橱窗、作品和画师资料，不能直接修改公共数组。

| 企划类型 | 题材选项（候选顺序） |
| --- | --- |
| 头像 | Q版、日系、古风、厚涂、男性、女性、双人、有背景、黑白、像素、小动物、安头 |
| 立绘 | 正比、Q版、日系、古风、厚涂、男性、女性、有背景、黑白、定制 |
| 角色设计 | 正比、Q版、日系、古风、男性、女性、小动物 |
| 插画 | 日系、古风、厚涂、场景、氛围、男性、女性、双人、有背景、横插、竖插、黑白、像素、小动物 |
| 平面设计 | 日系、古风、黑白、像素、Q版 |
| 自设/OC | 正比、Q版、日系、古风、男性、女性、双人、有背景、小动物、定制、安头 |

发布与编辑配套：企划类型仍必填且只能选一个，不能把大厅多选带入发布。题材继续可选、多选，改用该类型对应的小集合及紧凑可搜索多选控件，不再铺开 35 项；不提供“不限”标签。更换类型保留交集中的已选项，不适用项移除并明确提示。服务端同步校验对应关系。

发布/编辑区域标明“题材风格（选填）”，未选择不自动勾选；空选择按现有规则保存为空，不把“不限”作为字符串写入数据库。预览、详情及其他企划摘要继续显示实际已选题材，旧企划按已确认方案清空后显示未设置/不限，不伪造新标签。

大厅单类型时必须读取同一张对应表，不继续展示原 35 项；多类型时清空并禁用题材。向导只更新企划查询的题材选项及规则，画师查询仍使用原 35 项。已有订单快照原样保留；新订单自然沿用现有逻辑记录企划当时的 `subject`，不另改快照结构。

## 4. 实施范围与保护边界

这次以 UI 为主，但类型多选需要少量查询适配，不能只改按钮后用前端拼接分页结果。

- 前端：`views/projects/ProjectList.vue`，拟新增 `components/projects/ProjectFilterPopover.vue`、`constants/projectSubjects.js`；发布/编辑页复用企划题材映射，原 `constants/subjects.js` 不改。
- 后端：`ProjectController`、`ProjectService`、`ProjectServiceImpl` 增加建议参数 `projectCategories`（去重后的最多六个类型，重复查询参数传递），一次数据库 `IN` 查询完成并集和分页。保留现有单值 `projectCategory` 给已有调用方，新旧同时传则明确拒绝；旧 `category` 仍拒绝。空集合不加类型条件，多类型夹带具体题材则拒绝，不静默忽略。
- 企划题材规则集中维护，创建/编辑和单类型查询使用同一映射；向导企划查询选项同步新集合，原单类调用保持兼容。统计依然按每条企划保存的单一类型计算，不改成并集统计。
- 不改数据库表结构，继续 `project.project_category` 单值和 `project.subject` 逗号分隔存储；不改订单快照、交易、资金、邀请或删除规则。橱窗、作品、画师资料及其筛选保留原 35 项。
- 最近核对主库企划为 0 条，实施前再确认。若已产生记录，先检查旧题材；用户已同意旧企划题材可改为空，但须备份并只处理明确的旧企划范围，不能清空其他模块或订单快照，也不能继续假设空库。
- 验收最小集：六类题材清单一致、越组/非法题材被拒绝、题材空值允许、发布多选及编辑切类保留交集；零选/单选/多选并集、题材联动、未确认不请求、重置/取消、慢请求不覆盖、分页总数与可见性、发布编辑回显、窄屏和键盘。确认橱窗/作品/画师原 35 项不变，补前后端测试并构建，逐份同步接口与进度文档。

已按后续批注调整：**零类型时收起题材；单类型时大厅题材可多选并按 OR 匹配；多类型仍清空题材**。
