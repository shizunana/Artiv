# Artiv 个人资料与认证设计

> 来源：依据《Artiv 账户设置与画师认证功能调整任务说明》整理。
> 状态：实施中。
> 最近更新：2026-08-23。

---

## 1. 目标与产品边界

目前企划方个人中心无法正常进入部分个人资料编辑功能，同时画师与企划方公开主页上的资料编辑入口不统一。

画师主页和企划方主页上的“编辑资料”按钮全部取消显示。用户修改资料时，统一进入“账户设置”。公开主页只负责展示，不承担资料编辑入口。

## 2. 账户设置

“账户设置”是企划方和画师共用的设置入口，不根据当前工作台身份维护两套账户设置。

```text
账户设置
├─ 账号安全与资料设置
└─ 身份认证
```

## 3. 账号安全与资料设置

用于维护用户基础账户资料，首期允许修改：

- 头像；
- 昵称；
- 密码；
- 企划方个人简介；
- 电话、邮箱展示为后期能力，不伪造可保存功能。

规则：

- 企划方个人简介与画师个人简介分开维护、分身份读取；
- `/profiles/{id}?role=painter` 读取画师简介，`role=employer` 读取企划方简介；
- 画师个人简介不在本页修改，而在“身份认证 → 画师信息”维护；
- 普通账户资料修改不影响画师认证状态；
- 原“公开主页 → 编辑资料”流程统一改为“账户设置 → 账号安全与资料设置”。

## 4. 身份认证

账户设置中的第二个二级菜单为“身份认证”，首期实现“画师信息”。页面负责展示和维护：

- 当前认证状态；
- 笔名；
- 常用站（个人主页、作者主页或作品集地址）；
- 画师方个人简介；
- 题材风格；
- “前往申请”或“修改信息”。

其中画师个人简介和题材风格可以直接编辑，不需要重新审核，也不影响认证状态；笔名与常用站属于认证资料，初次认证或已认证后的变更均需管理员审核。

## 5. 画师认证状态

用户侧只展示三种认证状态：

| 状态 | 含义 | 用户操作 |
| --- | --- | --- |
| 未认证 | 从未申请，或上一次申请未通过 | 前往申请 |
| 审核中 | 初次认证申请已提交 | 不允许重复提交 |
| 已认证 | 管理员审核通过 | 修改信息 |

管理员拒绝初次申请后，用户状态恢复为“未认证”，不增加“未通过”用户状态；拒绝原因通过系统消息发送，后台申请记录仍保留“已拒绝”终态。

```text
未认证 → 提交申请 → 审核中
审核中 → 管理员通过 → 已认证
审核中 → 管理员拒绝 → 未认证 + 系统消息
```

## 6. 未认证状态展示

```text
画师认证    未认证

笔名：—
常用站：—

画师方个人简介：可直接编辑
题材风格：可直接编辑

[ 前往申请 ]
```

点击“前往申请”打开画师认证申请弹窗，先进入资格检查，不直接显示提交表单。

## 7. 申请画师认证前置条件

### 7.1 画师个人简介

用户必须填写画师个人简介。未填写时显示失败项，并提供“前往完善资料”定位到当前画师信息区域。

### 7.2 有效作品数量

用户必须发布至少 4 个公开、未删除的有效作品。

```text
✓ 已填写画师个人简介
✓ 已发布 4 个作品
```

不足时显示当前数量，例如：

```text
✓ 已填写画师个人简介
✕ 作品数量不足（3 / 4）
```

### 7.3 校验边界

前端展示条件完成情况，最终资格必须由后端重新校验，不能只依赖页面中的作品数量或简介状态。

## 8. 认证申请填写内容

资格满足后填写：

- 笔名：必填；
- 常用站：必填，必须是本人在支持平台上的具体个人主页、作者主页或作品集页面。

支持平台：Pixiv、Lofter、新浪微博、小红书、哔哩哔哩、DeviantArt、站酷、涂鸦王国。

系统只进行 URL 格式、支持域名和明显平台首页校验；页面是否确实属于申请人仍由管理员人工审核。例如 `https://www.pixiv.net/` 不能作为有效认证地址。

## 9. 提交认证与审核中规则

满足“画师简介、有效作品不少于 4 件、笔名、常用站”后才能提交。提交成功后用户状态由“未认证”变为“审核中”。

审核中：

- 不允许重复提交初次申请；
- 可以查看本次提交的认证资料；
- 前后端都必须拦截重复提交；
- 画师个人简介和题材风格仍可直接修改，它们不属于本次待审认证字段。

## 10. 管理员审核

管理员认证审核至少展示：

- 申请人和用户昵称；
- 笔名、常用站；
- 画师个人简介、题材风格；
- 有效作品数量、作品列表和公开主页入口；
- 申请时间、当前状态；
- 申请类型：初次认证或认证资料修改。

管理员可以通过或拒绝。拒绝必须填写原因；已处理申请不能重复处理。

### 10.1 初次认证

- 通过：用户由审核中变为已认证，申请资料成为正式认证资料；
- 拒绝：用户由审核中恢复为未认证，并发送包含原因的系统消息。

### 10.2 认证资料修改

已认证用户修改笔名或常用站会生成修改申请。管理员必须看到当前生效资料与新申请资料的差异；通过后新资料生效，拒绝后原资料保持不变。

## 11. 初次认证通过

通过后用户页显示：

```text
画师认证    已认证

笔名：XXX
常用站：https://...

画师方个人简介：可直接编辑
题材风格：可直接编辑

[ 修改信息 ]
```

“修改信息”只处理笔名和常用站；公开画师页面继续复用现有“认证画师”标识。

## 12. 初次认证拒绝

- 必须填写拒绝原因；
- 用户状态恢复为未认证；
- 不增加“未通过”用户状态；
- 后台保留已拒绝记录；
- 拒绝结果和原因通过系统消息告知用户；
- 用户完善资料后可以再次申请。

## 13. 已认证后的资料修改

### 13.1 直接可修改资料

画师个人简介、题材风格、头像、昵称、密码和企划方个人简介直接保存，不影响认证状态，不进入管理员审核。

### 13.2 需要审核的资料

笔名、常用站属于认证依据，修改时不能直接覆盖已生效资料，而是提交认证资料修改申请。

### 13.3 修改审核中

```text
当前状态：已认证
修改笔名 / 常用站
提交修改申请
原认证资料继续生效，新资料等待审核
```

- 用户认证状态保持已认证；
- 页面额外显示“认证资料修改审核中”；
- 公开页面继续使用原已生效资料；
- 同一时间只允许一笔待审核修改申请。

### 13.4 通过或拒绝

- 通过：新笔名、常用站替换正式资料，认证状态保持已认证，并发送通过通知；
- 拒绝：正式资料不变，认证状态保持已认证，并发送包含原因的拒绝通知。

## 14. 数据与后端设计边界

### 14.1 资料归属

账号公共资料：头像、昵称、密码，以及后期电话、邮箱。

企划方资料：企划方个人简介。

画师资料：画师个人简介、题材风格。

画师认证资料：笔名、常用站、认证状态。

两种身份的简介必须分别存储和读取，不能因同一账号可切换工作台身份而共用一个简介。

### 14.2 认证申请记录

至少保存：申请 ID、用户 ID、申请类型、申请笔名、申请常用站、修改前资料快照、申请状态、管理员 ID、审核原因、申请时间、审核时间和更新时间。

后台记录的“已拒绝”只是申请终态，不是新的用户认证状态。

### 14.3 生效资料与申请资料分离

已认证用户当前生效的笔名、常用站必须与待审修改申请分离。只有管理员通过后，事务内才用申请资料替换正式资料。

### 14.4 后端校验

初次申请：

- 当前登录用户合法且不是管理员；
- 画师个人简介非空；
- 有效作品不少于 4 件；
- 笔名与常用站合法；
- 不存在其他待审核初次申请。

资料修改申请：

- 当前用户已经认证；
- 不存在其他待审核修改申请；
- 新笔名、常用站合法；
- 只能修改本人资料。

管理员处理：

- 必须是正常管理员；
- 申请仍为待审核；
- 已通过或已拒绝的申请不能重复处理。

### 14.5 幂等与事务

管理员处理在事务内锁定申请和用户，确保待审核只能进入一个终态。

初次通过：更新申请、用户认证状态、正式认证资料、管理员审计和系统通知。

初次拒绝：更新申请、恢复未认证、保留原因、管理员审计和系统通知。

修改通过：更新申请、替换正式认证资料、保持已认证、管理员审计和系统通知。

修改拒绝：正式资料不变，只更新申请结果、审计和通知。

重复点击或重复请求不能重复改变资料、发送通知或写审计。

## 15. 常用站 URL 校验

常用站不拆成“平台 + 地址”两个字段，根据 URL 域名识别支持平台。

- 仅允许合法 http/https URL；
- 域名必须属于支持平台；
- 不接受无关域名；
- 不接受明显的平台首页；
- 应指向用户主页、作者主页或作品集页面；
- 系统不自动判断作品归属，真实性由管理员人工审核。

## 16. 前端开发范围

### 16.1 公开主页

- 画师和企划方公开主页移除“编辑资料”；
- 企划方身份读取企划方简介；
- 画师身份读取画师简介和题材风格；
- 两种简介切换时不能互相覆盖。

### 16.2 账户设置

新增统一入口和两个二级菜单：账号安全与资料设置、身份认证。

### 16.3 账号安全与资料设置

支持头像、昵称、密码和企划方简介；电话、邮箱首期明确显示“后期开放”。

### 16.4 身份认证 → 画师信息

展示状态、笔名、常用站、画师简介、题材风格和申请/修改入口。画师简介与题材风格直接编辑。

### 16.5 初次认证弹窗

两阶段流程：资格检查 → 填写笔名和常用站。资格未满足时不能进入提交阶段。

### 16.6 修改信息弹窗

展示当前笔名/常用站和新值；未修改字段可保留原值。提交后不覆盖正式资料，页面显示修改审核中。

## 17. 管理后台范围

### 17.1 申请列表

展示申请时间、申请人、申请类型、笔名、常用站和状态；支持待审核、已通过、已拒绝及申请类型筛选。

### 17.2 初次申请详情

展示用户基础资料、画师简介、题材风格、有效作品和入口、申请资料、申请时间、当前状态与历史处理结果。

### 17.3 修改申请详情

清晰展示当前生效资料与本次申请资料的修改前后差异。

### 17.4 审核操作

通过/拒绝建议二次确认；拒绝必须填写原因；终态申请禁止再次处理；普通用户手工请求管理员接口必须被拒绝。

## 18. 通知与审计

复用现有系统通知与管理员审计体系：

- 初次通过：“您的画师认证申请已通过。”；
- 初次拒绝：“您的画师认证申请未通过。原因：{原因}”；
- 修改通过：“您的画师认证资料修改已通过审核。”；
- 修改拒绝：“您的画师认证资料修改未通过审核。原因：{原因}”。

管理员审计记录管理员、申请人、申请 ID、申请类型、处理结果、原因和时间。

## 19. 权限要求

普通用户可以查看和维护自己的资料、提交自己的初次或修改申请；不能查看他人后台认证资料、调用管理员接口、修改他人申请或在审核中重复提交同类型申请。

管理员可以查看历史和待审申请、通过或拒绝，但不能重复处理终态申请。

## 22. Git 提交建议

可按“账户设置与双身份资料”“初次认证状态机”“管理员审核闭环”“认证资料修改审核”分批提交。每次提交前检查差异，不提交 `.m2/`、上传文件、调试日志、构建产物或无关格式化改动。

默认只提交本地 Git；只有用户明确要求时才推送远端。

## 23. 执行要求

- 不重复建设已有功能或增加无必要冗余字段；
- 不绕过现有 JWT、管理员鉴权、通知和审计体系；
- 认证状态与资格以后端为准；
- 双身份简介必须隔离；
- 画师简介和题材风格直接修改，不进入认证审核；
- 笔名和常用站修改必须审核后生效；
- 已认证用户提交修改时不得提前覆盖正式资料；
- 优先保证状态流转、权限、幂等和数据一致性；
- 完成后运行后端测试、前端构建和必要浏览器验收，全部通过后再提交 Git。

## 24. 现有结构复用与实施映射

本次实现优先复用以下现有能力：

- `user.bio` 继续作为画师个人简介，新增独立企划方简介字段，避免迁移现有画师资料；
- `user.tags` 继续作为画师题材风格，并复用前端 `SUBJECT_OPTIONS`；
- 认证历史继续使用 `artist_certification`，增加申请类型和修改前资料快照；
- 当前正式生效的笔名、常用站独立保存在用户资料中，待审修改不会覆盖；
- 作品资格复用公开且未删除作品统计；
- 结果通知复用系统消息，管理员处理复用现有审计日志；
