# Artiv 管理员成交价格分层设计计划

> 文档状态：已开发并完成回归  
> 编写日期：2026-08-27  
> 适用页面：管理员后台 → 数据统计 → 用户需求分析（`/admin/stats`）

## 1. 改动目标

将“用户需求分析”页面现有的以下三个统计模块整体移除：

- 题材风格 Top 10；
- 预算区间；
- 企划招募有效期。

原位置改为一张横跨两列的“完成订单成交价格分层”卡片。管理员可以查看全部企划类型，或选择某一个企划类型，观察该类型已经完成的企划订单在不同成交价格层级中的分布。

本功能回答的是：

> 在选定时间和企划类型下，平台已经真实完成的企划订单，主要成交在什么价格范围？

它不统计企划发布时填写的预算区间，也不使用尚未成交、已取消或仍在进行中的订单推测市场价格。

## 2. 统计口径

### 2.1 纳入的数据

一条订单必须同时满足以下条件才进入样本：

1. `order_info.status = 3`，即订单已经完成；
2. `order_info.completed_at` 位于管理员当前选择的统计日期范围内；
3. `order_info.deleted = 0`；
4. `order_info.project_id IS NOT NULL`，即订单来源为企划；
5. `order_info.amount` 存在且大于 0。

成交价格使用 `order_info.amount`，这是订单最终采用并完成结算的实际价格。

### 2.2 不纳入的数据

- 企划预算最低价、最高价及兼容字段 `project.budget`；
- 尚未完成的订单；
- 已取消订单；
- 退款、售后或争议尚未形成最终完成结果的订单；
- 只发布但未产生订单的企划；
- 应征报价；
- 橱窗订单。

橱窗订单没有“企划发布时的类型”，因此不应混入按企划类型统计的图表。后续如需要分析橱窗成交价格，应单独建设“橱窗成交价格分层”，不能把两种来源混为同一口径。

### 2.3 企划类型来源

统计类型必须表示该订单建立时保留的企划类型，避免企划后续编辑导致历史统计变化。

读取优先级：

1. 优先读取 `order_info.project_snapshot` 中的 `category`；
2. 旧订单快照缺少类型时，回退读取关联企划的 `project.category`；
3. 两处都无法取得时归入“未分类”，只在“全部类型”中参与统计，不单独出现在常规类型筛选项中。

当前企划订单快照已经保存 `category`，新数据不需要新增数据库字段。

## 3. 类型筛选

卡片右上角增加类型选择器，默认选中“全部类型”。

筛选项：

- 全部类型；
- 头像；
- Q版全身；
- 半身像；
- 立绘；
- 组合页；
- 服设；
- 壁纸；
- 表情包；
- Live2d；
- 平面设计。

“全部类型”表示合并所有企划类型的有效完成订单样本；选择具体类型后，只重新计算该类型的五档价格边界和订单数量。

首期类型筛选只影响“完成订单成交价格分层”卡片，不改变同页的企划趋势、类型占比、需求转化路径和供需缺口，避免管理员误以为整页已经切换统计维度。

## 4. 动态价格分层算法

### 4.1 展示目标

参考图采用五档结构，视觉比例固定为：

| 分层 | 目标样本比例 | 含义 |
| --- | ---: | --- |
| 低价段 | 10% | 成交价格最低的一成订单 |
| 偏低价段 | 20% | 第 10%–30% 的订单 |
| 主流价格段 | 40% | 第 30%–70% 的订单 |
| 偏高价段 | 20% | 第 70%–90% 的订单 |
| 高价段 | 10% | 成交价格最高的一成订单 |

图形保持 `10% / 20% / 40% / 20% / 10%` 的中间高、两侧低形态；每一档下方的价格区间根据当前样本动态变化。

### 4.2 边界计算

将符合条件的实际成交金额按从低到高排序，计算：

- P10：第 10 百分位；
- P30：第 30 百分位；
- P70：第 70 百分位；
- P90：第 90 百分位。

五档动态区间为：

1. `< P10`；
2. `P10 – P30`；
3. `P30 – P70`；
4. `P70 – P90`；
5. `> P90`。

例如某一时间段中，“头像”类完成订单计算出的边界为 `80、150、420、900`，页面显示：

`< ¥80`、`¥80–¥150`、`¥150–¥420`、`¥420–¥900`、`> ¥900`。

切换为“立绘”或“全部类型”后必须重新计算，不能使用写死的价格区间。

### 4.3 图表性质说明

本图不是用数学模型将真实数据强行拟合为正态分布，也不修改任何订单价格。准确名称建议使用：

> **完成订单成交价格分层**

副标题：

> 按已完成企划订单的实际成交价格，动态划分 10% / 20% / 40% / 20% / 10% 价格层级。

这样既保留参考图希望呈现的“中间高、两侧低”视觉结构，也不会让管理员误解为真实订单天然满足正态分布。

## 5. 同价边界与小样本

### 5.1 同一价格跨越分位点

若大量订单价格相同，不能为了凑出固定比例把同价订单任意拆进不同档位。应保证相同价格始终进入同一价格档，因此实际订单占比可能不是精确的 `10% / 20% / 40% / 20% / 10%`。

图柱上的百分比表示目标分层位置；悬浮详情同时显示真实订单数和真实占比，避免隐藏同价数据造成的偏差。

### 5.2 样本不足

- 有效完成订单少于 10 笔：不绘制五档图，显示“完成订单样本不足，至少需要 10 笔”。
- 有效订单不少于 10 笔，但不同成交价格少于 5 个：显示“成交价格过于集中，暂时无法形成五档价格区间”，并展示样本数、最低价、中位价和最高价。
- 没有有效完成订单：显示标准空状态“当前条件下暂无已完成企划订单”。

## 6. 页面结构

原三个小模块替换为一张跨两列卡片：

```text
┌──────────────────────────────────────────────┐
│ 完成订单成交价格分层       [全部类型      ▾] │
│ 按实际成交价格动态划分五档                    │
│                                              │
│                 40%                          │
│         20%     ███     20%                  │
│  10%    ███     ███     ███     10%          │
│  ███    ███     ███     ███     ███          │
│ <¥80  ¥80-150 ¥150-420 ¥420-900 >¥900       │
│                                              │
│ 样本 42 笔 · 中位成交价 ¥268 · 均价 ¥315     │
└──────────────────────────────────────────────┘
```

交互要求：

1. 继续服从页面顶部的近 7 天、近 30 天和自定义日期范围；
2. 类型切换只刷新本卡片，并显示局部加载状态；
3. 每档悬浮显示分层名、价格范围、订单数、真实占比和成交总额；
4. 金额计算保留两位小数，界面可按实际值省略无意义的 `.00`；
5. 卡片在窄屏下允许横向滚动或改为五行列表，价格文字不能互相遮挡。

## 7. 接口设计

建议新增独立接口，避免修改现有需求分析接口后导致全页跟随类型选择重新统计：

```http
GET /api/v1/admin/stats/price-distribution
```

查询参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `startDate` | 否 | 开始日期，沿用管理员统计页规则 |
| `endDate` | 否 | 结束日期，沿用管理员统计页规则 |
| `category` | 否 | 不传表示全部类型；传值时必须为平台支持的企划类型 |

响应示例：

```json
{
  "range": {
    "startDate": "2026-08-01",
    "endDate": "2026-08-27"
  },
  "category": null,
  "categoryLabel": "全部类型",
  "sampleSize": 42,
  "distinctPriceCount": 17,
  "sufficient": true,
  "averageAmount": 315.00,
  "medianAmount": 268.00,
  "minimumAmount": 50.00,
  "maximumAmount": 1800.00,
  "buckets": [
    {
      "key": "LOWEST",
      "name": "低价段",
      "rangeLabel": "< ¥80",
      "targetRate": 10,
      "orderCount": 4,
      "actualRate": 9.5,
      "gmv": 240.00
    }
  ]
}
```

无数据或样本不足仍返回 `200`，通过 `sufficient`、`sampleSize` 和 `distinctPriceCount` 让前端决定空状态，不将正常的数据不足视为接口异常。
