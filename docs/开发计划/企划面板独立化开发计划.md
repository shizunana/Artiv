# 企划面板独立化开发计划

> 文档状态：已实现并通过自动化回归  
> 编写日期：2026-08-29  
> 适用范围：企划方工作台 → 我的企划 → 企划面板

## 1. 改造目标

当前企划的公开展示、企划方管理、应征处理、邀请画师和企划订单入口集中在同一个企划详情页，导致公开浏览页面同时承担业务管理职责。

本次计划将两类页面的职责拆开：

- **企划详情**：面向所有访问者的统一浏览页，展示企划内容、公开的应征画师信息和画师侧应征/邀请响应入口。
- **企划面板**：仅企划发布者可进入的管理页，集中处理编辑、招募开关、应征画师、参与画师及邀请画师。

本次不是重做企划业务状态机，而是把已有能力重新组织到更清晰的入口中；能复用的接口、弹窗和卡片不重复开发。

## 2. 页面入口与路由

### 2.1 “我的企划”卡片

在 `企划方工作台 → 我的企划` 的每张企划卡片右侧提供两个主入口：

1. **企划详情**：进入现有 `/projects/:id`，仅用于浏览公开企划内容。
2. **企划面板**：进入新增 `/dashboard/projects/:id/panel`。

企划面板完成后，删除列表原有“编辑”入口，卡片只保留“企划详情 / 企划面板”，避免同一管理功能出现两个入口。

卡片主体点击行为维持进入企划详情，不默认跳入管理页。

### 2.2 权限

- 企划面板仅允许当前企划的 `employer_id` 访问。
- 非发布者访问时后端返回 403，前端显示“无权管理该企划”，不能只依赖前端隐藏入口。
- 管理员继续使用管理员企划治理页，不通过企划方管理面板操作。
- 逻辑删除的企划不能进入面板。
- 主动下架、已过期和违规下架企划仍允许发布者进入面板查看历史应征与订单，但可执行操作按现有规则禁用。

## 3. 页面整体结构

### 3.1 顶部企划摘要

顶部使用独立摘要卡，展示：

- 企划标题；
- 企划编号；
- 发布时间；
- 用途；
- 类型；
- 单张稿酬预算区间；
- 截稿日期；
- 当前状态：招募中、已过期、已下架、违规下架、定向邀请待回应等；
- 上下架开关；
- “编辑企划”按钮；
- “查看企划详情”按钮。

截稿日期在标题下方独立展示并提供“修改”入口；上下架开关只负责直接改变上架状态，不再打开综合管理弹窗。

第一版不增加“统计报表”按钮，不新增统计接口。后续确有企划维度数据分析需求时，再单独设计浏览、应征、邀请和成交指标。

### 3.2 功能标签页

公开企划摘要卡下方设置三个标签页：

1. **参与画师**：展示该企划已经创建的企划订单及其画师。
2. **应征画师**：展示当前仍有效的应征关系，并提供沟通和发送订单操作。
3. **邀请画师**：搜索或从已关注画师中选择目标，发送“邀请报价”或“带价邀请”。

公开企划默认进入“应征画师”，第一版不持久化用户上次选择。

定向企划同样使用企划面板，但标签语义调整为：

1. **参与画师**：展示接受定向邀请后由该企划产生的订单；
2. **邀请画师**：复用应征画师卡片结构，展示本次定向邀请的唯一目标画师及其待回应、已接受或已拒绝状态；
3. **邀请其他画师**：不开放操作，显示“定向企划不开放邀请其他画师；如需邀请其他人，请重新发布企划或按既有规则转为公开企划”。

定向企划默认进入“邀请画师”。这样可以共用企划面板整体结构，同时不会突破“一项定向企划只能邀请一名画师”的既有规则。

## 4. 顶部管理能力

### 4.1 日期、上下架与删除入口

企划面板不再保留笼统的“变更企划”按钮，原管理能力拆分为三个明确入口：

- **修改截稿日期**：放在标题和发布时间旁，使用独立日期弹窗；
- **上架状态**：摘要区开关直接执行上架或下架，不再弹出综合管理弹窗；
- **删除企划**：集中移动到“我的企划”列表页，通过独立选择弹窗处理。

重新上架仍要求截稿日期至少为当前日期 2 天后；过期企划需先修改日期。被拒绝的定向企划重新上架时继续按既有规则转为公开企划。待回应定向邀请、违规下架、关联订单等限制继续由后端校验。

“我的企划”的删除弹窗按公开企划/定向邀请当前分类加载项目，允许勾选后统一提交。待回应定向邀请在界面直接禁选；是否存在关联订单在提交时由后端逐条校验。删除成功的项目从列表移除，失败项目保留并给出提示。

### 4.2 编辑企划内容（新增能力）

新增“编辑企划”入口，用于企划尚未进入应征或合作关系时修正完整内容。可编辑：

- 标题；
- 需求描述；
- 预算区间；
- 类型；
- 题材风格；
- 参考图片；
- 稿件要求；
- 创作阶段及顺序。

该入口不允许修改：

- 合作方式（公开企划/定向企划）；
- 定向邀请目标画师；
- 发布者；
- 企划业务状态和治理状态；
- 截稿日期、上下架和删除（分别由日期入口、上架开关和“我的企划”删除弹窗负责）。

完整内容编辑只在企划仍未建立外部业务关系时开放。后端必须同时确认：

- 不存在 `deleted = 0` 的有效应征；
- 不存在待处理或已接受的邀请；
- 不存在任何关联企划订单，包括已拒单、已取消和已完成订单。

已拒绝或已失效邀请本身不锁定编辑；但只要已有应征或历史订单，仍然锁定。定向企划在邀请待回应或已接受期间不允许完整编辑，避免画师收到邀请后企划内容被整体替换。

前端隐藏或禁用只是引导，最终必须由后端事务校验。建议新增独立入参 `ProjectContentUpdateRequest`，不要直接复用包含 `mode`、`invitePainterId` 和 `deadline` 的发布 DTO。

完整编辑页面可以复用 `ProjectNew.vue` 的类型、预算、图片、稿件要求和创作阶段表单，但进入编辑模式时：

- 预填现有企划内容；
- 隐藏合作方式和邀请目标；
- 隐藏截稿日期；
- 提交到内容编辑接口；
- 保存成功后返回企划面板。

### 4.3 招募开关

参考企划面板的“招募停止”开关，但映射到 Artiv 已有状态和截稿日期，不新增第二套招募字段。

| 页面状态 | 开关展示 | 点击行为 |
| --- | --- | --- |
| 正常上架且未过期 | 开启 | 关闭时调用现有下架接口，`status = 4` |
| 主动下架 | 关闭 | 开启前必须选择至少当前日期 2 天后的新截稿日期，再调用重新上架接口 |
| 正常上架但已过期 | 关闭并标注“已过期” | 开启前选择新截稿日期，只延长日期即可恢复招募 |
| 管理员违规下架 | 禁用 | 只能由管理员恢复 |
| 定向邀请待回应 | 禁用 | 延续现有“不能撤回或下架”的规则 |

截稿日期只影响新增应征和接受邀请；已有应征、会话和订单不受上下架或过期影响。

## 5. 应征画师标签

### 5.1 复用内容

从 `ProjectDetail.vue` 抽取应征画师区域为可复用组件，例如：

`ProjectApplicantList.vue`

复用以下内容：

- 画师头像、昵称、简介；
- 平均评分与评价数；
- 题材标签；
- 四张公开作品预览；
- 应征报价；
- 定向邀请等待回应卡片；
- 私信；
- 发送企划订单；
- 已存在非终态订单时进入订单详情。

### 5.2 两种使用模式

- **企划详情模式**：只展示公开信息，不向企划方显示管理操作。
- **企划面板模式**：仅发布者可见“私信 / 发送企划订单 / 订单详情”。

画师本人在企划详情中的“取消应征 / 更改应征”仍保留，不迁入企划方面板。

### 5.3 数据接口

继续复用：

`GET /api/v1/projects/{projectId}/applications`

继续复用已有私信与发单接口：

- `POST /api/v1/messages/private`（现有企划会话方法）；
- `POST /api/v1/projects/{projectId}/applications/{applicationId}/order`。

不在前端复制应征业务判断；发单资格、重复非终态订单、黑名单、余额和账号状态仍由后端校验。

## 6. 参与画师标签

### 6.1 定义

“参与画师”不是另一套企划成员表。只要企划方已经基于该企划某条应征创建过企划订单，该订单对应画师就进入参与画师范围。已拒单、已取消、已完成和售后订单均属于该企划的参与历史，不因订单进入终态而移除画师。

页面数据以**企划订单**为事实来源：

- 一个企划可以向多名画师分别发送独立订单；
- 同一画师在历史订单结束并重新应征后，可能产生多笔订单；
- 每笔订单必须保留独立状态与“订单详情”入口，不能合并成一个虚构合作状态。

### 6.2 展示结构

采用“按画师分组、组内展示全部订单”的结构。每名参与画师只显示一张画师卡，卡片内列出该画师在当前企划下产生的全部订单，不能只保留最新订单，也不能把多笔订单合并成一个笼统状态。

画师卡顶部展示：

- 画师头像、昵称；
- 该画师在当前企划下的订单总数；
- 状态摘要，例如“进行中 1 笔 · 已完成 2 笔”。

画师卡内部不重新设计树状订单列表，直接复用现有“企划方工作台 → 我委托的订单”中的订单行组件和视觉结构。每笔订单仍独立展示：

- 企划封面；
- 企划标题与订单状态标签；
- 订单编号；
- 订单金额；
- 创建时间；
- 当前阶段；
- 订单状态；
- “订单详情”按钮。

由于当前页面已经处于某个企划的管理面板中，复用订单行时移除原有“企划详情”按钮，避免重复导航；右侧只保留“订单详情”。订单详情仍进入现有企划方订单详情路由。

布局关系：

```text
画师 Enana                         3 笔订单
进行中 1 笔 · 已完成 1 笔 · 已取消 1 笔

[复用“我委托的订单”订单行：订单 #20｜进行中｜第 1 阶段｜¥500｜订单详情]
[复用“我委托的订单”订单行：订单 #31｜已完成｜终稿｜¥800｜订单详情]
[复用“我委托的订单”订单行：订单 #42｜已取消｜¥600｜订单详情]
```

当同一画师订单较多时，画师卡默认展示最近若干笔，其余订单可在卡片内展开；展开只是 UI 收纳，不影响数据完整性。

状态筛选建议沿用现有订单语义：

- 全部；
- 待接单；
- 进行中；
- 待验收；
- 已完成；
- 已取消；
- 售后中。

状态筛选作用于组内订单，而不是直接筛掉整名画师。只要该画师至少有一笔订单符合当前筛选条件，就显示该画师卡，并且卡片内只列出符合条件的订单。另提供画师昵称搜索，用于快速定位某名参与画师。

“参与画师数量”按不同 `painter_id` 去重；订单数量单独展示，避免一个画师多笔订单造成数量误解。该计数包含已拒单、已取消等历史订单对应画师。

### 6.3 需要扩展的接口

当前 `GET /api/v1/orders` 只能按参与角色、订单来源和状态组筛选，不能按单个企划筛选。建议在原接口增加可选参数：

`GET /api/v1/orders?participantRole=employer&source=project&projectId={projectId}`

后端查询必须同时限定：

- `employer_id = 当前用户`；
- `project_id = projectId`；
- `deleted = 0`。

不能只按 `projectId` 查询，否则会造成企划订单越权读取。

前端复用现有订单状态文案、金额格式、封面和订单详情路由，不复制订单状态机。

## 7. 邀请画师标签

### 7.1 复用能力

邀请业务继续复用画师主页已有的两种公开企划邀请：

- **邀请报价**：不填写价格，画师接受时提交报价；
- **带价邀请**：企划方填写最低 ¥50 的邀请价格，画师接受后按该价格生成应征。

继续复用：

`POST /api/v1/invitations`

企划面板中固定当前 `projectId`，不再让用户从下拉框重复选择企划。

### 7.2 搜索与已关注画师

搜索交互复用发布定向企划时已经完成的选择器。进入公开企划“邀请画师”标签时，默认加载已关注且可邀请的认证画师，同时保留搜索按钮：

- 搜索已认证画师；
- “关注的画师”快捷入口；
- 头像、昵称和简介；
- 排除当前账号；
- 选择后填写邀请类型、价格和附言。

复用接口：

- 画师搜索：现有画师列表接口；
- 已关注画师：`GET /api/v1/follows/painters`；
- 邀请发送：`POST /api/v1/invitations`。

第一版可以直接复用现有后端校验：已经应征、存在待处理/已接受邀请、黑名单、企划过期或下架等情况由发送邀请接口拒绝，并向用户显示明确原因。

为减少重复代码，建议把画师主页邀请弹窗抽取为：

`ProjectInviteDialog.vue`

组件支持两种调用方式：

- 画师主页传入固定 `painterId`，用户选择公开企划；
- 企划面板传入固定 `projectId`，用户搜索并选择画师。

定向企划不调用该弹窗。“邀请其他画师”标签只显示不开放说明。

### 7.3 可邀请条件

公开企划主动邀请必须同时满足：

- 发布者为当前用户；
- `mode = 0`，即公开企划；
- 正常上架且未过期；
- 未被管理员违规下架；
- 未逻辑删除。

目标必须为已认证画师，且：

- 不是企划方本人；
- 双方不存在黑名单关系；
- 目标尚未有效应征该企划；
- 不存在按现行规则禁止的重复邀请。

## 8. 企划详情页调整

企划详情继续保留：

- 企划方公开资料；
- 截稿日期和预算；
- 参考图、需求详情、稿件要求、创作阶段；
- 公开应征画师列表；
- 画师应征、接受邀请、拒绝邀请、修改报价和取消应征；
- 返回列表等浏览导航。

迁移到企划面板的企划方操作：

- 修改截稿日期；
- 主动上下架；
- 私信应征画师；
- 发送企划订单；
- 进入该企划参与画师的订单；
- 主动邀请其他画师。

企划发布者浏览详情时，应征卡片与其他用户看到的公开信息一致，但不显示企划方管理按钮；页面可以提供一个单独的“进入企划面板”导航按钮，避免管理入口丢失。

## 11. 状态与异常规则

- 已过期或主动下架：可查看参与画师、应征历史与订单；禁止新增邀请、新应征和新发单，重新招募后恢复。
- 违规下架：可查看历史关系和订单；编辑、上架、邀请和新发单全部禁用。
- 逻辑删除：面板不可访问；存在关联订单时原本就不允许删除。
- 已有订单：不受企划过期或下架影响，继续正常接单、交付、验收、完成和售后。
- 应征取消或订单完成导致有效应征移除后，不再出现在“应征画师”，但历史订单仍出现在“参与画师”。
- 已拒单或已取消订单对应画师仍保留在“参与画师”历史中，可通过状态筛选查看。
- 只要存在任何关联订单，即使当前已没有有效应征，也不能再完整编辑企划内容。
- 黑名单：继续禁止新邀请、新沟通和新发单；已有非终态订单按现有规则阻止加入黑名单。
- 并发发单：继续依靠后端“同一应征不能同时存在重复非终态订单”校验。
