# 绘约（HuiYue）沟通与消息设计（F9）

> 版本：v1.0 ｜ 日期：2026-08-12 ｜ 性质：设计文档（尚未编码）
> 定位：订单开发前置模块（F9），支撑应征私聊、订单内议价、状态通知、系统通知。

## 1. 功能范围

- 站内信：系统通知 / 应征通知 / 订单变化 / 验收结果
- 私信：用户间 1v1 私聊（应征沟通、议价前沟通）
- 订单内聊天：订单双方在订单详情内的消息（含接单前议价）
- WebSocket 实时推送：新消息即时到达 + 未读红点
- 消息已读 / 全部已读

## 2. 数据模型（message 表）

现状（已有）：

| 字段 | 说明 |
| --- | --- |
| id / from_id / to_id / order_id | 基本消息结构 |
| type | 0 系统、1 应征、2 订单、3 私信 |
| content / read_at / deleted | 内容、已读时间、逻辑删除 |

需要补充：

- `project_id`（可选）：私信关联企划（应征沟通按企划聚合会话）
- `conversation_key`（推荐）：`from_to` 归一化（min:max）便于取双方会话，如 `1_2`

## 3. WebSocket 架构

当前 `MessageWebSocketHandler` 为骨架，需完善：

1. **连接鉴权**：`ws://localhost:8080/ws?token=<jwt>`，握手时用 JwtUtil 解析 userId，失败拒绝连接
2. **会话管理**：`userId → WebSocketSession`（已有 ConcurrentHashMap 骨架），支持多端（一个用户多连接）
3. **断线重连**：前端心跳（ping/pong）+ 断线指数退避重连；重连后拉取未读消息补差
4. **消息格式**：

```json
{
  "type": "NEW_MESSAGE",
  "data": { "id": 100, "fromId": 2, "toId": 1, "orderId": null, "content": "...", "createdAt": "2026-08-12 12:00" }
}
```

事件类型：`NEW_MESSAGE`、`ORDER_UPDATE`、`APPLICATION`、`SYSTEM`

## 4. 接口设计

### 4.1 已有接口（保持）

- `GET /api/v1/messages`：我的消息列表
- `PUT /api/v1/messages/{id}/read`：单条已读
- `PUT /api/v1/messages/read-all`：全部已读

### 4.2 新增接口

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| POST | `/api/v1/messages/private` | 发送私信（from 当前用户，body 含 toId/content/projectId?） | 登录 |
| GET | `/api/v1/messages/conversation?withUserId=` | 我与某用户的会话消息（分页） | 双方 |
| POST | `/api/v1/orders/{id}/messages` | 订单内发送消息 | 订单双方 |
| GET | `/api/v1/orders/{id}/messages` | 订单内消息列表（分页） | 订单双方 |

## 5. 事件推送清单

| 事件 | 触发时机 | 推送对象 |
| --- | --- | --- |
| APPLICATION | 画师应征企划 | 企划方 |
| ORDER_UPDATE | 订单创建 / 接单 / 状态变化 | 订单双方 |
| ORDER_STAGE | 阶段提交 / 验收结果 | 订单双方 |
| SYSTEM | 系统通知（认证结果、封禁等） | 相关用户 |

推送流程：业务操作 → 写 message 落库 → WebSocket pushToUser → 前端未读 +1 / 红点。

## 6. 前端结构

- 消息中心（`/dashboard/messages`、`/painter/messages`）：消息列表 + 会话切换
- 私聊窗口：应征列表 / 画师主页发起，1v1 聊天（气泡样式）
- 订单详情聊天框：订单内消息（接单前议价 + 进行中沟通）
- WebSocket 客户端（`src/utils/ws.js`）：连接、心跳、重连、事件分发、未读计数

## 6.1 私聊入口与交互设计

### 入口位置（4 类场景）

| 场景 | 入口 | 说明 |
| --- | --- | --- |
| ① 应征沟通（下单前核心） | 应征管理列表每条记录右侧「沟通」按钮 | 企划方与应征画师 1v1；画师侧「我的应征」有对应入口 |
| ② 发现画师 | 画师列表 / 画师主页「私聊」按钮 | 已认证画师可被私聊 |
| ③ 订单沟通 | 订单详情底部聊天框 | 接单前议价 + 进行中沟通 |
| ④ 消息中心 | 顶栏铃铛 → 消息中心会话列表 | 私信 / 订单消息 / 系统通知统一入口 |

### 触发与使用流程

```
点击「沟通 / 私聊」按钮
    ↓
打开私聊窗口（1v1，气泡样式，仅双方可见）
    ↓
发送消息 → 落库（conversation_key 聚合会话）→ WebSocket 推送给对方
    ↓
对方顶栏铃铛红点 +1 → 消息中心出现新会话 → 点击回复
    ↓
达成一致 → 企划方在应征列表「选定」该画师 → 创建订单
```

### 交互细节

- 应征列表「沟通」按钮与「选定」按钮并列，先沟通后选定
- 私聊窗口支持：发送文字、查看历史消息（分页加载）、消息时间分组
- 消息中心会话按最近消息时间排序，未读加粗 / 红点
- 订单详情聊天框：待接单时用于议价（配合画师报价 / 企划方确认金额按钮），接单后用于过程沟通

## 11. C2C 下单—沟通补充记录（2026-08-12）

> 本节对应隔离分支 `feature/f9-messaging` 的提交 `75217d6`（前置功能提交为 `5ff3c0b`），尚未合并入 `main`。它记录本轮新增的最小沟通闭环及测试边界。

### 11.1 本轮新增能力

- 消息中心收敛为“我的消息”和“系统通知”两个一级入口。
- 画师应征后通知企划方；企划方通过 `PUT /api/v1/applications/{id}/select` 选定应征者后，画师收到 `APPLICATION_SELECTED` 通知，双方自动建立带 `projectId` 的项目沟通会话。
- 橱窗 `POST /api/v1/stalls/{id}/purchase` 跳过支付，创建仅用于会话关联的最小 `order_info` 记录；买家收到 `STALL_PURCHASED`、画师收到 `STALL_PURCHASE_RECEIVED`，双方自动建立带 `orderId` 的交易沟通会话。
- 新增 `GET /api/v1/messages/notifications`；会话摘要按“双方 + projectId + orderId”隔离，避免普通私聊、应征沟通和橱窗沟通串在一起。
- 橱窗下单成功与应征选定成功均直接跳转到对应沟通会话；会话支持后续文本发送与 WebSocket 推送。

### 11.2 本轮明确不做

- 不做支付、托管、接单/拒单、订单阶段、验收、退款、库存扣减或恢复、订单详情页和完整订单状态流转。
- 最小订单只表示“本次双方沟通由哪个橱窗下单触发”，不能视为已支付或已开始履约。

### 11.3 测试记录与未测试接口

- 已通过：后端 `mvn.cmd test`（8 项、0 失败）、前端 `npm.cmd run build`。
- 已实际联调：橱窗下单后双方系统通知、自动交易会话、订单关联会话文本发送、应征选定后的自动项目会话。
- 未逐项人工联调：下架/无库存/自购等下单异常分支、应征选定越权与重复选定、双浏览器 WebSocket 实时到达及断线重连、所有通知卡片点击行为。
- 正式订单聊天 `POST/GET /api/v1/orders/{id}/messages`、订单状态接口仍未实现；当前橱窗沟通统一使用 `POST /api/v1/messages/private` 携带 `orderId`。

> 更完整的字段、请求示例和接口状态见隔离分支中的 `docs/接口文档.md` 与本文件第 11 节。

### 11.4 审查后补充的边界修复

- 订单详情 `GET /api/v1/orders/{id}` 仅允许该订单的企划方或画师读取；已以非参与者账户访问测试订单，确认返回 `2003`（无权限）。
- 企划关联会话仅在画师被选定后建立和发送；前端“沟通”入口也仅对已选定应征显示，避免已撤回或未选定应征进入会话。
- 当前打开的会话收到 WebSocket 新消息时，前端会直接追加气泡并同步已读与未读数。
- “系统通知全部已读”改用专用接口 `PUT /api/v1/messages/notifications/read-all`，只处理非私信通知，不再误读普通私信和交易会话。

### 11.5 仍未完成的人工验收

- 双浏览器同时在线时的 WebSocket 气泡实时追加、断线重连与未读补偿尚未逐项人工验收。
- 系统通知“全部已读”已验证后端过滤条件；尚未用双端未读私信场景逐项人工复验私信绝不受影响。
- 下架、无库存、自购、应征选定越权、重复选定等异常分支尚未逐项浏览器验收。
