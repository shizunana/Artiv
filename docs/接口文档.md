## 1. 通用约定

### 1.1 基础信息

- 基础路径：`/api/v1`
- 开发环境地址：`http://localhost:8080`
- 数据格式：JSON（`Content-Type: application/json`）
- 认证方式：登录后请求头携带 `Authorization: Bearer <token>`

### 1.2 统一返回结构

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

| code | 含义 |
|------|------|
| 200 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录 / 登录过期 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

### 1.3 分页返回结构

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "total": 100,
    "current": 1,
    "size": 10,
    "records": []
  }
}
```

## 2. 认证模块 `/auth`（✅ 已实现）

### 2.1 注册（模拟注册）

`POST /api/v1/auth/register`

```json
{
  "username": "artist001",
  "password": "123456",
  "nickname": "阿绘",
  "role": 2
}
```

> `role`：1 企划方、2 画师、3 管理员（注册仅允许 1 / 2）。无手机验证码、无短信。

响应：`data` 为创建的用户信息（不含密码）。

### 2.2 登录

`POST /api/v1/auth/login`

```json
{
  "username": "artist001",
  "password": "123456"
}
```

响应：

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "user": { "id": 1, "username": "artist001", "nickname": "阿绘", "role": 2, "certStatus": 0 }
  }
}
```

### 2.3 获取当前用户

`GET /api/v1/auth/me`（需登录）

响应：`data` 为当前登录用户信息（含 `role`、`certStatus`、`bio`、`tags`、`balance`）。`balance` 为当前可用余额；充值、提现、冻结及余额流水接口尚未实现。

### 6.1 发布企划示例

```json
{
  "title": "国潮风节日海报插画",
  "description": "需要一张国潮风格的节日海报插画",
  "budget": 1500.00,
  "deadline": "2026-09-01",
  "tags": ["国潮", "插画"],
  "category": "头像",
  "subject": ["Q版", "日系"],
  "images": ["/uploads/xxx.png"],
  "requirements": {
    "size": "3000×4000 px",
    "colorMode": "RGB",
    "formats": ["PNG", "PSD"],
    "publishPermission": "仅作品集展示"
  },
  "mode": 0
}
```

> `mode`：0 公开招募（全员可见）、1 定向邀请（仅被邀画师可见）。`recruit_deadline` 默认发布后 10 日。
> `category`：类型（同橱窗分类：头像 / 立绘 / 服设 等 10 项）；`subject`：题材风格（35 个选项，可多选）。

列表筛选参数：`category`（类型精确匹配）、`subject`（题材模糊匹配）。

### 6.2 企划状态

`TINYINT`：0 招募中、1 已选定、2 进行中、3 已完成、4 已关闭。

### 6.3 企划详情补充（2026-08-12，project-detail）

`GET /api/v1/projects/{id}` 已用于公开企划详情页。响应中 `employer` 是发布者安全摘要，不要求前端再请求 `/api/v1/users/{id}`，也不会返回用户名、密码、角色、认证状态、账号状态等敏感/内部字段。

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "id": 7,

    "requirements": "{\"size\":\"3000×4000 px\",\"colorMode\":\"RGB\",\"formats\":[\"PNG\",\"PSD\"],\"publishPermission\":\"仅作品集展示\"}",

      "id": 12,

      "avatar": "https://example.com/avatar.png",
      "bio": "Illustration studio",
      "tags": "fantasy,game"
```

前端约定：`images` 的第一张仅作为约稿大厅卡片封面；详情页展示完整有序参考图。详情页实现范围包括公共信息、参考图、结构化需求、发布者摘要、应征与作者侧应征管理入口；不包含参考站的交易担保、完整评价区、推荐画师、相似企划、举报/收藏/分享等扩展区块。

## 7. 应征模块 `/applications`（✅ 已实现）

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| POST | `/api/v1/projects/{id}/applications` | 画师应征（`intro` + 正数 `quote`）；要求已认证且至少有 4 件公开作品 | 已认证画师 |
| GET | `/api/v1/projects/{id}/applications` | 查看有效应征列表（安全画师摘要 + 4 件公开作品） | 公开 |
| GET | `/api/v1/applications/mine` | 我的应征（画师工作台） | 本人 |
| PUT | `/api/v1/applications/{id}/quote` | 修改待处理应征报价，请求体 `{ "quote": 1200 }` | 应征画师本人 |
| DELETE | `/api/v1/applications/{id}` | 撤销应征 | 本人 |

### 7.1 应征示例

```json
{
  "intro": "擅长国潮插画，可提供初稿预览",
  "workLink": "/works/1",
  "quote": 1200.00
}
```

应征状态：0 待处理、1 已通过、2 已拒绝、3 已撤销。

`GET /api/v1/projects/{id}/applications` 响应记录结构为 `ApplicationDetail`：`application`（待处理或已选定的有效应征记录）、`painter`（只含 `id`、`nickname`、`avatar`、`bio`、`tags` 的公开摘要）、`works`（该画师最近 4 件公开且未删除作品）。该接口允许匿名和所有登录角色访问，不返回余额、角色状态等账号内部字段。

应征前置规则：企划必须处于招募状态且未过招募截止时间；画师必须为正常账号、已认证画师，并至少有 4 件公开作品；同一画师不能重复保留待处理/已选定应征。申请画师认证接口 `/api/v1/users/me/cert` 同样要求先公开至少 4 件作品。

撤销与改价规则：两者均仅应征画师本人可调用，且当前仅待处理应征可撤销或改价。

沟通规则：应征本身不会自动创建聊天；企划作者可通过 `/projects/{projectId}/conversations/{painterId}` 发起，画师不能主动发起，只能在已有会话内回复。


事件类型：`NEW_MESSAGE`（新消息）、`ORDER_UPDATE`（订单变化）、`APPLICATION`（新应征）、`SYSTEM`（系统通知）。

| POST | `/api/v1/orders/{id}/cancel` | ✅ 已实现 | 仅企划方可取消待接单订单；退回余额并恢复库存。请求体可传 `reason`。 |
| POST | `/api/v1/orders/{id}/after-sale` | ✅ 已实现，仲裁未实现 | 仅企划方可在进行中或待验收时申请；状态变为 5 并记录原因，当前不自动退款或结算。画师侧仅保留“联系客服”占位。 |
| POST | `/api/v1/orders/{id}/stages` | ✅ 已实测 | 仅画师在状态 1 提交当前阶段；每次产生新版本，不覆盖历史；随后状态 `1 → 2`。 |

`POST /api/v1/orders/{id}/stages` 请求体：

```json
{
  "content": "本次交稿说明",
  "image": "/uploads/original.png"
}
```

- `image` 为必填且只允许一个 `/uploads/` 图片路径；画师每次交付只上传一张原图。
- 服务端读取原图后自动生成最长边不超过 1080px、JPEG 质量约 72%、带重复 `HUIYUE PREVIEW` 水印的预览图，写入 `/uploads/order-previews/`；订单阶段同时保存预览路径和原图路径。
- 企划方在交易完成前的详情响应中不会获得原图路径，只能看到水印预览；完成交易后才返回原图下载路径。
- 当前上传控制器只支持图片，因此交付暂指高清图片；PSD、ZIP 等源文件上传尚未实现。

`PUT /api/v1/orders/{id}/stages/current` 请求体：

```json
{
  "action": "complete",
  "remark": "验收备注"
}
```

- `action=approve`：通过当前阶段并进入下一阶段。
- `action=complete`：接受当前阶段的交付并直接完成交易，可从初稿等任意阶段跳过剩余阶段；同一事务内立即结算画师余额并开放当前原图。
- `action=revise`：要求修改且必须提供修改意见；画师订单详情会在被退回的提交上显示该意见。
- 阶段来自下单时的橱窗 `phases` 快照；橱窗后续修改不会影响已创建订单。

#### 15.7.2 资金、库存与并发规则

- 当前采用**简化托管**：下单时直接从企划方 `user.balance` 扣减，最终确认后增加画师 `user.balance`；尚未拆分“可用余额/冻结余额”，也没有资金流水表。
- 下单和退款恢复时使用数据库行锁读取买家、橱窗与订单，避免并发超卖或同一订单重复推进。
- 画师拒单或企划方在待接单时取消，会退回买家余额并恢复一件库存；只有企划方可在进行中/待验收阶段申请退款售后。画师侧改为“联系客服”占位，不能调用售后接口。
- 橱窗下架不会改变任何订单状态，也不会删除订单；已有订单的企划方仍可通过订单关系访问下架/无库存橱窗详情。
- 橱窗删除会检查所有未删除关联订单，只有订单状态全部属于 `3=已完成` 或 `4=已取消` 时才允许删除；`0/1/2/5` 均会阻止删除。
- 正式支付渠道、充值、提现、平台手续费和对账均未实现。

#### 15.7.3 订单事件、通知与会话卡片

- 每次关键流转写入 `order_event`：创建、接单、拒单、取消、交稿、要求修改、阶段通过、完成、申请售后。
- 同一事件同时创建双方站内通知，并向既有双方合并私聊写入带 `orderId` 的系统消息；“查看详情”按当前身份进入 `/dashboard/orders/{id}` 或 `/painter/orders/{id}`。
- 消息扩展栏“发送订单状态”先查询当前用户订单，再筛选当前会话双方共同参与的订单并弹出选择器；选择具体订单后发送 `subtype=PRIVATE_ORDER_CARD` 的卡片，保留 `orderId`，不创建新会话。
- 新表与字段迁移位于 `backend/sql/migrations/20260813_stall_order_flow.sql`。该迁移已在当前本地 `huiyue` 测试库执行。
