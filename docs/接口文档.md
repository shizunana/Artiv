# 绘约（HuiYue）接口文档

> 版本：v2.3 ｜ 更新日期：2026-08-13
> 本文以 `main` 分支控制器、服务实现与已合并提交为准。状态含义：✅ 已实现｜⚠️ 最小实现/有明确边界｜⏳ 未实现。

## 1. 通用约定

- 基础路径：`/api/v1`；开发环境：`http://localhost:8080`
- 登录接口以外，受保护接口使用 `Authorization: Bearer <token>`。
- 统一响应：`{ "code": 200, "message": "操作成功", "data": {} }`。
- 分页 `data`：`total`、`current`、`size`、`records`。
- 常用错误码：`2001` 参数校验失败、`2002` 资源不存在、`2003` 无权操作、`3001` 状态流转不合法、`4001` 上传非法。

## 3. 企划与应征

### 3.1 `POST /projects`

所有已登录账号可发布企划；服务端校验标题不超过 20 字、截稿日期不少于发布后 7 天。`mode=0` 公开招募，`mode=1` 定向邀请；定向时可提供 `invitePainterId`。

```json
{
  "title": "角色立绘约稿",
  "description": "需要一张全身角色立绘",
  "budget": 1500,
  "deadline": "2026-09-01",
  "category": "立绘",
  "subject": ["日系", "女性"],
  "images": "[\"/uploads/a.png\", \"/uploads/b.png\"]",
  "requirements": {
    "size": "3000×4000 px",
    "colorMode": "RGB",
    "formats": ["PNG", "PSD"],
    "publishPermission": "可以自由发布"
  },
  "mode": 0
}
```

- `category`：橱窗与企划共用的 10 个分类。
- `subject`：共享的 35 项题材风格，可多选；约稿大厅可通过 `subject` 筛选。
- `images` 第一张在大厅作为封面，详情页展示全部参考图。

### 3.2 应征与会话

| 方法 | 路径 | 权限/规则 |
| --- | --- | --- |
| POST | `/projects/{projectId}/applications` | 已认证画师提交 `intro`、正数 `quote`、可选 `workLink`。 |
| GET | `/projects/{projectId}/applications` | 仅企划作者；每项含应征、画师资料和最多 4 个作品。 |
| PUT | `/applications/{id}/select` | 仅企划作者；仅可选定待处理应征，写入“应征已被选定”通知。 |
| DELETE | `/applications/{id}` | 仅应征画师本人；仅待处理应征可撤销。 |
| POST | `/projects/{projectId}/conversations/{painterId}` | 仅企划作者可对待处理或已选定应征者主动建立/取得沟通首消息；画师不能用此接口主动建会话。 |
| POST | `/projects/{projectId}/order-intents/{painterId}` | ⚠️ 占位；仅校验归属与有效应征，返回“订单功能开发中”，不创建订单。 |

当前一次企划只在产品层面选定 1 名画师；数据关系仍以 `application` 为核心，后续可扩展多名入选。

## 4. 橱窗

### 4.1 管理与公开访问

- `GET /stalls`：仅返回 `status=1` 的上架橱窗；支持 `page`、`size`、`category`、`keyword`、`sort`、`subject`、`priceMin`、`priceMax`、`deliverTime`。
- `GET /stalls/mine`：当前画师的全部未删除橱窗（包括已下架）。
- `GET /stalls/{id}`：仅允许访问上架且未删除的橱窗；下架橱窗返回 `2002` 与消息“请先上架后查看详情”。
- `PUT /stalls/{id}/status?status=0|1`：本人上/下架；`DELETE /stalls/{id}`：本人逻辑删除并下架。

创建/编辑请求使用 `StallRequest`，至少包含 `title`、`cover`、`images`、`price`、`stock`、`deliverTime`、`phases`、`params`、`description`。`params` 存稿件参数 JSON，`phases` 存创作阶段 JSON。

### 4.2 `POST /stalls/{id}/purchase`（最小下单—沟通）

已登录用户可购买其他画师的上架、有库存橱窗。该接口：

1. 以橱窗价格生成一条 `order_info`，`status=0`；
2. 给买家与画师各写一条系统通知；
3. 写入一条交易来源的会话引导消息。

**边界**：不支付、不扣库存、不接单、不进入履约；该订单仅用于保留橱窗下单事实和沟通来源。不能将它视为完整 F8 订单。

## 6. 消息与 WebSocket

### 6.1 REST

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/messages` | 当前用户收到的全部消息分页。 |
| GET | `/messages/conversations` | 当前用户按**对方用户**合并后的私聊会话摘要。 |
| GET | `/messages/conversation?withUserId={id}` | 我与该用户的单一文本私聊历史。`projectId`、`orderId` 参数目前不再切分读取结果。 |
| POST | `/messages/private` | 发送最多 500 字文本私信；`toId`、`content` 必填。可携带项目/订单来源做权限校验，但新消息统一写入双方直聊会话。 |
| GET | `/messages/notifications` | 仅系统/应征通知，排除 `type=3` 私信。 |
| GET | `/messages/unread-count` | 当前用户总未读数。 |
| PUT | `/messages/{id}/read` | 仅接收者标记一条消息已读。 |
| PUT | `/messages/read-all` | 标记当前用户所有未读消息。 |
| PUT | `/messages/notifications/read-all` | 只标记非私信通知，不影响直聊未读。 |

### 6.2 当前会话规则

- 会话键为归一化双方 ID（`minId_maxId`）；同一对用户在消息中心仅显示一个会话，防止橱窗/应征来源重复出现“分身”。
- 橱窗购买、企划作者主动开启沟通会写一条带业务 `subtype` 的引导消息；前端以“系统提示”卡片展示，并预留“查看详情”跳转接口。
- 引导消息保留 `projectId`/`orderId` 作为业务来源；普通后续私信不再按来源拆分会话。
- 企划作者可创建项目沟通；画师只能在已有会话中回复。

### 6.3 WebSocket

地址：`ws://localhost:8080/ws?token=<jwt>`。后端已进行 token 鉴权，支持同一账号多连接；消息先落库，再尝试推送 `NEW_MESSAGE`、`APPLICATION`、`SYSTEM`。前端已提供指数退避重连。心跳、断线后自动补拉、双账号实时人工回归仍待补测。
