## 1. 通用约定

- 基础路径：`/api/v1`
- 后端端口：`8080`
- 前端开发地址：`http://localhost:5173`
- 请求与响应：JSON；上传接口使用 `multipart/form-data`
- 登录鉴权：`Authorization: Bearer <token>`
- WebSocket：`ws://localhost:8080/ws?token=<token>`
- 时间：ISO 8601；金额：十进制数；分页页码从 1 开始

统一响应：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

分页响应的 `data` 使用 MyBatis-Plus `Page`，常用字段：

```json
{
  "records": [],
  "total": 0,
  "size": 10,
  "current": 1,
  "pages": 0
}
```

### 1.1 匿名访问规则

以下 GET 接口允许匿名访问；如携带 JWT，服务端仍会解析身份，用于下架资源、历史订单关联资源等可选鉴权：

- 企划、橱窗、作品的公开列表及数字 ID 详情
- `GET /api/v1/projects/{projectId}/applications`
- `GET /api/v1/users/artists`
- `GET /api/v1/users/{id}/public-profile`
- `GET /api/v1/users/{id}/works`
- `GET /api/v1/users/{id}/stalls`
- `GET /api/v1/users/{id}/projects`
- `GET /api/v1/reviews`

除登录、注册和上述公开 GET 外，其余接口默认需要 JWT。

### 1.2 首页公开数据组合

首页不新增专用聚合接口，使用以下已实现的匿名公开接口并行读取真实内容：

- `GET /api/v1/projects?page=1&size=4&sort=newest`：最新公开招募企划。
- `GET /api/v1/projects/{projectId}/applications?page=1&size=1`：读取每条首页企划的有效应征总数；单条统计失败时明确显示暂不可用，不伪造为 0。
- `GET /api/v1/stalls?page=1&size=4&sort=newest`：最新在售且有库存的画师橱窗。
- `GET /api/v1/works?page=1&size=8&sort=newest`：首页精选作品。
- `GET /api/v1/users/artists?page=1&size=3`：认证画师、简介、题材标签和公开作品摘要。

上述业务区域独立处理加载、空数据和失败重试；首页不使用虚构评价、硬编码业务指标或静态业务数据作为接口失败后的回退内容。首屏右侧五图是随前端发布的固定装饰资源，只用于视觉展示，不代表作品记录，也没有点击跳转。当前首页数据量较小，企划应征数沿用大厅现有逐条查询方式；数据规模扩大后可新增公开聚合接口避免 N+1 请求。

注册请求：

```json
{
  "username": "artist01",
  "password": "123456",
  "nickname": "示例画师",
  "role": 2
}
```

用户名为 3–20 位且沿用既有唯一约束，密码为 6–32 位。`nickname` 会去除首尾空格并要求全表唯一；重复昵称返回业务码 `1004`，不会创建用户。数据库使用 `uk_nickname` 作为并发场景的最终约束。

| GET | `/api/v1/users/{id}/projects` | 已实现 | 匿名 | 指定企划方公开或已完成企划；默认每页 12 |
| POST | `/api/v1/users/me/certifications` | 已实现 | 画师 | 提交认证申请；要求主页简介和至少 4 件公开作品 |
| GET | `/api/v1/users/me/certifications/latest` | 已实现 | 画师 | 查询本人最近一次认证申请 |
| PUT | `/api/v1/users/me/cert` | 兼容接口 | 画师 | 旧客户端认证入口，内部转为新认证申请；新代码不得调用 |
| PUT | `/api/v1/users/me/profile` | 已实现 | 画师 | 修改唯一昵称、主页简介和平台统一题材风格标签；认证前也可维护 |
| PUT | `/api/v1/users/me/avatar` | 已实现 | 登录 | 更新本人头像，只接受本站 `/uploads/` 地址 |
| GET | `/api/v1/users/{id}` | 兼容接口 | 登录 | 返回基础用户资料并清除密码；公开页面应优先使用 `public-profile` |

画师大厅 `subjects` 为英文逗号分隔的多选值，当前按“同时包含全部所选题材”筛选。服务端目前先读取认证画师再进行内存筛选和分页，数据规模扩大前需要改为数据库分页。

展示资料请求：

```json
{
  "nickname": "示例画师",
  "bio": "擅长人物与场景插画",
  "tags": ["日系", "场景", "厚涂"]
}
```

`nickname` 必填，去除首尾空格后最长 50 字；允许保留本人当前昵称，但不能与其他用户重复。服务层先排除本人 ID 检查，数据库 `uk_nickname` 负责并发写入的最终保护；冲突返回业务码 `1004` 和“昵称已被使用，无法更改”。接口返回清除密码后的最新用户资料，前端据此同步顶部导航和工作台昵称。

认证申请请求：

```json
{
  "commonId": "画师阿绘",
  "commonSite": "https://example.com/artist-profile"
}
```

`commonId` 必填；`commonSite` 可空，填写时必须为有效的 `http/https` 个人主页。提交时服务端再次统计公开作品并保存数量快照，管理员通过前仍会重新核验主页简介和公开作品数。

头像请求：

```json
{
  "avatar": "/uploads/xxxxxxxx.jpg"
}
```

公开主页接口只应返回公开展示字段，不应扩展用户名、手机号、余额、认证材料等隐私字段。正常用户无论认证状态都能打开 `role=painter` 主页并查看公开作品；前端根据 `certStatus` 显示“认证画师”或“未认证”。认证仍是应征等交易能力的权限条件，不是公开主页的准入条件。需求完成率和准时交稿率只在画师视图统计、展示；企划方视图不计算也不展示需求完成率。

公开列表参数：`page`、`size`、`category`、`keyword`、`sort`、`subject`、`priceMin`、`priceMax`、`deliverTime`。

创建橱窗的关键字段：

```json
{
  "title": "角色立绘约稿",
  "category": "立绘",
  "cover": "/uploads/cover.png",
  "images": "/uploads/detail-1.png,/uploads/detail-2.png",
  "price": 500,
  "stock": 3,
  "deliverTime": "30天",
  "phases": "[{\"name\":\"初稿\"},{\"name\":\"修改\"},{\"name\":\"终稿\"}]",
  "params": "{\"subjects\":[\"日系\"]}",
  "description": "服务说明"
}
```

编辑接口只接受：

```json
{
  "stock": 5,
  "subjects": ["日系", "场景"]
}
```

立即下单会校验上架、库存、余额以及禁止购买自己的橱窗；事务内扣减余额和库存，并创建订单快照、阶段、事件、双方通知和会话系统卡片。

> 待补权限边界：产品规则要求只有已认证画师可以创建橱窗，但当前 `POST /stalls` 只校验登录账号未被封禁，尚未校验画师身份和 `cert_status=2`。前端入口限制不能替代后端校验，本项按“部分实现”记录。

| GET | `/api/v1/projects/{id}` | 已实现 | 匿名/可选登录 | 下架企划仅作者、既有应征者、关联订单双方或正常管理员可读 |

列表参数：`page`、`size`、`keyword`、`status`（兼容参数）、`sort`、`budgetMin`、`budgetMax`、`deadlineWithin`、`deadlineAfter`、`tag`、`category`、`subject`。

当前列表服务固定只返回 `mode=0`、`status=0`、治理状态正常且未删除的企划；`sort=budget` 按预算降序，其他值回退为按创建时间倒序。列表尚未按 `recruit_deadline` 排除已过招募期企划，也没有定时任务自动变更招募/截稿状态；应征接口会在招募期到期后拒绝新应征。

发布企划请求：

```json
{
  "title": "角色立绘需求",
  "description": "需求说明",
  "budget": 800,
  "deadline": "2026-09-30",
  "tags": ["长期合作"],
  "category": "立绘",
  "subject": ["日系", "女性"],
  "images": "/uploads/reference.png",
  "requirements": {
    "style": "风格不限",
    "size": "与画师商议",
    "colorMode": "RGB",
    "formats": ["JPG", "PNG"],
    "publishPermission": "需经委托方同意发布"
  },
  "phases": "[{\"name\":\"初稿\"},{\"name\":\"修改\"},{\"name\":\"终稿\"}]",
  "mode": 0,
  "invitePainterId": null
}
```

标题最长 20 字，预算必须大于 0，截稿日期至少为发布后 7 天。创作阶段只保存名称和顺序，旧版 `percent` 字段会被忽略。

> 待补可见性边界：公开大厅已固定排除 `mode=1` 的定向企划，但数字 ID 详情尚未完整限制为发布者、被邀请画师、关联业务方或管理员可见，不能将“列表不可见”等同于“详情已鉴权”。

应征请求：

```json
{
  "intro": "创作思路和相关经验",
  "quote": 700
}
```

应征要求：企划处于有效招募期；画师账号正常、认证通过、至少有 4 件公开作品；报价为正数。已撤销或已拒绝的历史记录再次应征时会复用并重新激活。

应征列表只统计状态 0 待处理、1 已选定且未删除的记录。企划大厅卡片和详情页均应使用分页响应 `total` 作为有效应征人数。

正式企划订单金额取应征报价；同一企划可以向多名画师分别发单，但同一应征不能同时存在重复非终态订单。

| GET | `/api/v1/orders/{id}/disputes/current` | 已实现 | 订单双方 | 查询当前争议、双方证据与订单事件，不返回无关私聊 |

| PUT | `/api/v1/orders/{id}/stages/current` | 已实现 | 企划方 | 通过、要求修改或直接完成当前阶段 |

订单列表参数：

- `page`、`size`
- `source=stall` 或 `project`
- `statusGroup=delivery`、`review` 或 `afterSale`
- `participantRole=employer` 或 `painter`

订单状态：

| 值 | 状态 |
| --- | --- |
| 0 | 待接单 |
| 1 | 进行中 |
| 2 | 待验收 |
| 3 | 已完成 |
| 4 | 已取消 |
| 5 | 争议中 |

阶段提交：

```json
{
  "content": "初稿说明",
  "image": "/uploads/original.png"
}
```

服务端根据唯一原图生成最长边不超过 1080px、带 `ARTIV PREVIEW` 水印的验收预览。交易完成前企划方响应中的原图地址会被清空；最后阶段通过或执行 `complete` 后结算并开放原图。

阶段验收：

```json
{
  "action": "approve",
  "remark": ""
}
```

`action` 支持：

- `approve`：通过并进入下一阶段；若已是最后阶段则完成
- `revise`：要求修改，`remark` 应填写修改意见
- `complete`：跳过剩余阶段并直接完成、结算、开放原图

争议请求：

```json
{
  "reason": "当前交付与确认需求不一致",
  "images": ["/uploads/evidence-a.png", "/uploads/evidence-b.png"],
  "description": "图片中标出了差异位置"
}
```

争议只允许从进行中或待验收状态发起。创建后订单进入 `5=争议中`，普通交易操作暂停，等待管理员执行全额退款企划方或全额结算画师。

用户封禁请求：

```json
{
  "status": 1,
  "reason": "多次发布违规内容",
  "bannedUntil": "2026-09-01T00:00:00"
}
```

`bannedUntil` 为空表示永久封禁。封禁用户仍能登录、浏览和查看历史，但不能发布企划、应征、创建橱窗、购买橱窗或按应征发送新订单；封禁事务会锁定并终止其全部未结束订单，向下单用户全额退款，并恢复橱窗库存。限时封禁由定时任务与请求时惰性检查自动解除。

仲裁请求：

```json
{
  "result": "REFUND_EMPLOYER",
  "reason": "根据双方证据认定应全额退款"
}
```

`result` 首期只接受 `REFUND_EMPLOYER` 和 `SETTLE_PAINTER`。`PARTIAL_REFUND` 为后续扩展预留值，当前会明确返回状态流转错误。所有认证、封禁、企划治理、仲裁和自动解封都会写入 `admin_action_log`。

统计日期默认近 7 天，提供近 30 天快捷选项，自定义范围为 1–366 天。总用户数是当前未删除用户快照；新增用户、新增订单、完成订单和成交额随日期范围变化，成交额只统计 `completed_at` 落在范围内且当前状态为已完成的订单。需求统计中的 `categories` 用于企划类型分布，`supplyDemandGap[].activeStalls` 用于当前在售橱窗类型分布；`funnel` 按企划去重，前端展示相邻阶段转化率。

## 14. 错误码

| code | 含义 |
| --- | --- |
| 200 | 操作成功 |
| 400 | 参数错误 |
| 401 | 未登录或登录过期 |
| 403 | 无权操作该资源 |
| 404 | HTTP 资源不存在 |
| 500 | 服务器内部错误 |
| 1001 | 用户名已存在 |
| 1002 | 用户名或密码错误 |
| 1003 | Token 无效或已过期 |
| 1004 | 昵称已存在 |
| 2001 | 参数校验失败 |
| 2002 | 业务资源不存在 |
| 2003 | 无权操作该业务资源 |
| 3001 | 状态流转不合法 |
| 3002 | 预算或余额不足 |
| 4001 | 上传文件类型或大小不合法 |

> 当前响应语义：业务异常通常仍以 HTTP 200 返回统一 JSON，并在响应体 `code` 中使用 `2001`、`2003`、`3001` 等业务码；认证拦截等少数场景会直接使用 HTTP 401。若验收要求越权请求的 HTTP 状态必须为 403，需要统一调整异常到 HTTP 状态的映射，并同步回归前端拦截逻辑。
