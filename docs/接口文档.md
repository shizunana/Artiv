## 1. 通用约定

### 1.1 基础信息

- 基础路径：`/api/v1`
- 开发环境地址：`http://localhost:8080`
- 数据格式：JSON（`Content-Type: application/json`）
- 认证方式：登录后请求头携带 `Authorization: Bearer <token>`

### 1.2 统一返回结构

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

| code | 含义 |
|------|------|
| 200 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录 / 登录过期 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

### 1.3 分页返回结构

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "total": 100,
    "current": 1,
    "size": 10,
    "records": []
  }
}
```

## 2. 认证模块 `/auth`（✅ 已实现）

### 2.1 注册（模拟注册）

`POST /api/v1/auth/register`

```json
{
  "username": "artist001",
  "password": "123456",
  "nickname": "阿绘",
  "role": 2
}
```

> `role`：1 企划方、2 画师、3 管理员（注册仅允许 1 / 2）。无手机验证码、无短信。

响应：`data` 为创建的用户信息（不含密码）。

### 2.2 登录

`POST /api/v1/auth/login`

```json
{
  "username": "artist001",
  "password": "123456"
}
```

响应：

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "user": { "id": 1, "username": "artist001", "nickname": "阿绘", "role": 2, "certStatus": 0 }
  }
}
```

### 2.3 获取当前用户

`GET /api/v1/auth/me`（需登录）

响应：`data` 为当前登录用户信息（含 `role`、`certStatus`、`bio`、`tags`）。

### 6.1 发布企划示例

```json
{
  "title": "国潮风节日海报插画",
  "description": "需要一张国潮风格的节日海报插画",
  "budget": 1500.00,
  "deadline": "2026-09-01",
  "tags": ["国潮", "插画"],

  "subject": ["Q版", "日系"],

  "mode": 0
}
```

> `mode`：0 公开招募（全员可见）、1 定向邀请（仅被邀画师可见）。`recruit_deadline` 默认发布后 10 日。

列表筛选参数：`category`（类型精确匹配）、`subject`（题材模糊匹配）。

### 6.2 企划状态

`TINYINT`：0 招募中、1 已选定、2 进行中、3 已完成、4 已关闭。

## 7. 应征模块 `/applications`（✅ 已实现）

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| POST | `/api/v1/projects/{id}/applications` | 画师应征（`intro` + 正数 `quote` + 可选作品链接） | 已认证画师 |
| GET | `/api/v1/projects/{id}/applications` | 查看企划应征列表（含画师基础资料和最多 4 个作品） | 企划作者 |
| GET | `/api/v1/applications/mine` | 我的应征（画师工作台） | 本人 |
| DELETE | `/api/v1/applications/{id}` | 撤销应征 | 本人 |

### 7.1 应征示例

```json
{
  "intro": "擅长国潮插画，可提供初稿预览",
  "workLink": "/works/1",
  "quote": 1200.00
}
```

应征状态：0 待处理、1 已通过、2 已拒绝、3 已撤销。

`GET /api/v1/projects/{id}/applications` 响应记录结构为 `ApplicationDetail`：`application`（应征记录）、`painter`（画师基础资料）、`works`（该画师最多 4 个作品）。该接口仅企划作者可访问。

撤销规则：`DELETE /api/v1/applications/{id}` 仅应征画师本人可调用，且当前仅待处理应征可撤销。

沟通规则：应征本身不会自动创建聊天；企划作者可通过 `/projects/{projectId}/conversations/{painterId}` 发起，画师不能主动发起，只能在已有会话内回复。

#### 橱窗下单响应示例

`POST /api/v1/stalls/5/purchase`

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "id": 9,
    "stallId": 5,
    "employerId": 1,
    "painterId": 2,
    "amount": 120.00,
    "status": 0
  }
}
```

> `status=0` 在现有表结构中保留为“待接单”，但本轮不提供接单/拒单操作；它只表示创建了沟通关联记录，不能作为已支付、已接单或已开始履约的依据。

> `GET /api/v1/orders/{id}` 已增加订单参与者校验：只有 `employerId` 或 `painterId` 可读取；本轮已实际验证非参与者返回 403。

#### 交易会话发送示例

```json
  "toId": 2,
  "orderId": 9,
  "content": "请确认角色设定和交付时间。"

```

## 15. 2026-08-13 当前实现勘误与新增记录（优先于上文早期表述）

本节只记录相对早期文档的变化；未列出的接口仍按原章节查阅。当前 `main` 已通过后端 29 项单元测试与前端生产构建。

### 15.1 橱窗管理与最小下单—沟通

| 方法 | 路径 | 当前状态 | 当前行为 |
| --- | --- | --- | --- |
| GET | `/api/v1/stalls` | ✅ | 只返回上架且未删除橱窗；支持 `category`、`keyword`、`sort`、`subject`、`priceMin`、`priceMax`、`deliverTime`。 |

| GET | `/api/v1/stalls/{id}` | ✅ | 仅上架橱窗可访问；下架项返回 `2002`，消息“请先上架后查看详情”。 |
| PUT | `/api/v1/stalls/{id}/status?status=0|1` | ✅ | 仅橱窗所属画师可上/下架。 |

| POST | `/api/v1/stalls/{id}/purchase` | ⚠️ | 购买其他画师的上架、有库存橱窗时创建最小 `order_info`、双方通知与会话引导消息；不支付、不扣库存、不接单、不履约。 |

### 15.2 企划、应征与订单意图

- `POST /projects` 已支持：标题（最多 20 字）、需求描述、预算、截稿日（至少发布后 7 天）、分类（10 项）、题材风格（35 项可多选）、多参考图、结构化 `requirements`、公开/定向 `mode`。
- `GET /projects` 支持 `keyword`、`status`、`sort`、`budgetMin`、`budgetMax`、`deadlineWithin`、`deadlineAfter`、`tag`、`category`、`subject`。大厅卡片以第一张参考图为封面。
- `GET /projects/{id}` 已返回安全 `employer` 摘要和完整参考图/稿件要求；不要求前端二次读取完整用户实体。
- `PUT /applications/{id}/select` 已实现：仅企划作者可选定待处理应征，并给画师写入 `APPLICATION_SELECTED` 通知；不自动创建正式订单，也不自动拒绝其他应征。
- `POST /projects/{projectId}/conversations/{painterId}` 已实现：仅企划作者可对待处理或已选定应征者主动建立/获取引导会话；画师不得主动建立。
- `POST /projects/{projectId}/order-intents/{painterId}` 是无副作用占位，返回“订单功能开发中”。当前一个企划在产品层面仅选定一名画师，但仍使用 `application` 关系，便于未来多画师扩展。

### 15.4 订单、评价与上传的边界

- `GET /orders` 与 `GET /orders/{id}` 已限制为订单双方，非参与者返回 `2003`。
- 旧 `POST /orders` 仍直接接收实体，尚未完成金额来源、归属、重复订单等安全化；不得用于正式企划下单。

### 15.5 作品集与作品广场（2026-08-13 新增）

| 方法 | 路径 | 当前状态 | 当前行为 |
| --- | --- | --- | --- |
| GET | `/api/v1/works` | ✅ | 仅返回 `visibility=1` 的公开、未删除作品；支持 `page`、`size`、`category`、`subject`、`keyword`、`sort=newest|oldest`。 |
| GET | `/api/v1/works/mine` | ✅ | 返回当前登录画师自己的所有未删除作品，包含公开和仅自己可见作品。 |
| POST | `/api/v1/works` | ✅ | 上传单张作品记录。需要先调用上传接口取得图片地址，再提交标题、类型、题材、说明、图片和可见范围。 |
| PUT | `/api/v1/works/{id}/visibility?visibility=0|1` | ✅ | 仅作品所属用户可修改可见范围；`0` 隐藏，`1` 公开。 |
| DELETE | `/api/v1/works/{id}` | ✅ | 仅作品所属用户可删除，使用逻辑删除。 |

`POST /api/v1/works` 请求体：

```json
{
  "title": "夏日角色立绘",
  "category": "立绘",
  "subject": "女性,日系",
  "image": "/uploads/example.png",
  "description": "作品说明，最多 500 字。",
  "visibility": 1
}
```

- `category` 使用橱窗同款 10 项类型；`subject` 使用现有 35 项题材风格，可多选并以英文逗号存储。
- `visibility=1` 为公开，会展示于作品广场；`visibility=0` 为仅自己可见，不会通过公开列表接口返回。
- 我的作品页的“隐藏/公开”按钮调用可见范围接口，不会删除作品图片或作品记录。
- 上传接口 `POST /upload` 当前允许的图片格式及 5MB 限制仍适用。作品编辑、点赞、收藏、作品详情页和画师主页跳转尚未实现。
