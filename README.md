# 艺绘（Artiv）

艺绘是一个面向企划方与自由画师的美术约稿交易平台（毕业设计项目），采用 **Vue 3 + Spring Boot + MySQL** 前后端分离架构。

> 权利说明：Artiv 项目及项目所有者原创的代码、功能设计和文档仍归项目所有者所有；部分演示图片引用自网络公开的私人作品，其图片权利归原作者或合法权利人。使用、部署或再分发前请阅读[《素材与版权免责声明》](素材与版权免责声明.md)。

当前已形成的主要业务链路：

**发布企划 / 浏览固定价橱窗 → 应征或直接下单 → 双方合并私聊 → 画师接单 → 按创作阶段交付与验收（水印预览）→ 模拟托管结算 → 双方评价 / 争议仲裁**

## 已实现重点

- 首页已重构为站内真实内容门户，展示固定首屏视觉图、招募企划、橱窗、精选作品和认证画师。
- 正常用户不论是否认证均可展示公开画师主页和作品；认证状态用于控制应征等交易能力。
- 企划方和画师共用 `/settings` 账户设置；账号资料、企划方简介与画师资料分离，公开主页不再承担编辑入口。
- 已认证画师修改笔名或常用站时先生成待审申请，管理员通过后才替换正式资料；拒绝不会影响当前认证状态和已生效资料。
- 企划支持 6 个企划类型（头像、立绘、角色设计、插画、平面设计、自设/OC）、35 项题材、多个参考图、自定义创作阶段、上下架、受保护删除及一企划向多名画师分别发单；发布单选、大厅精确筛选。
- 企划只保留一个截稿日期：日期当天仍可产生新应征，次日自动从大厅排除并禁止新应征/接受邀请；已建立的应征、会话与订单继续运行。主动下架和自然过期分别显示“已下架”“已过期”，重新上架或拒绝邀请后转公开必须选择至少 2 天后的新日期。
- 橱窗支持库存、固定价格、上下架、删除保护、正式下单以及订单阶段快照。
- 订单支持模拟资金托管、接单、每阶段版本 1–9 张图片交付、要求修改、提前完成、最终结算和高清原图放行。订单详情按状态返回水印/原图，但 `/uploads/**` 仍是公开静态映射，不能据此认定原图下载授权已完整实现。
- 接单、交稿、修改、阶段通过、提前/正常完成与企划方主动取消通知统一展示订单标题快照；企划/橱窗标题超过 10 字时截为前 10 字加 `...`。平台系统通知与会话系统提示统一用中文单书名号 `「」` 标记人名、标题和阶段，并以品牌蓝强调这些对象；普通用户私信保持原文与原色。
- 双方均可发起争议并提交图片证据；管理员可执行全额退款或全额结算，部分退款仅保留扩展位。
- 消息按双方用户合并为唯一会话，不开发独立订单聊天室；具体订单通过订单状态卡片和 `orderId` 区分。
- `role=1/2` 只保存默认工作台入口；点击工作台切换会持久化该偏好，但应征、创建橱窗等画师交易权限始终由后端认证状态和具体业务条件决定。
- 画师大厅已使用数据库分页与当前页批量聚合，只读取每名画师最近 5 件公开作品，不再把全部认证画师和全部作品载入内存。
- 关注认证画师、收藏公开作品和收藏上架橱窗已形成真实关系接口；管理入口复用公共大厅的关注/收藏筛选，不存在独立收藏中心。企划方、画师两种工作台共用同一侧栏快捷卡和收藏数据。
- 他人公开主页可加入账号级黑名单或举报用户；屏蔽关系由服务端双向限制关注、邀请、应征、下单、会话与私信，并在账户设置中提供“查看主页 / 解除屏蔽”。画师个人最低带价金额仍为后续能力，当前带价邀请固定最低 ¥50。
- 定向邀请复用普通应征与后续订单流程：待回应画师计入应征人数；接受后建立合并私聊，并在会话系统提示和独立系统消息分别写入相同正文；拒绝后自动下架，可由企划方改为公开招募。
- 公开企划主动邀请复用同一提醒箱：邀请报价由画师接受时只填写报价，带价邀请只需确认企划方预设且锁定的价格；三类邀请接受均不要求填写应征说明，接受后只生成有效应征并自动建立会话，不直接创建订单。普通大厅应征仍需填写应征介绍和报价。企划过期、下架或删除后，仍待处理的公开邀请显示“已失效”。
- 普通企划应征与定向邀请通知统一使用用户展示名；优先昵称、其次登录名，仅在两者均缺失时回退内部 ID。历史 `画师 #ID` 应征通知已通过幂等迁移修正。
- “收到的邀请”复用订单横向卡片，支持全部、待处理、已接受、已拒绝、已失效筛选，并区分定向邀请、邀请报价和带价邀请；删除只隐藏当前画师的提醒，不改变邀请状态，也不影响已建立的会话、应征、订单或履约。
- 企划方与已认证画师首页均已整理为快捷工作台：画师侧保留经营概览，企划方侧聚焦进行中订单、近期企划和快捷操作；全部复用现有业务接口，不新增独立统计接口。
- 完成订单支持双方在 7×24 小时内各评价一次；公开主页、画师大厅、应征卡和橱窗详情展示角色对应评分，画师可申请隐藏不当评价并由管理员审核。
- 管理后台包含统一管理员鉴权与审计、认证审核、永久/限时封禁、违规企划下架、订单仲裁及需求/运营统计；封禁多订单退款、两类仲裁、评价申诉批准/驳回和限时自动解封已完成专用数据 E2E。
- 用户管理详情可“发放资金”追加模拟余额，或用“余额调整”设置最终余额；两类操作均要求原因，由服务端事务、用户行锁和审计保护，只用于测试数据维护，不建立真实充值或资金流水。
- 艺绘向导以右侧非模态窗口与原页面共存，支持文字及单轮最多 4 张私有参考图，通过澄清整理约稿需求，并可只读解释管理员本人业务。当前只对正常管理员开放，DeepSeek 视觉实验模型已联调；GLM 仅保留扩展接口，会话与图片不跨后端重启。
- 全站顶部导航、橱窗大厅卡片和橱窗详情页已完成最近一轮视觉整理；橱窗列表与详情均读取画师公开主页头像，昵称支持唯一性校验后的修改。

## 启动方式

当前正式、推荐的运行方式是直接在 Windows 安装 **MySQL 8、JDK 21、Maven 3.9+ 和 Node.js 20+**，再分别启动数据库、后端与前端。跨电脑安装、离线交付和局域网演示请按[《跨电脑部署文档》](docs/部署文档.md)执行。

仓库中的 Docker 配置仅作为未来可能使用的备用方案，不属于当前正式部署项，也尚未完成镜像构建和容器运行验证；没有 Docker 环境时无需安装或启用 Docker，详见[《Docker 备用演示方案》](docs/Docker演示环境.md)。

本机根目录保留可选的 `启动Artiv.cmd`，因含固定工具路径和 MySQL 服务名，已移出 Git 跟踪并加入忽略规则，不随新的仓库检出交付。它不安装依赖、不初始化数据库；换电脑应按下面的命令及部署文档启动，若另行复制该辅助脚本，须按目标环境调整配置。

### 1. 数据库

1. 启动本机 MySQL 8 服务。启动器使用 `MySQL80-Artiv`；旧部署示例中的 `MySQL80` 需按实际安装的服务名替换。
2. 仅在首次建库或明确需要重建空白初始环境时执行 [`backend/sql/init.sql`](backend/sql/init.sql)。脚本只保留三个初始用户，其余业务表为空；普通启动不要重复初始化数据库。
3. 按需修改 [`backend/src/main/resources/application.yml`](backend/src/main/resources/application.yml)，或使用未提交的本地配置/环境变量覆盖数据库连接。

### 2. 后端

```powershell
cd D:\ProjectForGraduation\Artiv\backend
mvn.cmd spring-boot:run
```

后端默认地址：`http://127.0.0.1:8080`。

### 3. 前端

```powershell
cd D:\ProjectForGraduation\Artiv\frontend
npm.cmd install
npm.cmd run dev
```

前端默认地址：`http://127.0.0.1:5173`，开发环境通过 Vite 代理转发 `/api`、`/ws` 和 `/uploads`。

## 测试数据库基线

仓库提供 [`scripts/database-baseline.ps1`](scripts/database-baseline.ps1) 保存测试开始前的数据库基线。基线 SQL 含账号、消息和订单等本地数据，因此被 Git 忽略；是否存在有效基线须在当前电脑执行 `Status` 确认，不能由 Git 同步状态推断。

查看基线状态：

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\scripts\database-baseline.ps1 -Action Status
```

首次创建基线：

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\scripts\database-baseline.ps1 -Action Capture
```

已有基线时如需显式替换为新的当前状态，添加 `-ReplaceBaseline`；旧基线会先自动保留。

测试结束后还原（执行前先停止后端）：

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\scripts\database-baseline.ps1 -Action Restore -ConfirmRestore
```

还原前会自动备份测试结束时的数据。完整安全规则见[《数据库测试基线》](docs/数据库测试基线.md)。
